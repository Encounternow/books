## 開場：霧裡下山

小傑和爸爸去爬山，下午起了大霧，能見度只剩兩三公尺，看不到山下的路，也看不到山頂。爸爸說：「沒關係，我們只要一直往下走，總會走到登山口。」

小傑問：「可是看不到路，怎麼知道哪邊是下？」爸爸用腳踩了踩四周的地面：「感覺腳下哪邊最陡、往哪邊是下坡，就往那邊走幾步。走完再踩一次，再決定方向。」

小傑又問：「那一次要走幾步？」爸爸說：「太小步天黑都走不到；太大步可能一腳跨過山谷，跑到對面山坡上去了。」

這段對話，其實就是 AI 訓練時最核心的演算法。第 3 章我們說「訓練 = 調整參數讓損失最小」，但沒說「怎麼調」。如果參數只有一個，你可以把每個值都試一遍；但真正的模型有幾百萬、幾十億個參數，不可能全部試。梯度下降就是在霧裡下山的方法：不需要看到整座山，只要知道腳下的坡度，就能一步一步走到谷底。

## 核心概念

### 損失函數是一座山

先回想第 3 章：模型有參數（例如直線的斜率 a 和截距 b），我們用一個**損失函數（Loss Function）**衡量「目前的參數錯得多嚴重」，數字越小越好。

把參數當 x 軸，損失當 y 軸，畫出來就是一座山（準確說是一個谷）。這一章先用一個故意設計得很簡單的損失函數練習：

```
L(w) = (w − 3)² + 1
```

只有一個參數 w。你可以算幾個點：L(0) = 10、L(1) = 5、L(2) = 2、L(3) = 1、L(4) = 2、L(5) = 5。畫出來是一個谷，最低點在 w = 3，損失是 1：

```
L
10 | *                           *
 8 |
 6 |
 5 |    *                   *
 4 |
 2 |         *         *
 1 |              *
 0 +--+----+----+----+----+----+--- w
   0  1    2    3    4    5    6
```

這個例子的答案我們一眼看得出來（w = 3）。但真實的損失函數有幾百萬個參數，畫不出來也看不出來，所以我們要練習「看不到全貌也能找到谷底」的方法。

### 斜率：腳下的坡度

站在山坡上某一點，**斜率（Slope）**告訴你兩件事：
- **正負**：斜率是正的，表示往右走會往上；斜率是負的，往右走會往下。
- **大小**：數字越大，坡越陡。

怎麼算某一點的斜率？最直覺的方法是「往右踩一小步，看高度變多少」：

```
斜率 ≈ (L(w + h) − L(w − h)) ÷ (2h)，h 是一個很小的數，例如 0.01
```

在 w = 0 試試：L(0.01) = (−2.99)² + 1 = 9.9401，L(−0.01) = (−3.01)² + 1 = 10.0601，斜率 ≈ (9.9401 − 10.0601) ÷ 0.02 = −6。負的，表示往右走是下坡，而且很陡。

在 w = 3 試試：L(3.01) = 1.0001，L(2.99) = 1.0001，斜率 ≈ 0。坡度是 0：這就是谷底的特徵。

對於 (w − 3)² 這種平方的函數，其實有一條現成的規則：**(w − 3)² 的斜率是 2(w − 3)**。驗證一下：w = 0 時 2 × (0 − 3) = −6，和剛才用小步踩出來的一樣；w = 3 時是 0。（這條規則背後是「導數」的概念，想知道為什麼的話可以讀《數學這樣想（進階）》第 9 章 https://book.vichuang.tw/math2/ ，但本章只要會用「踩一小步」的方法就夠了。後面的 +1 是常數，不影響斜率，因為把整座山抬高 1 公尺，坡度不會變。）

### 梯度下降的規則：往斜率的反方向走

有了斜率，下山的規則只有一行：

```
新的 w = 舊的 w − 學習率 × 斜率
```

**學習率（Learning Rate）**是一個你自己決定的小數字，常寫成 η（讀作 eta）或程式裡的 `lr`，代表「一步走多大」。

為什麼是「減」？斜率是負的（往右是下坡）時，減掉負數等於加，w 變大，往右走，正好是下坡方向；斜率是正的時候，w 變小，往左走，也是下坡。所以「減去斜率」永遠是往下走。而且坡越陡，斜率越大，一步就走越遠；接近谷底坡變平，步伐自動變小，不容易衝過頭。

### 一維手算：從 w = 0 走到 3

用 L(w) = (w − 3)² + 1，斜率 = 2(w − 3)，學習率 0.1，從 w = 0 出發：

| 步 | 目前 w | 損失 L(w) | 斜率 2(w − 3) | 走多遠 −0.1 × 斜率 | 新的 w |
|---|---|---|---|---|---|
| 1 | 0 | 10 | −6 | +0.6 | 0.6 |
| 2 | 0.6 | 6.76 | −4.8 | +0.48 | 1.08 |
| 3 | 1.08 | 4.686 | −3.84 | +0.384 | 1.464 |
| 4 | 1.464 | 3.359 | −3.072 | +0.307 | 1.771 |
| 5 | 1.771 | 2.510 | −2.458 | +0.246 | 2.017 |
| 6 | 2.017 | 1.966 | −1.966 | +0.197 | 2.214 |
| 7 | 2.214 | 1.619 | −1.573 | +0.157 | 2.371 |
| 8 | 2.371 | 1.396 | −1.258 | +0.126 | 2.497 |

看出規律了嗎？w 一路往 3 靠近，損失從 10 降到 1.4；每一步走的距離越來越短（0.6、0.48、0.384……每次都是前一步的 0.8 倍），因為越接近谷底坡越平。再走 20 步左右，w 就會非常接近 3。它永遠不會「剛好」等於 3，但會近到你分不出差別，這在 AI 裡完全夠用。

### 學習率太小、太大會怎樣

學習率是梯度下降最重要的設定。同樣從 w = 0 出發，看不同學習率的前幾步：

| 學習率 | 第 1 步後 | 第 2 步後 | 第 3 步後 | 第 4 步後 | 發生什麼事 |
|---|---|---|---|---|---|
| 0.01 | 0.06 | 0.119 | 0.177 | 0.233 | 太慢，走 100 步還到不了 |
| 0.1 | 0.6 | 1.08 | 1.464 | 1.771 | 穩穩走過去 |
| 0.5 | 3 | 3 | 3 | 3 | 一步剛好跳到谷底（這個函數太單純才會這樣） |
| 0.9 | 5.4 | 1.08 | 4.536 | 1.771 | 左右跳來跳去，但越跳越近 |
| 1.0 | 6 | 0 | 6 | 0 | 永遠在 0 和 6 之間彈跳，到不了 |
| 1.1 | 6.6 | −1.32 | 8.184 | −3.221 | 越跳越遠，損失爆炸 |

你可以自己驗算 1.1 那一列：w = 0 時斜率 −6，走 −1.1 × (−6) = 6.6，到 6.6；此時斜率 2 × 3.6 = 7.2，走 −1.1 × 7.2 = −7.92，到 −1.32。每一次都跨過谷底跳到對面更高的地方。這就是爸爸說的「一腳跨過山谷」。

所以學習率的選法是：**先小試幾步，損失有穩穩下降就好；如果損失忽大忽小或越來越大，學習率就要調小**。真正的 AI 訓練，學習率通常是 0.001 到 0.1 之間，而且常常會隨著訓練進行慢慢調小。

### 二維：兩個參數一起下山

真正的直線預測有兩個參數：斜率 a 和截距 b。損失函數變成「一塊地形」，兩個參數就是東西向和南北向。下山的規則一樣，只是要分別算「往 a 方向的坡度」和「往 b 方向的坡度」，然後兩個方向同時各走一步。這一組坡度合在一起叫**梯度（Gradient）**，就是「每個方向的斜率排成的向量」。所以梯度下降的意思就是「沿著梯度的反方向下降」。

用三個點 (1, 3)、(2, 5)、(3, 7) 來練習，直線是 y = a·x + b，損失用均方誤差（MSE）。第 3 章用的是平方和（SSE），MSE 就是 SSE 再除以資料筆數，兩者的「碗」形狀一樣、谷底在同一個位置，只是數字縮小了：

```
L(a, b) = 平均 (a·x + b − y)²
```

兩個方向的坡度，用和一維相同的「平方的斜率是 2 倍」規則得到：

```
a 方向的坡度 = 2 × 平均 (誤差 × x)
b 方向的坡度 = 2 × 平均 (誤差)
其中 誤差 = a·x + b − y（預測減真實）
```

為什麼 a 方向要多乘一個 x？直覺是：a 是「每單位 x 的影響」，x 大的點，a 稍微一動對它的預測就影響很大，所以它對 a 坡度的貢獻也要按 x 加權。b 對每個點的影響都一樣，所以不用加權。

從 a = 0、b = 0、學習率 0.1 出發，手算第 1 步：

```
預測全是 0，誤差 = (0 − 3, 0 − 5, 0 − 7) = (−3, −5, −7)
a 坡度 = 2 × 平均(−3×1, −5×2, −7×3) = 2 × 平均(−3, −10, −21) = 2 × (−34 ÷ 3) ≈ −22.667
b 坡度 = 2 × 平均(−3, −5, −7) = 2 × (−5) = −10
新 a = 0 − 0.1 × (−22.667) ≈ 2.267
新 b = 0 − 0.1 × (−10) = 1
```

一步就從 (0, 0) 跳到 (2.267, 1)，已經很接近正確答案 a = 2、b = 1。第 2 步：誤差變成 (2.267+1−3, 4.533+1−5, 6.8+1−7) = (0.267, 0.533, 0.8)，a 坡度 ≈ 2.489、b 坡度 ≈ 1.067，新 a ≈ 2.018、新 b ≈ 0.893。損失從 27.667 降到 0.332 再降到 0.005。活動 5-2 會在試算表上把這個過程做到 10 步以上。

### 真實的 AI 為什麼還是用這一招

你可能會想：這麼簡單的方法，真的能訓練出會認字、會聊天的 AI 嗎？能，而且幾乎所有現代 AI 都是靠它（和它的改良版）。原因有三個：

1. **不需要看到整座山**。不管幾億個參數，每一步只要算出目前位置的梯度就好。
2. **每一步都很便宜**。算梯度就是一堆乘法和加法，矩陣乘法（第 4 章）擅長的事。
3. **自動調步伐**。接近谷底時梯度自然變小，步伐自動縮小。

它也有弱點：可能走進一個「小谷」就以為到底了（局部最低點），或在很平的地方走得很慢。第 7、8 章會看到工程師怎麼用各種技巧對付這些問題，但底層的想法不變：看斜率、往反方向走一小步、重複。

### 活動 5-2：試算表二維下山，讓直線自己貼上資料

**材料／工具**：Google 試算表或 Excel。

**步驟**
1. 在 A1 打「步」、B1 打「a」、C1 打「b」、D1 打「損失」、E1 打「a坡度」、F1 打「b坡度」。資料點 (1,3)、(2,5)、(3,7) 固定寫在 H2:I4（H 欄 x、I 欄 y）。學習率寫在 K1（填 0.1）。
2. A2 填 1、B2 填 0、C2 填 0（起點）。
3. D2 填損失：`=AVERAGE((B2*$H$2+C2-$I$2)^2, (B2*$H$3+C2-$I$3)^2, (B2*$H$4+C2-$I$4)^2)`。
4. E2 填 a 坡度：`=2*AVERAGE((B2*$H$2+C2-$I$2)*$H$2, (B2*$H$3+C2-$I$3)*$H$3, (B2*$H$4+C2-$I$4)*$H$4)`。
5. F2 填 b 坡度：`=2*AVERAGE(B2*$H$2+C2-$I$2, B2*$H$3+C2-$I$3, B2*$H$4+C2-$I$4)`。
6. 第 3 列是下一步：A3 填 `=A2+1`，B3 填 `=B2-$K$1*E2`，C3 填 `=C2-$K$1*F2`，D3:F3 直接從上一列往下複製。
7. 把第 3 列整列往下拉到第 21 列（共 20 步）。
8. 選 A 欄和 D 欄，插入折線圖，看損失怎麼下降。
9. 把 K1 改成 0.01、0.3、0.4，觀察圖怎麼變。

- 學習率 0.1：第 1 步 (a, b) = (0, 0)、損失 27.667；第 2 步 (2.267, 1.000)、損失 0.332；第 3 步 (2.018, 0.893)、損失 0.005；第 11 步約 (2.035, 0.921)、損失約 0.0009。前三步損失暴跌，之後慢慢往 a = 2、b = 1 挪。

## 用工具看看

打開 Colab，新增筆記本，貼上下面的程式。這次換一組新資料：5 個人的讀書時數和考試分數（和第 3 章的腳長與身高是同一類「用直線預測」的問題），我們不用公式直接解，而是讓梯度下降自己把直線「走」到最佳位置。

```python
import numpy as np

# 1. 資料：5 個人的讀書時數 x 與考試分數 y（和第 3 章同類的「用直線預測」問題）
x = np.array([1, 2, 3, 4, 5], dtype=float)
y = np.array([52, 58, 65, 69, 78], dtype=float)

# 2. 從一條亂猜的直線開始：y = a·x + b，a、b 都先設 0
a, b = 0.0, 0.0
lr = 0.01          # 學習率：每一步走多大

# 3. 定義「損失」：預測和真實的差，平方後取平均（MSE）
def loss(a, b):
    pred = a * x + b
    return np.mean((pred - y) ** 2)

# 4. 梯度下降：算斜率、往反方向走一小步，重複很多次
for step in range(1, 3001):
    pred = a * x + b
    err = pred - y                    # 每一筆的誤差
    grad_a = 2 * np.mean(err * x)     # 損失對 a 的斜率
    grad_b = 2 * np.mean(err)         # 損失對 b 的斜率
    a -= lr * grad_a                  # 往斜率的反方向走
    b -= lr * grad_b
    if step in (1, 10, 100, 500, 1000, 3000):
        print(f"第 {step:4d} 步：a = {a:.3f}, b = {b:.3f}, 損失 = {loss(a, b):.3f}")

# 5. 跟 numpy 直接算出的最佳直線比一比
best_a, best_b = np.polyfit(x, y, 1)
print(f"numpy 直接算：a = {best_a:.3f}, b = {best_b:.3f}, 損失 = {loss(best_a, best_b):.3f}")
```

**你應該看到**

```
第    1 步：a = 4.116, b = 1.288, 損失 = 2587.383
第   10 步：a = 16.001, b = 5.889, 損失 = 299.490
第  100 步：a = 14.322, b = 16.537, 損失 = 153.546
第  500 步：a = 8.370, b = 38.027, 損失 = 11.026
第 1000 步：a = 6.681, b = 44.126, 損失 = 1.204
第 3000 步：a = 6.300, b = 45.498, 損失 = 0.860
numpy 直接算：a = 6.300, b = 45.500, 損失 = 0.860
```

幾件值得注意的事：
- 損失從 2587 一路降到 0.86，梯度下降走到的直線（a = 6.300、b = 45.498）和 numpy 用公式算的最佳直線幾乎一樣。多走幾千步，小數點後的差也會消失。
- 第 10 步時 a 衝到 16，比最後的 6.3 大很多，之後才慢慢退回來。這是因為一開始 b 還很小（分數都 50 幾分，b 卻只有 5），a 先「代替」b 把線抬高，等 b 慢慢長大，a 才退回正確值。這種「繞路」在真實訓練裡很常見。
- 試試把 `lr` 改成 0.1，你會看到損失變成天文數字甚至 `nan`（不是數字），這就是學習率太大跨過山谷。改成 0.001 則 3000 步還走不到。

## 常見錯誤與迷思

- **「梯度下降會直接算出最佳答案」** → 它不是「算出」，而是「一步一步走過去」，而且只會越來越接近，不會剛好等於 → 它是一個「重複很多次的小修正」，停止的條件通常是「損失不再明顯下降」。
- **「學習率越大學得越快」** → 太大會跨過谷底跳到對面，損失反而變大甚至爆炸 → 學習率要試：先小再慢慢加大，看到損失忽大忽小就縮回來。
- **「新 w = 舊 w + 學習率 × 斜率」** → 加號會往上坡走，損失越來越大 → 記住是「減」：斜率為負（往右下坡）時減去負數等於往右走。
- **「斜率是 0 就一定是最低點」** → 也可能是最高點或局部的小谷底 → 梯度下降保證往下走，但不保證走到「全世界最低」；實務上靠多試幾個起點和各種技巧改善。
- **「每一步都走固定距離」** → 走的距離是「學習率 × 斜率」，坡陡時走得遠，坡平時走得短 → 這正是它的優點：接近谷底自動放慢。
- **「二維以上太複雜，跟一維是不同方法」** → 完全同一個規則，只是每個方向各算一個斜率、各走一步 → 幾億個參數的大模型也是這樣：每個參數一個斜率，全部同時更新。

## 想一想

1. L(w) = (w − 3)² + 1，w = 5 時的斜率是多少？往哪邊走是下坡？

<details><summary>參考答案</summary>

斜率 = 2 × (5 − 3) = 4，是正的，表示往右是上坡，所以要往左走（w 變小）才是下坡。

</details>

2. 從 w = 5 出發，學習率 0.25，走 3 步，w 分別變成多少？

<details><summary>參考答案</summary>

第 1 步：斜率 4，w = 5 − 0.25 × 4 = 4。第 2 步：斜率 2，w = 4 − 0.5 = 3.5。第 3 步：斜率 1，w = 3.5 − 0.25 = 3.25。每步距離減半，往 3 靠近。

</details>

3. 換一個損失函數 L(w) = (w + 2)² + 5。它的谷底在哪裡？斜率規則是什麼？從 w = 0、學習率 0.1 走 2 步。

<details><summary>參考答案</summary>

谷底在 w = −2（損失 5）。斜率 = 2(w + 2)。w = 0 時斜率 4，走到 0 − 0.4 = −0.4；此時斜率 2 × 1.6 = 3.2，走到 −0.4 − 0.32 = −0.72。

</details>

4. 某個同學用學習率 0.05 訓練，損失變化是 100 → 98 → 96 → 94……；另一個同學用 0.8，損失變化是 100 → 150 → 90 → 200。請分別建議他們怎麼調整，為什麼？

<details><summary>參考答案</summary>

第一位下降得太慢，可以把學習率加大（例如 0.2 或 0.5）看看會不會快一點。第二位損失忽大忽小，表示一步跨過了谷底，要把學習率調小（例如 0.1）。

</details>

5. 在二維例子裡，如果資料點的 x 改成 (10, 20, 30)（y 不變），a 方向的坡度會變得比原本大很多（第 1 步大約 −226.7 而不是 −22.7）。這會造成什麼問題？你會怎麼處理？

<details><summary>參考答案</summary>

a 的坡度大 10 倍，用同樣的學習率 0.1，a 一步就會跳到 22.7，遠遠跨過正確答案（正確的 a 現在是 0.2），損失爆炸。解法是把學習率調小很多（例如 0.001），或者先把 x 除以 10 讓它回到 1～3 的範圍再訓練，這叫「特徵縮放」，第 8 章會再提到。

</details>

6. 開放挑戰：修改 Colab 的程式，把 `x` 改成 `np.array([10, 20, 30, 40, 50])`（讀書分鐘數），其他不變。先猜損失會怎樣，再執行看看。接著試著找一個能讓它穩穩下降的學習率，並記錄你試了哪些值。最後想一想：有沒有辦法不改學習率就讓它正常訓練？

<details><summary>參考答案</summary>

x 變成 10 倍，a 方向的坡度大約變成 100 倍（誤差 × x 變 10 倍，而且 a 本身對預測的影響也變 10 倍），用原本的 0.01 會立刻爆炸，印出很大的數或 nan。學習率大約要縮到 0.0001 才會穩定，但 b 的方向會變得很慢。不改學習率的做法是把 x 先除以 10（或減平均再除以標準差）再訓練，訓練完再把 a 換算回去，這叫特徵縮放，是實務上幾乎一定會做的前處理。

</details>

## 本章小結

- 損失函數把「參數」和「錯多嚴重」連起來，畫出來像一座山；訓練就是走到谷底。
- 斜率告訴你腳下的坡度：正負決定方向，大小決定陡度；可以用「往兩邊踩一小步看高度差」算出來，平方函數有現成規則 (w − c)² 的斜率是 2(w − c)。
- 梯度下降的規則只有一行：新參數 = 舊參數 − 學習率 × 斜率。減號保證永遠往下坡走。
- 越接近谷底坡越平，步伐自動變小；它只會越來越接近答案，不會剛好等於。
- 學習率太小走太慢；太大會跨過谷底來回彈跳甚至爆炸。看損失曲線：穩穩下降就對了，忽大忽小就調小。
- 多個參數時，每個方向各算一個斜率（合起來叫梯度），所有參數同時各走一步；幾億個參數的模型也是這樣。
- 在 Colab 用 numpy 寫梯度下降只要十幾行，走幾千步就能找到和公式一樣的最佳直線。
- 它可能卡在局部的小谷或平坦處，後面的章節會看到改良的方法，但核心想法不變。

## 名詞表

| 中文 | 英文 | 一句話解釋 |
|---|---|---|
| 梯度下降 | Gradient Descent | 看目前位置的斜率，往反方向走一小步，重複到損失不再下降。 |
| 損失函數 | Loss Function | 衡量目前參數錯得多嚴重的函數，越小越好。 |
| 斜率 | Slope | 函數在某一點的坡度，正負表示方向、大小表示陡度。 |
| 導數 | Derivative | 斜率的正式名稱，見《數學這樣想（進階）》第 9 章。 |
| 梯度 | Gradient | 每個參數方向的斜率排成的向量。 |
| 學習率 | Learning Rate | 一步走多大的倍數，常寫成 η 或 lr。 |
| 更新 | Update | 用「舊參數 − 學習率 × 斜率」換成新參數的動作。 |
| 步／迭代 | Step / Iteration | 做一次更新。 |
| 收斂 | Converge | 損失越來越接近某個值、不再明顯下降。 |
| 發散 | Diverge | 損失越來越大或忽大忽小，通常是學習率太大。 |
| 局部最低點 | Local Minimum | 附近都比它高、但不是整座山最低的小谷底。 |
| 均方誤差 | Mean Squared Error | 誤差平方的平均；第 3 章的平方和（SSE）除以筆數就是它。 |
| 特徵縮放 | Feature Scaling | 先把輸入的數字調整到差不多的範圍，讓梯度下降比較穩。 |
