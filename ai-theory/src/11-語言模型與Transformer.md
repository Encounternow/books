# 第 11 章　語言模型與Transformer

## 本章目標

學完這一章，你會：

- 用一句話說出語言模型在做什麼：預測下一個字。
- 親手用一小段童話做出 2-gram 文字產生器，並用它「寫」出新句子。
- 解釋注意力（Attention）的直覺：每個字看其他字，決定誰重要，再把重要的混進來。
- 看懂 Transformer 結構的一張圖，知道資料從 token 進去到機率出來經過哪些站。
- 說明「溫度」怎麼影響輸出，為什麼同一個問題每次答案不一樣。
- 解釋幻覺（Hallucination）從哪裡來：模型在預測合理的下一個字，不是在查證。
- 在 Colab 上用自己寫的童話訓練字元級 n-gram 產生器，觀察 n 和溫度的影響。

## 開場：手機輸入法的接龍

你在手機上打「今天天氣」，輸入法跳出三個建議：「很好」「真好」「如何」。你點「很好」，它又建議：「，」「啊」「喔」。一直點下去，可以不用自己想就「寫」出一整句話——雖然通常寫到第十個字就開始怪怪的。

輸入法怎麼知道「今天天氣」後面常接「很好」？它從大量的文字裡數過：「天氣」後面接「很好」幾次、接「如何」幾次。它沒有在「理解」天氣，只是在算「接下來最可能出現什麼字」。

ChatGPT 做的事，本質上跟這個輸入法一樣：給它前面的文字，它算出下一個字的機率，挑一個，接上去，再算下一個。差別在於它看的「前面的文字」可以長達幾萬字、它的「數過」是用上千億個參數的神經網路去學的，所以它接出來的字可以連貫幾千字而不走樣。

這一章我們從最小的版本——用一段童話數字——開始，一路看到 Transformer 的結構，最後回答一個很多人問的問題：它為什麼會一本正經地講錯話？

## 核心概念

### 語言模型 = 預測下一個字

語言模型（Language Model）的定義只有一句：給它前面的文字，它輸出「下一個 token 是什麼」的機率表。

```
輸入：「小狐狸每天去河邊」
輸出：
  喝水  0.60
  玩    0.20
  看    0.10
  。    0.05
  其他  0.05
```

有了這張表，就能產生文字：從機率表挑一個字（最高的，或照機率抽），接到後面，變成「小狐狸每天去河邊喝水」，再餵回去算下一張表，再挑一個……一直到挑出「結束」符號為止。

這個「算機率 → 挑一個 → 接上去 → 再算」的迴圈，就是所有聊天 AI 產生回答的方式。你看到它一個字一個字蹦出來，不是特效，它真的一次算一個 token。「訓練語言模型」就是用大量文字讓它把機率表學準，損失函數就是第 8 章的交叉熵——正確的下一個字機率越低，罰越重。

### 最小的語言模型：n-gram

最簡單的做法是直接數。只看前一個字來決定下一個字，叫 2-gram（也叫 bigram，兩個一組）；看前兩個字叫 3-gram；通稱 n-gram。

用這段切好詞的小童話：

```
從前 有 一隻 小 狐狸 。 小 狐狸 住 在 森林 。 森林 裡 有 一條 河 。 小 狐狸 每天 去 河邊 喝水 。
```

數「每個詞後面接了什麼」，列成 2-gram 表（只列有分歧的幾條）：

| 前一個詞 | 下一個詞：次數 | 機率 |
|---|---|---|
| 有 | 一隻：1、一條：1 | 各 1/2 |
| 小 | 狐狸：3 | 1 |
| 狐狸 | 。：1、住：1、每天：1 | 各 1/3 |
| 。 | 小：2、森林：1 | 2/3、1/3 |
| 森林 | 。：1、裡：1 | 各 1/2 |

從「小」出發產生：小 → 狐狸（唯一選擇）→ 擲一次三選一，假設抽到「住」→ 在 → 森林 → 二選一，抽到「裡」→ 有 → 二選一，抽到「一條」→ 河 → 。→ 小……得到「小狐狸住在森林裡有一條河。小……」。每一步都是故事裡出現過的接法，但整句話是新拼出來的。

n-gram 的問題是**記性太短**。2-gram 只記前一個詞，寫到「森林」時早就忘了主角是誰。改成 3-gram、4-gram 記性變長，但大部分「前三個詞的組合」在訓練文字裡只出現過一次，產生出來的就是原文照抄，而且沒見過的組合完全無法處理（看看「用工具看看」裡 3-gram 的結果）。要記得長，又要能處理沒見過的組合，需要神經網路——以及下面要講的注意力。

### 注意力：每個字看其他字，決定誰重要

看這句話：「小兔子迷路了，小狐狸帶他回家。」「他」是誰？你知道是小兔子。因為你讀到「他」的時候，回頭看了前面，發現「小兔子」是迷路的那個、「小狐狸」是帶路的那個。

第 10 章說過，一般詞向量裡「他」永遠是同一個向量。注意力（Attention）機制讓每個字的向量可以依上下文改變，做法是：**每個字對句子裡其他的字打分數，分數高的多混一點進來**。

分成三步（這裡用「他」當例子）：

1. **打分數**：「他」對每個字算一個分數，分數高表示相關。真正的做法是內積：每個字有一個「查詢向量」（Query）和一個「鑰匙向量」（Key），「他」的查詢向量和別人的鑰匙向量做內積，就是分數。假設算出來：小兔子 2、小狐狸 1、回家 0.1。
2. **分數變權重**：用 softmax 把分數變成加起來是 1 的權重（大的變更大、小的變更小）：小兔子 0.66、小狐狸 0.24、回家 0.10。
3. **加權混合**：每個字還有一個「內容向量」（Value）。「他」的新向量 = 0.66 × 小兔子的內容 + 0.24 × 小狐狸的內容 + 0.10 × 回家的內容。

用迷你數字算一次。假設內容向量是：小兔子 [1, 0]、小狐狸 [0, 1]、回家 [1, 1]。那麼：

「他」的新向量 = 0.66×[1, 0] + 0.24×[0, 1] + 0.10×[1, 1] = [0.66 + 0.10, 0.24 + 0.10] = [0.76, 0.34]

這個向量「大部分是小兔子、一點點小狐狸」——「他」現在帶著「小兔子」的資訊了。換一句話，「他」的分數和權重會不同，新向量也不同。這就解決了第 10 章「蘋果手機 vs 吃蘋果」的問題。

```
                 小兔子        小狐狸        回家
                   │            │            │
「他」的分數：      2            1           0.1       ← 查詢 · 鑰匙
softmax 權重：    0.66         0.24         0.10      ← 加起來是 1
                   └────────────┴────────────┘
                            加權混合內容向量
                                   │
                                   ▼
                      「他」的新向量（主要是小兔子）
```

查詢、鑰匙、內容這三種向量，都是用矩陣把原本的詞向量乘出來的（第 4 章：矩陣是一個變換），那些矩陣是訓練出來的權重。一層 Transformer 裡有很多組這樣的矩陣同時在算，叫多頭注意力（Multi-head Attention）：一個頭可能在找「他指誰」，另一個頭在找「動詞的主詞是誰」，再一個頭在看「前一個字是什麼」。

### Transformer 的結構一張圖

Transformer 是 2017 年提出的神經網路結構，把注意力當主角。GPT 這類模型用的是它的「只產生」版本，長這樣：

```
輸入 token：  小    狐    狸    每    天    去
               │     │     │     │     │     │
               ▼     ▼     ▼     ▼     ▼     ▼
          ┌────────────────────────────────────────┐
          │ 詞向量表（第 10 章）+ 位置編碼           │   ← 告訴模型每個字排第幾個
          └────────────────────────────────────────┘
               │     │     │     │     │     │
          ┌────────────────────────────────────────┐
          │ 第 1 層                                 │
          │   多頭注意力：每個字看前面所有的字        │   ← 混合上下文
          │   前饋網路：每個字各自過一個兩層網路      │   ← 第 7 章那種網路
          └────────────────────────────────────────┘
               │     │     │     │     │     │
          ┌────────────────────────────────────────┐
          │ 第 2 層（同樣的結構，不同的權重）         │
          └────────────────────────────────────────┘
               │          ……疊 N 層……
          ┌────────────────────────────────────────┐
          │ 第 N 層                                 │
          └────────────────────────────────────────┘
                                             │
                                             ▼
                                   最後一個位置的向量
                                             │
                                             ▼
                                 矩陣乘法 → softmax
                                             │
                                             ▼
                              「下一個 token」的機率表
                               河邊 0.6  森林 0.2  山坡 0.1 ……
```

幾個重點：

- **位置編碼（Positional Encoding）**：注意力本身不知道順序（它只是算內積和加權平均），所以要把「我是第幾個字」的資訊加進向量裡，否則「狗咬人」和「人咬狗」分不出來。
- **每一層都是「注意力 + 前饋網路」**：注意力負責「字和字之間交流」，前饋網路負責「每個字自己消化一下」。小模型疊 12 層，大模型疊 100 層左右。
- **只看前面**：產生文字時，每個字只能看它前面的字（不能偷看答案），所以圖裡的注意力是「看前面所有的字」。
- **最後只用最後一個位置**：要預測下一個字，看最後一個位置經過 N 層之後的向量，乘一個矩陣變成詞彙表大小的分數，softmax 成機率。

整個結構裡沒有任何文法規則或字典，只有矩陣乘法、注意力、ReLU 一類的運算，和幾十億個靠梯度下降調出來的權重。

### 為什麼要那麼多資料與算力

一個小型 Transformer 幾千萬個參數，GPT-3 有 1,750 億個，更新的模型更多。這些參數全部靠第 5 章的梯度下降，從幾兆個 token 的文字裡一點一點調出來——每看一小批文字，算損失，反向傳播，更新一次。

為什麼要這麼多？兩個理由：

- **語言的組合太多**。n-gram 數不完所有組合，神經網路靠「相似的輸入有相似的輸出」來推廣，但要推廣得好，就得看過夠多樣的例子。
- **參數多才裝得下**。模型的「知識」（巴黎是法國首都、Python 的語法）都存在權重裡。研究發現參數和資料一起加大，損失會很有規律地下降，某些能力要到一定規模才會出現。

代價是算力：訓練一個大模型要幾千顆 GPU 跑好幾個月。所以絕大多數人用的是別人訓練好的模型，頂多微調（第 12 章），跟第 9 章的遷移學習是同一個思路。

### 溫度與取樣

模型輸出的是機率表，不是答案。從表裡「挑一個」的方法，決定了輸出的風格。

最簡單的是每次都挑機率最高的，叫貪婪（Greedy），穩定但無聊，而且容易一直重複同一句話。

更常用的是照機率隨機抽（取樣，Sampling），而且抽之前可以用溫度（Temperature）調整機率表的「尖銳程度」。做法是在 softmax 之前把分數除以溫度 T：

| 分數 | T = 0.5（低溫） | T = 1（原本） | T = 2（高溫） |
|---|---|---|---|
| 河邊 2.0 | 0.86 | 0.66 | 0.50 |
| 森林 1.0 | 0.12 | 0.24 | 0.30 |
| 山坡 0.1 | 0.02 | 0.10 | 0.19 |

溫度低，最高的那個幾乎獨占，輸出保守、固定；溫度高，機率拉平，輸出多變、有創意，也更容易出怪字。溫度接近 0 就等於貪婪。這就是為什麼《AI 怎麼用》裡說「同一個問題問兩次答案會不一樣」——它在抽籤。

n-gram 模型也可以做同樣的事：把「次數」當分數，次數開 1/T 次方再除以總和，效果一樣（「用工具看看」會示範）。

### 幻覺從哪裡來

幻覺（Hallucination）是指模型講出流暢、自信、但不是真的的內容：編造一本不存在的書、一條不存在的法律、一個不存在的網址。

為什麼？回到定義：**語言模型在預測合理的下一個字，不是在查證**。

訓練資料裡，「這個說法出自」後面通常接「某某教授 2015 年發表於某某期刊的論文」這樣的句型。模型學會了這個句型，當它需要接下去時，就產生一個「長得很像引用」的東西——作者名字合理、年份合理、期刊名字合理，全部是從機率表抽出來的，沒有任何一步是「去資料庫查有沒有這篇論文」。

幾個特別容易幻覺的情況：

- **冷門事實**：訓練資料裡只出現過一兩次的事（某個小鎮的人口、某個小公司的歷史），模型記不牢，但句型記得牢，就用句型補上合理的數字。
- **要求精確引用、網址、數字**：這些東西的「合理樣子」很固定，但正確內容是任意的，猜中機率極低。
- **問題本身有錯誤前提**：「為什麼第 20 章說……」模型傾向順著接下去，而不是說「沒有第 20 章」。

重要的是：模型的「信心」（機率高）跟「正確」是兩回事。它對編出來的引用可能跟對 1 + 1 = 2 一樣有信心。這就是為什麼《AI 怎麼用》一直強調要查證；第 12 章會講「先查再答」（RAG）怎麼緩解，第 13 章再完整討論限制與安全。

## 動手做

### 活動 11-1：紙筆 2-gram 童話產生器

**材料／工具**：紙、筆、一個銅板、一顆骰子。

**步驟**

1. 用這段 24 個字的迷你童話當訓練資料（字元級：一個字就是一個 token，句號也算）：

```
小貓愛吃魚。小狗愛吃肉。小貓愛睡覺。小狗愛跑步。
```

2. 從第一個字開始，每一對相鄰的字記一筆「前一個字 → 下一個字」。例如「小→貓」「貓→愛」「愛→吃」……全部 23 對。
3. 整理成表：每個字當「前一個字」時，後面接過哪些字、各幾次。
4. 從「小」開始產生 20 個字：看「小」那一列，如果只有一個選擇就直接接；有兩個選擇擲銅板；有三個以上用骰子（例如三選一：1–2 選第一個、3–4 第二個、5–6 第三個；但要注意次數不同時機率要不同，像「愛」後面「吃」出現 2 次、「睡」「跑」各 1 次，就用 1–3 吃、4 睡、5 跑、6 重擲）。
5. 寫下你產生的 20 個字，念念看。再產生一次，看跟第一次一不一樣。

**你應該看到／得到**：2-gram 表：

| 前一個字 | 後面接過的字：次數 |
|---|---|
| 小 | 貓：2、狗：2 |
| 貓 | 愛：2 |
| 狗 | 愛：2 |
| 愛 | 吃：2、睡：1、跑：1 |
| 吃 | 魚：1、肉：1 |
| 魚 / 肉 / 覺 / 步 | 。：各 1 |
| 睡 | 覺：1 |
| 跑 | 步：1 |
| 。 | 小：3 |

可能產生的結果像「小狗愛吃魚。小貓愛跑步。小狗愛睡覺。小貓」——「小狗愛吃魚」「小貓愛跑步」原文裡都沒有，是模型拼出來的新句子，而且文法全對，因為每一步接法都出現過。兩次產生結果通常不同，因為中間擲了銅板和骰子。你剛剛親手跑了一個語言模型。

|---|---|
| 第一次產生的 20 字 |  |
| 第二次產生的 20 字 |  |
| 有沒有產生出原文沒有的句子 |  |
| 哪個字後面的選擇最多 |  |

### 活動 11-2：用骰子體驗溫度

**材料／工具**：活動 11-1 的表、骰子、紙筆。

**步驟**

1. 只看「愛」那一列：吃 2 次、睡 1 次、跑 1 次。原本的機率是吃 1/2、睡 1/4、跑 1/4。
2. 做三種「溫度」的擲法：
   - **低溫（接近 0）**：不擲，永遠選最多次的「吃」。
   - **原本（T = 1）**：骰子 1–3 吃、4 睡、5 跑、6 重擲（機率 1/2、1/4、1/4）。
   - **高溫（很大）**：三個一樣多，骰子 1–2 吃、3–4 睡、5–6 跑。
3. 每種溫度各從「小」開始產生 3 個句子（產生到句號為止），其他字的選擇照活動 11-1 的做法。
4. 比較三組句子：哪一組最「安全」？哪一組最「多變」？哪一組最像在重複？

**你應該看到／得到**：低溫那組三句幾乎一樣（只有「貓／狗」會變，因為「小」那一列是對半），永遠是「小X愛吃魚。」或「小X愛吃肉。」。高溫那組「睡覺」「跑步」出現的次數明顯變多，三句差異最大。T = 1 介於中間。這就是聊天 AI 裡「溫度」旋鈕的效果：低溫穩定但重複，高溫多變但容易出怪東西。

### 活動 11-3：注意力打分數（紙筆）

**材料／工具**：紙、筆、計算機。

**步驟**

1. 句子：「小兔子 迷路 了 ， 小狐狸 帶 他 回家 。」。我們要幫「他」算注意力。
2. 幫「他」對前面每個詞打一個「相關程度」分數，0 到 3 分（你自己判斷，問自己「要知道『他』是誰，這個詞幫了多少忙？」）。
3. 把分數加起來，每個分數除以總和，得到權重（這是 softmax 的簡化版：把分數變成加起來是 1）。
4. 假設每個詞有一個 2 維的內容向量：小兔子 [1, 0]、迷路 [0.5, 0]、了 [0, 0]、，[0, 0]、小狐狸 [0, 1]、帶 [0, 0.5]。用你的權重做加權相加，算出「他」的新向量。
5. 看看新向量第一格（兔子那一維）和第二格（狐狸那一維）哪個大，解釋為什麼。

## 用工具看看

在 Colab 新增筆記本，貼上整段執行。這段程式用一篇我們自己寫的 184 字小童話，建字元級 n-gram 表，然後產生文字，並示範溫度的效果。不需要下載任何東西，只用 Python 內建的套件。

```python
import random
from collections import defaultdict, Counter

# 一段自己寫的小童話，當作訓練資料（你可以換成自己的故事）
story = """
從前從前，森林裡住著一隻小狐狸。小狐狸每天早上都會去河邊喝水，
然後跑到山坡上看太陽。有一天，小狐狸在河邊遇到一隻小兔子。
小兔子說：「你好，我迷路了，你可以帶我回家嗎？」小狐狸點點頭，
帶著小兔子穿過森林，走過小橋，爬上山坡。太陽快下山的時候，
他們終於看到小兔子的家。小兔子的媽媽很開心，請小狐狸吃了甜甜的紅蘿蔔。
從那天起，小狐狸和小兔子每天都一起去河邊喝水，一起看太陽。
"""
# 把換行拿掉，變成一長串字（字元級：一個中文字就是一個單位）
story = story.replace('\n', '').strip()
print("故事總共", len(story), "個字")

# 建 n-gram 表：記錄「前 n 個字」之後，各種下一個字出現幾次
def build(text, n):
    table = defaultdict(Counter)
    for i in range(len(text) - n):
        context = text[i:i+n]          # 前 n 個字
        nxt = text[i+n]                # 接下來的那個字
        table[context][nxt] += 1
    return table

# 先看看 2-gram 表裡「小」後面接過什麼
t1 = build(story, 1)
print("「小」後面接過的字：", dict(t1['小']))
print("「狐」後面接過的字：", dict(t1['狐']))

# 產生文字：從一個開頭出發，每次照機率抽下一個字
def generate(table, n, start, length=40, temperature=1.0, seed=0):
    random.seed(seed)
    out = start
    for _ in range(length):
        context = out[-n:]
        if context not in table:        # 沒見過這個開頭就停
            break
        chars, counts = zip(*table[context].items())
        # 溫度：把次數開 1/溫度 次方，溫度低→更偏向最常見，溫度高→更平均
        weights = [c ** (1.0 / temperature) for c in counts]
        out += random.choices(chars, weights=weights)[0]
    return out

for n in [1, 2, 3]:
    table = build(story, n)
    print(f"\n=== 看前 {n} 個字（{n+1}-gram）===")
    print(generate(table, n, start=story[:n], length=40))

# 溫度：看「小」後面各字的機率怎麼隨溫度改變
def probs(counter, temperature):
    chars, counts = zip(*counter.items())
    w = [c ** (1.0 / temperature) for c in counts]   # 次數開 1/溫度 次方
    total = sum(w)
    return {ch: round(x / total, 2) for ch, x in zip(chars, w)}

print("\n=== 「小」的下一個字，在不同溫度下的機率 ===")
for temp in [0.3, 1.0, 3.0]:
    print(f"溫度 {temp}：", probs(t1['小'], temp))

# 同一個「看前 1 個字」的模型、同一個亂數種子，只改溫度，看產生的文字怎麼變
print("\n=== 看前 1 個字，不同溫度 ===")
for temp in [0.3, 1.0, 3.0]:
    print(f"溫度 {temp}：", generate(t1, 1, start='小', length=30, temperature=temp, seed=7))
```

**怎麼讀這些輸出**

- 程式裡的 `n` 是「看前幾個字」，看前 1 個字就是本章說的 2-gram。
- 看前 1 個字：「從那天，小兔子的家嗎？」——每兩個字連起來都通順，整句不知所云。記性只有一個字。
- 看前 2 個字：「森林裡住著一隻小兔子的家」——開始有片語了，但「小兔子的家」接「。小狐狸和……」仍然跳來跳去。
- 看前 3 個字：幾乎是原文照抄，只在「小」之後岔到了「兔子說」。184 字的故事裡，三個字的組合大多只出現過一次，模型沒有選擇，只能照抄。這就是 n-gram 的兩難：n 小沒記性，n 大變成背書。
- 溫度表：「橋」原本只出現 1 次（機率 0.08），溫度 0.3 把它壓到 0、溫度 3.0 把它抬到 0.22。溫度低→保守、溫度高→敢選冷門的。
- 三種溫度產生的文字，前 7 個字一樣（因為「小→狐→狸→點→點→頭→，」一路都沒得選或亂數剛好一樣），之後開始分岔。溫度 0.3 那句卡在「山坡上山坡上」——低溫容易重複，跟聊天 AI 溫度太低會跳針是同一件事。

## 常見錯誤與迷思

- **「ChatGPT 在資料庫裡查答案」** → 它沒有資料庫，只有權重；回答是一個字一個字預測出來的 → 它的「知識」是壓縮在參數裡的統計規律，查證要靠外接工具（第 12 章 RAG）。
- **「答案很流暢、很有自信，所以是對的」** → 流暢是語言模型最擅長的事，跟正確無關 → 引用、數字、網址、冷門事實一定要查。
- **「同一個問題答案不一樣，表示它壞了」** → 它在照機率抽籤（取樣），溫度不是 0 就會有變化 → 要穩定可以把溫度調低，但不保證更正確。
- **「n-gram 的 n 越大越好」** → n 大了之後絕大多數組合沒見過，變成照抄原文或卡住 → 要記得長又要能推廣，需要神經網路和注意力。
- **「注意力就是模型在『注意』，像人一樣」** → 它只是「算分數、softmax、加權平均」的數學運算 → 名字是比喻。
- **「Transformer 裡有文法規則」** → 整個結構只有矩陣乘法、注意力、啟動函數 → 文法是從資料裡「浮現」出來的統計規律，沒有人寫進去。

## 想一想

1. 用活動 11-1 的 2-gram 表，從「貓」開始，不擲骰子、每次都選次數最多的字（平手時選表裡先出現的），會產生什麼？產生到第 15 個字會發生什麼事？

<details><summary>參考答案</summary>

貓 → 愛 → 吃（2 次，最多）→ 魚（平手選先出現的）→ 。→ 小 → 貓（平手）→ 愛 → 吃 → 魚 → 。→ 小 → 貓……「貓愛吃魚。小貓愛吃魚。小貓愛」一直循環。這就是貪婪選法的毛病：沒有隨機性就會跳針。

</details>

2. 某個語言模型對「台灣最高的山是」後面的機率是：玉山 0.7、雪山 0.15、阿里山 0.1、其他 0.05。溫度調很低會輸出什麼？溫度調很高呢？哪一種設定比較適合「查事實」？哪一種適合「寫故事」？

<details><summary>參考答案</summary>

溫度很低：幾乎永遠輸出「玉山」。溫度很高：四個選項機率拉近，常常會輸出「雪山」甚至「阿里山」。查事實要低溫（要最可能的答案，不要意外），寫故事要高一點的溫度（要變化）。但注意：低溫只是讓它「穩定地輸出它認為最可能的」，如果它學錯了，低溫會穩定地錯。

</details>

3. 句子「小狐狸把紅蘿蔔給小兔子，因為牠肚子餓了。」「牠」比較可能是誰？注意力機制靠什麼線索判斷？如果句子改成「……因為牠很大方」呢？

<details><summary>參考答案</summary>

第一句「牠」是小兔子（肚子餓的是收到食物的那方），第二句「牠」是小狐狸（大方的是給的那方）。注意力靠「牠」的查詢向量和其他詞的鑰匙向量算分數，而這些向量是訓練出來的，訓練資料裡「給……因為……餓」這類句型通常指向收的人，「給……因為……大方」指向給的人。模型沒有「餓」或「大方」的常識，只有這些句型的統計。這也說明為什麼要大量資料：這種細微的線索得看過很多次才學得到。

</details>

4. 為什麼 Transformer 需要位置編碼，n-gram 卻不需要？

<details><summary>參考答案</summary>

n-gram 的「前 n 個字」本身就是按順序排的，順序資訊內建在表的索引裡。注意力是對所有字算內積再加權平均，加權平均不管順序（a×0.3 + b×0.7 和 b×0.7 + a×0.3 一樣），所以要另外把「第幾個位置」加進向量，模型才分得出「狗咬人」和「人咬狗」。

</details>

5. 請設計一個問題，讓語言模型「很可能幻覺」，並說明為什麼。再設計一個「很不容易幻覺」的問題。

<details><summary>參考答案</summary>

容易幻覺：「請列出三篇 2019 年研究台灣國中生睡眠時間的論文，附作者和期刊名。」因為它需要精確的冷門引用，「論文引用的樣子」很固定但內容是任意的，模型會用句型補出看起來合理的假引用。不容易幻覺：「請把這段話翻成英文：……」或「1 加到 100 是多少」，因為答案完全由輸入決定、或是訓練資料裡出現過無數次的高頻模式。

</details>

6. 開放挑戰：用「用工具看看」的程式，把 `story` 換成兩段風格差很多的文字（例如一段童話加一段新聞），各 200 字以上。用 2-gram 產生 5 次，觀察：它會在兩種風格之間切換嗎？切換通常發生在什麼字之後？這跟「注意力只看前兩個字」有什麼關係？

<details><summary>參考答案</summary>

答案因人而異。通常會發現切換發生在兩段文字都用到的高頻字（「的」「，」「。」「是」）之後，因為那個字在兩段裡都有鄰居，模型抽到哪一段的鄰居就跳到哪一段。n-gram 只記前兩個字，不記得「我現在在寫童話」，所以一碰到共用的字就可能跳槽。Transformer 的注意力能看前面幾千個字，知道整體風格，比較不會跳。

</details>

## 本章小結

- 語言模型只做一件事：給前面的文字，輸出下一個 token 的機率表。產生文字就是「算、挑、接、再算」的迴圈。
- n-gram 是最小的語言模型：直接數「前 n 個字後面接什麼」。n 小沒記性，n 大變背書。
- 注意力讓每個字對其他字打分數（查詢 · 鑰匙），softmax 成權重，加權混合內容向量，得到隨上下文改變的新向量。
- Transformer = 詞向量 + 位置編碼 + 疊 N 層「多頭注意力 + 前饋網路」+ 最後一個位置輸出機率。裡面只有數學運算和訓練出來的權重，沒有規則或字典。
- 參數多、資料多，是因為語言的組合太多、知識要存在權重裡；代價是巨大的算力。
- 溫度控制機率表的尖銳程度：低溫穩定重複，高溫多變冒險。取樣是「同一問題答案不同」的原因。
- 幻覺來自「預測合理的下一個字」而非「查證」：冷門事實、精確引用、錯誤前提最容易出事；流暢和自信都不代表正確。
