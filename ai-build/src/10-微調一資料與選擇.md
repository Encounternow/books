# 第 10 章　微調一：資料與選擇

## 本章目標

學完這一章，你會：

- 說出微調（Fine-tuning）是什麼、它改變的是模型的哪一部分，以及它和 RAG、提示工程的根本差別。
- 用一張決策表判斷：遇到一個需求，該改提示、該做 RAG、還是該微調。
- 看懂並寫出微調資料集的 JSONL 格式（一行一筆、每筆是一段對話）。
- 解釋為什麼「資料品質比數量重要」，以及合成資料與去重的陷阱。
- 寫一支清洗腳本：檢查格式、去掉空白與太短的、過濾個資、去完全重複、用嵌入去近似重複，然後切成訓練集與驗證集。
- 知道整理資料時要注意的授權與隱私問題。

## 開場：想要一個「像我」的回覆機器人

小宇在群組裡以「講話很有梗」出名：喜歡用電子零件打比方（「你這題卡住就像 LED 接反了啦」）、句尾愛加「欸」「啦」「喔」。他想做一個機器人，別人傳訊息來時，先幫他擬一個「像他會講的」草稿。

他先試了提示工程：在 system prompt 裡寫「回覆要簡短、口語、常用欸啦喔、喜歡用電子零件打比方」。結果還可以，但模型的「梗」很生硬，像是在模仿，而且每次都要帶著這一大段說明。

他又試 RAG：把過去的訊息做成向量庫，每次找幾句相近的給模型參考。結果更怪：模型會「引用」他以前講過的話，而不是「用他的方式講新的話」。RAG 擅長「查資料」，不擅長「學風格」。

這時候才輪到微調：拿他過去的幾百則對話，讓模型真的「練習」用他的方式回覆，把習慣寫進參數裡。

但微調最難的不是訓練——第 11 章會看到，程式幾十行就寫完了。最難的是**資料**：要幾筆？什麼格式？哪些要丟？重複的怎麼辦？別人的訊息可以用嗎？這一章專門講這些。

## 核心概念

### 微調是什麼

《AI 怎麼運作》第 12 章講過，像 Claude 這類模型是先用大量文字「預訓練」出一個會接話的底座，再用人工整理的對話「微調」成會聽指令、會好好回答的助理。微調（Fine-tuning）就是：**拿一個已經訓練好的模型，用你自己的一小批資料再訓練一下，讓它的參數往你要的方向稍微移動。**

一個比喻：預訓練是讀完十二年國教，微調是進公司後的兩週新人訓練。新人訓練不會重教加減乘除，只教「我們公司的報告格式是這樣、客人問這個要這樣回」。資料少、時間短、但效果很針對。

微調改變的是模型的**參數**，所以它學到的東西會「內化」：不用每次在提示裡重講、也不用檢索。但也因為這樣，它學壞了也很難用提示扳回來，而且資料裡的錯誤和偏見會被一起學進去。

### 三種方法：提示、RAG、微調

| | 提示工程（第 6 章） | RAG（第 8 章） | 微調（第 10、11 章） |
|---|---|---|---|
| 改變什麼 | 每次送進去的文字 | 每次送進去的資料 | 模型本身的參數 |
| 適合教 | 任務說明、格式、角色 | 知識、事實、會變動的資料 | 風格、語氣、固定格式、專門領域的用語 |
| 要準備 | 一段好的說明與幾個範例 | 文件 + 向量庫 | 幾百到幾千筆高品質範例 + GPU |
| 做一次要多久 | 幾分鐘 | 幾小時 | 幾小時到幾天（含整理資料） |
| 資料更新 | 改提示就好 | 重建索引就好 | 要重新訓練 |
| 成本 | 每次呼叫多一些 token | 每次呼叫多幾段資料 | 一次訓練費用，之後每次呼叫更短 |
| 風險 | 提示太長、被忽略 | 檢索不到、亂講 | 過擬合、學到資料裡的錯、忘掉原本的能力 |

### 決策表：遇到需求時怎麼選

| 你的需求 | 先試 | 如果不夠 | 說明 |
|---|---|---|---|
| 「回答要用固定的 JSON 格式」 | 提示 + 結構化輸出（第 2 章） | 幾乎不需要微調 | 格式問題提示就能解決 |
| 「要知道我家／我公司的資料」 | RAG | 把 RAG 做好（切塊、評估） | 知識會變，微調不划算 |
| 「要用我的語氣講話」 | 提示 + few-shot 範例 | 微調 | 風格很難用文字描述清楚，用範例學最有效 |
| 「要懂某個領域的黑話、縮寫」 | 提示裡給對照表 | 微調 | 對照表太長時微調較好 |
| 「每次都要給一大段一樣的說明，太貴」 | 提示快取（第 6 章） | 微調 | 快取通常就夠了 |
| 「小模型做某個任務一直做不好」 | 換大模型、改提示 | 微調小模型 | 微調可以讓小模型在「單一任務」上接近大模型 |
| 「答案常常是編的」 | RAG + 要求引用 | 不要微調 | 微調不會解決亂講，反而可能更自信地亂講 |
| 「要學會新的事實（例如今年的新聞）」 | RAG | 不要微調 | 微調學事實效率很差又容易忘 |

兩條經驗法則：

1. **先提示、再 RAG、最後才微調。** 便宜的先試，大多數需求在前兩步就解決了。
2. **微調教「怎麼說」，RAG 教「說什麼」。** 兩個可以合用：一個用你的語氣回覆的模型，加上 RAG 提供它該講的事實。

### 資料集格式：指令／回應對

微調資料的基本單位是一組「輸入 → 期望的輸出」，叫指令／回應對（Instruction/Response Pair）。現在最通用的格式是「對話格式」：每筆資料是一段對話，有 system、user、assistant 三個角色，和第 1 章呼叫 API 時的 `messages` 長得一樣。

檔案用 JSONL（JSON Lines）：**一行一筆 JSON**，不是整個檔案一個大 JSON 陣列。好處是可以逐行讀、逐行加，壞掉一行不影響其他行，幾十萬筆也不用一次載進記憶體。

一筆長這樣（為了閱讀排版成多行，實際檔案裡是一行）：

```json
{"messages": [
  {"role": "system", "content": "你是小宇，一個國中生。回覆要簡短、口語、常用「欸」「啦」「喔」，喜歡用電子零件打比方。"},
  {"role": "user", "content": "Arduino 的燈不會亮怎麼辦"},
  {"role": "assistant", "content": "先量電壓喔，十次有八次是 LED 接反啦。"}
]}
```

三個角色各自的意義：

- **system**：這個模型的角色設定。微調時每筆都放同一句，訓練完之後使用時也放同一句，模型就會「認得」這是它該切換到的模式。
- **user**：別人說的話，也就是輸入。
- **assistant**：**你希望模型說的話**。這是模型真正在學的部分，品質決定一切。

另一種較舊的格式叫 Alpaca 格式：`{"instruction": "...", "input": "...", "output": "..."}`。網路上的資料集常見，意思一樣，第 11 章的工具兩種都吃，本書統一用對話格式。

### 資料品質比數量重要

微調的資料不用多。幾個常見的量級：

| 目的 | 大約筆數 | 說明 |
|---|---|---|
| 學一種固定格式（例如永遠回 JSON） | 50–200 | 格式很好學 |
| 學一種語氣／風格 | 200–1,000 | 本書活動的目標 |
| 學一個專門領域的問答 | 1,000–10,000 | 要涵蓋夠多情況 |
| 大幅改變模型行為 | 10,000 以上 | 已經超出個人專案 |

但「筆數」有一個前提：每一筆都是**你真的希望模型學會的樣子**。模型會一視同仁地學每一筆，包括：

- 你隨手敷衍的「嗯」「好」——它會學到「常常敷衍」。
- 你打錯字的那幾則——它會學到錯字。
- 你某次心情不好罵人的那則——它會學到罵人。
- 同一句話重複出現 20 次——它會覺得這句話超重要，動不動就講。

所以整理資料的順序是：**先刪、再補**。先把不想要的刪乾淨，剩下 150 筆乾淨的，遠比 500 筆混雜的好。

### 合成資料與去重

真實資料常常不夠。這時候大家會想到合成資料（Synthetic Data）：用現成的模型（例如 Claude）照你的風格「生」幾百筆，或者用程式把現有資料「變化」出更多筆。

合成有用，但有兩個陷阱：

1. **變化不等於資訊。** 把「明天要考數學欸」前面加個「嗨，」、後面加個「！」，看起來是三筆，但模型學到的東西和一筆一樣。等一下活動裡你會親眼看到：219 筆「看起來很多」的資料，去重後只剩 21 筆。
2. **模型生的像模型，不像你。** 用 Claude 生「小宇的語氣」，生出來的是「Claude 想像中的小宇」。少量用來補不足的情境可以，比例太高就會把你的風格洗掉。

去重（Deduplication）因此是整理資料的核心步驟，分兩層：

- **完全重複**：忽略空白、標點、大小寫之後一模一樣。用一個 `set` 記住看過的就行。
- **近似重複**：意思幾乎一樣但字有一點不同。這就用第 7 章的嵌入：兩筆的餘弦相似度超過某個門檻（例如 0.95）就視為重複，只留一筆。

### 訓練／驗證切分

整理好的資料不能全部拿去訓練。要留一小部分（通常 10%）當驗證集（Validation Set），訓練時不給模型看，訓練完拿來測：模型在「沒看過的資料」上表現如何。

為什麼？因為模型可以把訓練資料「背起來」。如果你只用訓練資料測，它會考 100 分，但遇到新訊息就露餡。這叫過擬合（Overfitting），《AI 怎麼運作》第 8 章講過。驗證集就是抓過擬合的工具：訓練集分數一直升、驗證集分數開始掉，就是背起來了，該停了。

切分要注意：**先去重再切分**。不然同一筆的兩個變體一個在訓練、一個在驗證，驗證就等於偷看答案。而且要固定亂數種子，這樣每次切出來一樣，才能比較不同次訓練的結果。

### 授權與隱私

整理對話資料會碰到別人的東西，這幾件事要先想清楚：

| 資料來源 | 可以用嗎 | 注意 |
|---|---|---|
| 你自己寫的訊息（assistant 那一側） | 可以 | 這是你的 |
| 別人傳給你的訊息（user 那一側） | 要小心 | 那是別人的話，拿去訓練前最好問過；至少去掉名字、電話、地址 |
| 網路上的公開資料集 | 看授權 | 很多標 CC BY 或 Apache 可以用；標「僅限研究」的就不能拿來做產品 |
| 用 Claude 等模型生成的 | 看服務條款 | 用來訓練自己的小模型通常可以，但要讀條款 |
| 公司、學校內部文件 | 要問 | 不是你的就不是你的 |

隱私的底線：**資料集裡不要有可以認出某個人的資訊**——電話、電子郵件、身分證字號、住址、全名。清洗腳本要有一關專門抓這些。還有，訓練好的模型會「記得」訓練資料，有人問它「小宇的電話幾號」它可能真的答出來。微調前刪掉，比訓練後再補救容易一百倍。

## 動手做

### 活動 10-1：整理一份 200 筆「用我的語氣回覆」的資料集

這個活動的主角是你自己的資料。作者提供工具和一份「練習用的合成資料」讓流程跑得起來，但真正的資料集要你自己蒐集。

**材料／工具**

- 你過去的對話紀錄（通訊軟體的匯出、郵件、留言），至少能找出 200 組「別人說 → 你回」
- 第 7 章的 venv（會用到 `sentence-transformers` 做去重）
- 資料夾 `ch10/`，檔案 `add_example.py`、`make_dataset.py`、`inspect_dataset.py`

**步驟**

1. 決定 system prompt。一句話描述「這個模型是誰、要怎麼講話」，之後每一筆都用同一句。寫得太細沒有用，風格是從 assistant 的範例學的，不是從這句學的。

2. 蒐集真實對話。有兩種做法：

   (a) 從通訊軟體匯出聊天紀錄，用程式把「對方訊息 → 你的下一則回覆」配對。各家匯出格式不同，這裡不提供通用程式；原則是一行一行讀、記住上一則是誰說的、換人說話時就配成一對。

   (b) 手動輸入。寫一個小工具一筆一筆加（`add_example.py`）：

```python
import json

# 一筆一筆手動輸入自己的對話，附加到 my_data.jsonl 的最後面
SYSTEM = "你是小宇，一個國中生。回覆要簡短、口語，喜歡用電子零件打比方。"

print("輸入對方的訊息與你的回覆，直接按 Enter 結束。")
count = 0
while True:
    q = input("對方說：").strip()
    if not q:
        break
    a = input("你回覆：").strip()
    row = {"messages": [
        {"role": "system", "content": SYSTEM},
        {"role": "user", "content": q},
        {"role": "assistant", "content": a},
    ]}
    # "a" 模式是附加，不會蓋掉之前的資料
    with open("my_data.jsonl", "a", encoding="utf-8") as f:
        f.write(json.dumps(row, ensure_ascii=False) + "\n")
    count += 1
print(f"這次新增了 {count} 筆")
```

   執行 `python add_example.py`，一問一答輸入，空白行結束。每天花十分鐘輸入 20 筆，十天就有 200 筆。

3. 如果你暫時沒有真實資料，先用作者的合成資料跑完流程。`make_dataset.py` 從 20 組種子對話「變化」出 210 筆，再故意混進幾筆髒資料：

random.seed(42)

    ("你週末要幹嘛", "應該在家焊東西啦，烙鐵剛買新的頭，超想試。"),
    ("Arduino 的燈不會亮怎麼辦", "先量電壓喔，十次有八次是 LED 接反啦。"),

    ("你覺得這題怎麼解", "欸這題用歐姆定律套就好，V 等於 I 乘 R 啦。"),
    ("晚餐吃什麼", "我媽說滷肉喔，你要來吃嗎。"),
    ("社團幾點", "週五三點啦，記得帶電錶喔。"),
    ("我的程式一直報錯", "先看最後一行錯誤訊息啦，那是電路的保險絲，一定從那邊找。"),

    ("可以教我焊接嗎", "可以喔，但要大人在場啦，烙鐵三百多度不是開玩笑的。"),
    ("你的腳踏車修好了嗎", "補胎補好了啦，內胎破一個洞而已喔。"),
    ("要不要一起做科展", "好啊，我想做綠豆發芽跟水溫的實驗欸，你負責記錄喔。"),
    ("這個 Wi-Fi 密碼多少", "貼在路由器底下啦，電視旁邊那台喔。"),
    ("你怎麼都不回訊息", "欸抱歉，在寫程式進入心流了啦。"),
    ("明天颱風會放假嗎", "不知道欸，先把陽台的盆栽搬進來比較實在喔。"),
    ("ESP32 跟 Arduino 差在哪", "ESP32 有 Wi-Fi 啦，像是會上網的 Arduino 喔。"),
    ("幫我看一下這段程式", "丟過來啦，先說喔，變數名字取好看一點。"),
    ("你喜歡貓還是狗", "貓欸，我家咪咪一天餵兩次，超好養啦。"),

PREFIX = ["", "欸 ", "嗨，", "問一下，", "請問 "]
SUFFIX = ["", "？", "～", "！", "。"]

rows = []
for i in range(210):
    q, a = random.choice(SEEDS)
    q = random.choice(PREFIX) + q + random.choice(SUFFIX)
    rows.append({"messages": [
        {"role": "system", "content": SYSTEM},
        {"role": "user", "content": q},
        {"role": "assistant", "content": a},

rows.append({"messages": [{"role": "system", "content": SYSTEM}, {"role": "user", "content": "  在嗎  "}, {"role": "assistant", "content": "   "}]})           # 空回覆

rows.append({"messages": [{"role": "system", "content": SYSTEM}, {"role": "user", "content": "信箱給我"}, {"role": "assistant", "content": "xiaoyu@example.com 喔"}]})     # 電子郵件
rows.append({"messages": [{"role": "user", "content": "少了 system 欸"}, {"role": "assistant", "content": "這筆格式不對啦"}]})                                              # 缺欄位

rows.append(rows[0])                                                                                                                                                  # 完全重複
for _ in range(3):
    rows.append(rows[5])                                                                                                                                              # 再重複三次

random.shuffle(rows)
with open("raw.jsonl", "w", encoding="utf-8") as f:

### 活動 10-2：寫資料清洗腳本

**材料／工具**

- 活動 10-1 的 `raw.jsonl`（或你自己的 `my_data.jsonl`，把檔名改一下）
- 新檔案 `clean_dataset.py`、`split_dataset.py`

**步驟**

1. 寫 `clean_dataset.py`，五關依序過濾，每關記錄剩幾筆：

```python
import json
import re
from sentence_transformers import SentenceTransformer, util

rows = [json.loads(line) for line in open("raw.jsonl", encoding="utf-8")]
report = {"原始": len(rows)}

# ---- 第 1 關：格式檢查（一定要有 system、user、assistant 三個角色）----
def valid(r):
    roles = [m.get("role") for m in r.get("messages", [])]
    return roles == ["system", "user", "assistant"]
rows = [r for r in rows if valid(r)]
report["格式正確"] = len(rows)

# ---- 第 2 關：整理空白、去掉空的或太短的回覆 ----
for r in rows:
    for m in r["messages"]:
        # 把連續空白壓成一個，再去掉頭尾空白
        m["content"] = re.sub(r"\s+", " ", m["content"]).strip()
rows = [r for r in rows if len(r["messages"][-1]["content"]) >= 4
        and len(r["messages"][1]["content"]) >= 2]
report["長度合格"] = len(rows)

# ---- 第 3 關：個資（電話、電子郵件）直接整筆丟掉 ----
PII = re.compile(r"(09\d{2}-?\d{3}-?\d{3})|([\w.]+@[\w.]+\.\w+)")
rows = [r for r in rows if not PII.search(r["messages"][-1]["content"])]
report["無個資"] = len(rows)

# ---- 第 4 關：完全重複（忽略大小寫與標點後一樣就算重複）----
def key(r):
    q = r["messages"][1]["content"]; a = r["messages"][-1]["content"]
    return re.sub(r"[\s，。！？~～!?.,]", "", (q + "|" + a).lower())
seen, unique = set(), []
for r in rows:
    k = key(r)
    if k not in seen:
        seen.add(k); unique.append(r)
rows = unique
report["去完全重複"] = len(rows)

# ---- 第 5 關：近似重複（用嵌入向量，相似度 > 0.95 視為同一筆）----
model = SentenceTransformer("paraphrase-multilingual-MiniLM-L12-v2")
texts = [r["messages"][1]["content"] + " " + r["messages"][-1]["content"] for r in rows]
vecs = model.encode(texts, normalize_embeddings=True)
sim = util.cos_sim(vecs, vecs)
keep = []
for i in range(len(rows)):
    # 只跟「已經決定保留」的比，太像就不留
    if all(sim[i][j] < 0.95 for j in keep):
        keep.append(i)
rows = [rows[i] for i in keep]
report["去近似重複"] = len(rows)

with open("clean.jsonl", "w", encoding="utf-8") as f:
    for r in rows:
        f.write(json.dumps(r, ensure_ascii=False) + "\n")

print("| 步驟 | 剩下筆數 |")
print("|---|---|")
for k, v in report.items():
    print(f"| {k} | {v} |")
```

## 常見錯誤與迷思

- **「微調可以讓模型學會新知識，例如我家的規則。」** → 效率很差，幾百筆資料學不到事實，而且規則一改就要重訓。 → 正確理解：事實用 RAG，微調留給風格、格式、領域用語。

- **「資料越多越好，先把能找到的全丟進去。」** → 模型會一視同仁地學每一筆，包括敷衍的、錯字的、情緒化的。 → 正確理解：先刪再補。150 筆乾淨的勝過 500 筆混雜的。

- **「用 Claude 生 1,000 筆就不用自己整理了。」** → 生出來的是「Claude 想像中的你」，比例太高會洗掉你的風格；而且變體很多但資訊很少。 → 正確理解：合成資料只用來補真實資料缺的情境，而且一樣要過去重。

- **「去重就是去掉一模一樣的。」** → 「明天要考數學欸」和「嗨，明天要考數學欸！」不一模一樣，但對模型來說是同一筆。 → 正確理解：要做兩層，完全重複用字串比對，近似重複用嵌入相似度。

- **「驗證集從訓練集裡隨便抄幾筆就好。」** → 那模型等於考試前看過考卷，分數沒有意義。 → 正確理解：先去重、再切分、訓練時絕對不給模型看驗證集。

- **「對方的訊息也是我的聊天紀錄，當然可以用。」** → 那是別人說的話，而且常常含有別人的個資。 → 正確理解：user 側盡量問過對方，至少把名字、電話、地址清掉；不確定就不要用。

- **「JSONL 和 JSON 一樣，整個檔案是一個陣列。」** → 錯，JSONL 是一行一筆，沒有最外層的 `[ ]` 和逗號。 → 正確理解：不用 `json.load()` 讀整檔，而是逐行 `json.loads(line)`。

## 想一想

1. 以下三個需求，各自該用提示、RAG 還是微調？(a) 讓模型永遠用三句話回答；(b) 讓模型知道社團這學期的器材清單；(c) 讓模型用阿公講話的口氣回覆。

<details><summary>參考答案</summary>

(a) 提示：格式類的要求一句話就能解決。(b) RAG：清單是會變的事實，放進向量庫檢索即可，改了重建索引就好。(c) 微調：口氣很難用文字描述清楚，要用幾百筆阿公的真實對話讓模型學；可以先試 few-shot 提示，不夠再微調。

</details>

2. 活動 10-2 的清洗表裡，「去完全重複」從 214 砍到 88，「去近似重複」從 88 砍到 21。請說明這兩關各抓到什麼樣的重複，以及為什麼完全重複那關抓不到第二種。

<details><summary>參考答案</summary>

完全重複那關先把空白和標點去掉再比，所以「明天要考數學欸」「明天要考數學欸！」「明天要考數學欸？」被視為同一筆；但「嗨，明天要考數學欸」多了「嗨」這個字，字串就不一樣了，它抓不到。近似重複那關用嵌入向量，「嗨，明天要考數學欸」和「明天要考數學欸」的餘弦相似度超過 0.95，就被判為同一筆。字串比對抓「字一樣」，嵌入抓「意思一樣」，這正是第 7 章的主題。

</details>

3. 小宇的資料集裡有 30 筆回覆是「好」「嗯」「OK」。他覺得這也是他的風格（他真的常這樣回），不想刪。你會怎麼建議？

<details><summary>參考答案</summary>

兩個角度。第一，這些回覆沒有資訊，模型學到的只是「常常敷衍」，之後別人問正經問題它也可能回「嗯」。第二，如果「簡短回應」真的是他風格的一部分，可以保留少數幾筆（例如 3 到 5 筆）當作「有時候會這樣」，而不是 30 筆讓它變成主流。清洗腳本裡「長度至少 4 字」那關會把這些全刪，他可以把門檻改成 2 字再手動挑幾筆留著。總之比例要對：訓練資料的分布就是模型之後的行為分布。

</details>

4. 為什麼要「先去重再切分」而不是「先切分再去重」？舉一個具體的例子說明後者會出什麼問題。

<details><summary>參考答案</summary>

先切分的話，「明天要考數學欸」可能被分到訓練集，「嗨，明天要考數學欸！」被分到驗證集。訓練時模型看過前者，驗證時遇到後者幾乎等於同一題，它會答得很好，驗證分數虛高，你以為模型學會了「小宇的風格」，其實它只是背了那句話。先去重再切分，就保證驗證集裡的每一筆都是模型真的沒看過的。

</details>

5. （挑戰）請擴充 `clean_dataset.py` 的第 3 關，再抓三種個資：身分證字號（一個大寫英文字母加 9 個數字）、LINE ID（例如「我的 LINE 是 xxx」）、地址（含「路」「段」「號」）。寫出正規表達式，並想一想：地址那條會不會誤殺正常句子？

<details><summary>參考答案</summary>

身分證：`[A-Z]\d{9}`。LINE ID：`LINE\s*(ID|是|：|:)\s*\S+`（不分大小寫，用 `re.IGNORECASE`）。地址：`\S+(路|街)\S*(段|巷|弄)?\S*號`。地址那條很容易誤殺：「這條路走到底」「下一段再說」不含「號」所以不會中，但「這題我寫到第 3 號」會中。解法是個資過濾不要直接刪，改成「標記出來讓人看」：把疑似含個資的筆數和內容印出來，人工確認後再決定。清洗腳本的原則是「寧可多印給人看，不要默默刪」。

</details>

6. （挑戰）如果你想做的不是「像我的語氣」，而是「社團的 Arduino 助教」：回答社員關於接線與除錯的問題。請設計這個資料集：system prompt 怎麼寫、user 和 assistant 各從哪裡來、要幾筆、有什麼授權與隱私問題、要不要搭配 RAG。

<details><summary>參考答案</summary>

system：「你是 Arduino 社團的助教，用繁體中文、先問清楚接線再給建議，答案要附上要量哪裡的電壓。」user：社員真的問過的問題（社團群組、紙本提問單），要去掉學號和名字並徵得同意；也可以請老師和幾位社員各寫 30 個「新手常問的問題」補足。assistant：老師或資深社員寫的「理想回答」，不要用模型生的，因為助教的價值就在「老師會怎麼教」。筆數：300 到 800 筆，涵蓋接線、程式錯誤、零件選擇、安全四類。授權：社員的問題要同意書，老師的回答要老師同意用於訓練。RAG：要搭配，因為「這學期的器材清單」「社團時間」是會變的事實，放 RAG；微調只負責「助教的講法」。

</details>

## 本章小結

- 微調是用你的一小批資料再訓練一次已有的模型，改變的是參數，學到的東西會內化。
- 先提示、再 RAG、最後才微調；微調教「怎麼說」，RAG 教「說什麼」。
- 資料集用 JSONL（一行一筆），每筆是 system／user／assistant 三段對話；assistant 那段是模型真正在學的。
- 資料品質比數量重要：模型一視同仁地學每一筆，先刪再補，150 筆乾淨的勝過 500 筆混雜的。
- 合成資料看起來多、資訊少；本章實測 219 筆去重後剩 21 筆。去重要做兩層：字串比對抓完全重複、嵌入相似度抓近似重複。
- 先去重再切分，固定亂數種子，10% 留作驗證集，訓練時絕對不給模型看。
- 個資（電話、郵件、身分證、地址）在訓練前刪掉；別人的訊息要問過；公開資料集看授權。
- 清洗腳本的輸出要是一張「每關剩幾筆」的表，讓你看得見每一刀砍掉了什麼。

| 微調 | Fine-tuning | 用少量自己的資料再訓練已有的模型，調整它的參數 |
| 預訓練 | Pre-training | 用大量文字訓練出會接話的底座模型 |
| 指令／回應對 | Instruction/Response Pair | 一組「輸入」與「期望輸出」，是微調資料的基本單位 |
| 對話格式 | Chat Format | 用 system／user／assistant 三個角色表示一筆資料的格式 |
| JSONL | JSON Lines | 一行一筆 JSON 的文字檔格式 |
| 合成資料 | Synthetic Data | 用模型或程式產生、而非真實蒐集的資料 |
| 去重 | Deduplication | 移除完全或近似重複的資料 |
| 近似重複 | Near-duplicate | 字不完全一樣但意思幾乎相同的兩筆資料 |
| 訓練集 | Training Set | 給模型學習用的資料 |
| 驗證集 | Validation Set | 訓練時不給模型看、用來檢查它有沒有真的學會的資料 |
| 過擬合 | Overfitting | 模型把訓練資料背起來，遇到新資料就表現變差 |
| 個人識別資訊 | Personally Identifiable Information (PII) | 能認出某個人的資料，例如電話、郵件、身分證字號 |
| 正規表達式 | Regular Expression | 描述文字模式的小語言，用來找電話、郵件等固定格式 |
| 亂數種子 | Random Seed | 固定它可以讓「隨機」的結果每次都一樣 |
| 授權 | License | 資料或程式的使用許可條款 |
