# 第 7 章　嵌入與向量搜尋

## 本章目標

學完這一章，你會：

- 說出嵌入（Embedding）是什麼：把一句話變成一串數字，而且意思相近的句子數字也相近。
- 用餘弦相似度（Cosine Similarity）算出兩個向量像不像，並且自己手算一個小例子。
- 用 sentence-transformers 在自己的電腦上跑一個小型多語言嵌入模型，不需要 API 金鑰。
- 用 chromadb 把 50 條筆記存成向量資料庫，並用一句話查出最相關的幾條。
- 比較關鍵字搜尋和向量搜尋的差別，知道各自在什麼時候會失敗。
- 知道中文在嵌入時要注意的幾件事：繁簡、空格、否定詞。

## 開場：找不到那條筆記

小宇的手機備忘錄裡有兩百多條筆記：外婆家鑰匙放哪、冷氣濾網上次什麼時候洗、Arduino 的 LED 要配幾歐姆的電阻……某天晚上他翻來覆去睡不著，想起自己好像記過「睡前不要滑手機」之類的提醒，就在備忘錄搜尋「睡不著」。

結果：找不到。

他明明記過。後來他一條一條翻，才在第 43 條找到：「睡前一小時不要看手機，藍光會讓人比較難入睡。」原來他當初寫的是「難入睡」，不是「睡不著」。手機的搜尋只認得「一模一樣的字」，意思一樣但字不一樣，它就當作沒看到。

這就是關鍵字搜尋的天生限制：它比的是「字」，不是「意思」。「睡不著」和「難入睡」對你來說是同一件事，對手機來說卻是兩串毫無關係的字。

這一章要教電腦「比意思」：把每一句話變成一串數字——一個向量——而且意思接近的句子，數字也接近。這樣「找意思相近的筆記」就變成「找數字相近的向量」，而這是電腦最擅長的事。這個技術叫嵌入，它是下一章 RAG 的地基。

## 核心概念

### 關鍵字搜尋的極限

先把問題講清楚。關鍵字搜尋（Keyword Search）的做法很直接：你輸入幾個字，它去每一份文件裡找「有沒有出現這幾個字」，出現越多次、或出現越多個字的排越前面。

它有三個天生的弱點：

| 弱點 | 例子 | 發生什麼事 |
|---|---|---|
| 同義詞 | 搜「睡不著」，筆記寫「難入睡」 | 字不同，找不到 |
| 跨語言 | 用英文搜中文筆記 | 完全對不上 |
| 字面巧合 | 搜「蘋果手機」，找到「我早餐吃蘋果」 | 字有對上，意思無關 |

它當然也有優點：快、簡單、找「專有名詞」或「代號」特別準（搜「ESP32」就是要 ESP32，不要別的）。所以真正的系統通常是兩種都用，這一章先把向量搜尋學會，第 8 章再談怎麼合併。

### 嵌入：把一句話變成一個點

嵌入（Embedding）的意思是：用一個模型把一段文字變成一個固定長度的數字列表，也就是一個向量（Vector）。你在《AI 怎麼運作》第 10 章看過「詞向量」：把「國王」「女王」各變成一串數字，讓意思相近的詞住得近。這一章用的是「句子嵌入」，把整句話變成一個向量，道理一樣，只是對象從一個詞變成一句話。

想像一張很大的地圖，每一句話都是地圖上的一個點。嵌入模型就是那個「決定每句話該放在哪裡」的人，它受過訓練，會把意思相近的句子放在附近：「今天天氣很好」和「The weather is nice today」會被放在隔壁，「我想吃拉麵」會放在很遠的另一區。

只是這張地圖不是 2 維的，而是幾百維的。我們這章用的模型輸出 384 維，也就是每一句話變成 384 個數字。人腦想像不了 384 維，但沒關係，「兩點離得近不近」這件事在任何維度都算得出來。

這些數字本身沒有「第 17 個數字代表天氣」這種可讀的意思。它們是模型從幾億句話裡自己學出來的特徵，我們只管一件事：**相近的意思 → 相近的向量**。

### 餘弦相似度：量方向像不像

有了向量，怎麼量「像不像」？最常用的是餘弦相似度（Cosine Similarity）。它量的是兩個向量「方向」的夾角：方向完全一樣是 1，互相垂直（無關）是 0，方向完全相反是 −1。

公式（你在《AI 怎麼運作》第 4 章和第 10 章見過）：

```
                    a · b            （內積：對應位置相乘再相加）
餘弦相似度 = ─────────────────────
               |a| × |b|            （兩個向量各自的長度相乘）
```

用三個迷你向量手算一次。假設每個向量有三個特徵：「甜不甜」「是不是水果」「是不是動物」：

| 詞 | 向量 |
|---|---|
| 蘋果 | [1, 1, 0] |
| 香蕉 | [1, 1, 0] |
| 狗 | [0, 0, 1] |
| 蛋糕 | [2, 2, 0] |

蘋果 vs 狗：內積 = 1×0 + 1×0 + 0×1 = 0，所以相似度 = 0，無關。

蘋果 vs 蛋糕：內積 = 1×2 + 1×2 + 0×0 = 4；|蘋果| = √(1+1+0) = √2 ≈ 1.414；|蛋糕| = √(4+4+0) = √8 ≈ 2.828；相似度 = 4 ÷ (1.414 × 2.828) = 4 ÷ 4 = 1。

注意這個結果：蛋糕的數字是蘋果的兩倍，但餘弦相似度還是 1。因為餘弦只看「方向」不看「長度」。這就是為什麼大家用餘弦而不用「直接相減」：一句長句子和一句短句子，向量長度可能差很多，但如果意思一樣，方向就會一樣。

用 Python 把這個算法寫出來（`cosine_by_hand.py`）：

```python
import math

def cosine(a, b):
    """用定義算餘弦相似度：內積 ÷ (長度 a × 長度 b)"""
    # 內積：對應位置相乘再相加
    dot = sum(x * y for x, y in zip(a, b))
    # 長度：每個數字平方相加再開根號
    len_a = math.sqrt(sum(x * x for x in a))
    len_b = math.sqrt(sum(y * y for y in b))
    return dot / (len_a * len_b)

# 三個「迷你向量」，想像每個數字是一個特徵分數
apple  = [1, 1, 0]   # 甜、是水果、不是動物
banana = [1, 1, 0]   # 一模一樣的方向
dog    = [0, 0, 1]   # 完全不同的方向
cake   = [2, 2, 0]   # 跟蘋果同方向，只是數字放大兩倍

print("蘋果 vs 香蕉：", round(cosine(apple, banana), 3))
print("蘋果 vs 狗　：", round(cosine(apple, dog), 3))
print("蘋果 vs 蛋糕：", round(cosine(apple, cake), 3))
```

執行結果：

```
蘋果 vs 香蕉： 1.0
蘋果 vs 狗　： 0.0
蘋果 vs 蛋糕： 1.0
```

跟手算一樣。真實的嵌入向量有 384 個數字，算法完全相同，只是迴圈跑 384 次。

### 真的跑一個嵌入模型

接下來不用手刻向量了，我們請一個訓練好的模型來做。這章用 `sentence-transformers` 這個套件，模型選 `paraphrase-multilingual-MiniLM-L12-v2`：它支援中文、英文等 50 多種語言，只有 1 億多個參數，下載約 470 MB，一般筆電不用顯示卡也跑得動。第一次執行會自動下載到你家目錄的快取資料夾，之後就不用再下載。

```python
from sentence_transformers import SentenceTransformer

# 載入一個小型的多語言嵌入模型（第一次會自動下載，約 470 MB）
# 這個模型支援中文、英文等 50 多種語言
model = SentenceTransformer("paraphrase-multilingual-MiniLM-L12-v2")

# 準備四句話：兩句意思一樣但語言不同、一句無關、一句字面相似但意思不同
sentences = [
    "今天天氣很好",
    "The weather is nice today",
    "我想吃拉麵",
    "今天天氣很差",
]

# encode() 會把每句話變成一個向量（一串數字）
vectors = model.encode(sentences)

# 看看向量的形狀：4 句話，每句 384 個數字
print("向量形狀：", vectors.shape)
print("第一句的前 5 個數字：", vectors[0][:5].round(4))
```

執行結果（作者機器上第一次連下載約 35 秒，之後載入約 3 秒）：

```
向量形狀： (4, 384)
第一句的前 5 個數字： [ 0.1848  0.2423 -0.0128  0.0972  0.0807]
```

`(4, 384)` 就是「4 句話、每句 384 個數字」。那 384 個數字你看不出意思，沒關係，重點是下一步：算它們之間的餘弦相似度。`sentence_transformers.util.cos_sim` 可以一次算出「每句對每句」的表：

```python
from sentence_transformers import SentenceTransformer, util

# 載入模型（和前面同一個，已下載過就不會再下載）
model = SentenceTransformer("paraphrase-multilingual-MiniLM-L12-v2")

sentences = [
    "今天天氣很好",
    "The weather is nice today",
    "我想吃拉麵",
    "今天天氣很差",
]
vectors = model.encode(sentences)

# util.cos_sim 會算出「每一句對每一句」的餘弦相似度矩陣
sim = util.cos_sim(vectors, vectors)

# 印成表格：列是第 i 句，欄是第 j 句
print("       ", "  ".join(f"句{j+1}" for j in range(len(sentences))))
for i, s in enumerate(sentences):
    row = "  ".join(f"{sim[i][j]:.2f}" for j in range(len(sentences)))
    print(f"句{i+1}   {row}   ← {s}")
```

執行結果：

```
        句1  句2  句3  句4
句1   1.00  0.88  0.16  0.35   ← 今天天氣很好
句2   0.88  1.00  0.10  0.29   ← The weather is nice today
句3   0.16  0.10  1.00  0.12   ← 我想吃拉麵
句4   0.35  0.29  0.12  1.00   ← 今天天氣很差
```

讀這張表：

- 對角線都是 1.00：自己跟自己當然最像。
- 句 1 和句 2（中文與英文的「天氣很好」）：0.88，非常像。模型「看穿」了語言，比的是意思。
- 句 1 和句 3（天氣 vs 拉麵）：0.16，幾乎無關。
- 句 1 和句 4（天氣很好 vs 天氣很差）：只有 0.35。它們只差一個字，關鍵字搜尋會覺得超像，但嵌入模型知道「好」和「差」意思相反，把它們拉開了。不過也沒有拉到 0，因為它們畢竟都在講天氣。

這張表就是這一章的精華：**嵌入讓電腦能比「意思」，而不是比「字」。**

### 向量資料庫：幫你找最近的鄰居

現在你會把句子變向量，也會算相似度。要做搜尋，流程就是：

```
建索引（做一次）
  每條筆記 ──嵌入模型──▶ 向量 ──▶ 存起來（連同原文）

查詢（每次問）
  問題 ──嵌入模型──▶ 問題向量 ──▶ 跟所有筆記向量算相似度 ──▶ 取最高的 k 條
```

50 條筆記的話，用一個迴圈算 50 次餘弦就好。但如果是 5 萬條、500 萬條呢？每問一次都算幾百萬次內積會太慢。向量資料庫（Vector Database）就是專門解決這件事的工具：它把向量存起來，並且用特別的索引結構（常見的叫 HNSW，你可以想成「先分區再找」的地圖）讓「找最近的 k 個」在幾百萬筆裡也只要幾毫秒。

這本書用 chromadb。它是一個用 Python 就能裝、資料直接存在一個資料夾裡、不用架伺服器的向量資料庫，非常適合個人專案。它的幾個基本動作：

| 動作 | 程式 | 說明 |
|---|---|---|
| 開資料庫 | `chromadb.PersistentClient(path="資料夾")` | 資料存在這個資料夾，關機不會消失 |
| 建集合 | `client.get_or_create_collection(name=...)` | 一個集合像一張表 |
| 加資料 | `collection.add(ids=, documents=, embeddings=)` | id 要唯一；原文和向量一起存 |
| 查詢 | `collection.query(query_embeddings=, n_results=k)` | 回傳最近的 k 筆 |

一件要知道的事：chromadb 回傳的不是「相似度」而是「距離」。選用餘弦距離時，距離 = 1 − 餘弦相似度，所以距離 0 是最像、距離 1 是無關。書裡的程式都會把它換算回相似度印出來，讀起來比較直覺。

### 中文的注意事項

多語言嵌入模型處理中文已經很不錯，但有幾件事值得先知道。作者用模型實測了五組句子（`chinese_notes.py`）：

| 相似度 | 句子 A | 句子 B | 說明 |
|---|---|---|---|
| 0.98 | 電腦程式設計 | 电脑程序设计 | 繁體、簡體幾乎當成一樣 |
| 0.99 | 我喜歡吃蘋果 | 我 喜歡 吃 蘋果 | 有沒有空格幾乎沒差 |
| 0.90 | 腳踏車後輪沒氣 | 單車後輪爆胎 | 不同說法同一件事，抓得到 |
| 0.43 | 今天天氣很好 | 今天天氣不好 | 否定詞有拉開，但不算很遠 |
| 0.95 | 機器學習 | Machine Learning | 中英對照很穩 |

結論：

1. **繁簡不用先轉換。** 但如果你的筆記混了繁簡，建議還是統一，因為查詢結果的「顯示」會混在一起不好看。
2. **不需要先斷詞。** 《AI 怎麼運作》第 10 章提過中文沒有空格要自己切，但現代嵌入模型內建子詞切法，整句丟進去就好。
3. **否定詞是弱點。** 「很好」和「不好」只拉到 0.43，不是 0。如果你的資料裡有很多「可以／不可以」「要／不要」這種只差一個字的規則，向量搜尋可能分不清楚。第 8 章會講怎麼用「重排」和「讓 AI 讀上下文」來補救。
4. **太短的查詢效果差。** 只打一個詞「鑰匙」會比打「鑰匙放在哪裡」差一點，因為模型是用句子訓練的。
5. **專有名詞和代號**（型號、縮寫、人名）向量模型不一定認得，這種時候關鍵字搜尋反而準。

```python
import chromadb
from sentence_transformers import SentenceTransformer

# 載入同一個嵌入模型（查詢的向量要和存進去的向量用同一個模型算）
model = SentenceTransformer("paraphrase-multilingual-MiniLM-L12-v2")

# 打開剛才建好的資料庫與集合
client = chromadb.PersistentClient(path="my_notes_db")
collection = client.get_collection("notes")

def search(question, k=3):
    """把問題變向量，找出最相近的 k 條筆記"""
    q_vec = model.encode(question).tolist()
    result = collection.query(query_embeddings=[q_vec], n_results=k)
    print(f"\n問：{question}")
    # result 裡的 documents 與 distances 都是「每個查詢一個列表」，所以取 [0]
    for doc, dist in zip(result["documents"][0], result["distances"][0]):
        # chromadb 回傳的是「餘弦距離」= 1 − 餘弦相似度，所以換算回相似度
        print(f"  相似度 {1 - dist:.2f}｜{doc}")

search("鑰匙在哪裡")
search("怎麼量電流")
search("晚上睡不著怎麼辦")
search("what is RAG")
```

### 活動 7-2：關鍵字搜尋 vs 向量搜尋

**材料／工具**

- 活動 7-1 做好的 `my_notes_db` 資料庫與 `notes.py`
- 新檔案 `compare_search.py`

**步驟**

1. 寫一個很簡單的關鍵字搜尋：把問題拆成一個一個字，去掉「的、了、嗎」這類虛字，數每條筆記裡出現了幾個字，多的排前面。這是很陽春的做法，但真實搜尋引擎的核心（叫 BM25）也是類似的「算字出現幾次」的想法。
2. 寫一個向量搜尋，和活動 7-1 一樣。
3. 準備五個問題，故意設計成不同類型：字面對得上的、同義詞的、簡體字的、英文的、換一種說法的。
4. 兩種方法各跑一次，並排印出來。

```python
import chromadb
from sentence_transformers import SentenceTransformer
from notes import NOTES

model = SentenceTransformer("paraphrase-multilingual-MiniLM-L12-v2")
client = chromadb.PersistentClient(path="my_notes_db")
collection = client.get_collection("notes")

def keyword_search(question, k=3):
    """關鍵字搜尋：數每條筆記裡「出現了幾個問題裡的字」，多的排前面"""
    # 把問題拆成單字，去掉常見的虛字
    stop = set("的了嗎呢怎麼要在哪裡是什麼我你他")
    chars = [c for c in question if c.strip() and c not in stop]
    scored = []
    for note in NOTES:
        # 分數 = 問題裡有幾個字出現在這條筆記
        score = sum(1 for c in chars if c in note)
        if score > 0:
            scored.append((score, note))
    # 分數高的排前面，取前 k 條
    scored.sort(key=lambda x: -x[0])
    return scored[:k]

def vector_search(question, k=3):
    """向量搜尋：問題變向量，找最相近的 k 條"""
    q_vec = model.encode(question).tolist()
    r = collection.query(query_embeddings=[q_vec], n_results=k)
    return [(1 - d, doc) for doc, d in zip(r["documents"][0], r["distances"][0])]

questions = [
    "鑰匙在哪裡",          # 字面有對上
    "晚上睡不著怎麼辦",      # 筆記裡寫的是「入睡」，字面對不上
    "钥匙在哪里",           # 簡體字
    "how to measure current",  # 英文問中文筆記
    "貓咪幾點吃飯",          # 筆記寫「餵」，問題寫「吃飯」
]

for q in questions:
    print(f"\n===== 問：{q}")
    print("【關鍵字搜尋】")
    kw = keyword_search(q)
    if not kw:
        print("  （找不到任何結果）")
    for score, note in kw:
        print(f"  命中 {score} 字｜{note}")
    print("【向量搜尋】")
    for sim, note in vector_search(q):
        print(f"  相似度 {sim:.2f}｜{note}")
```

## 常見錯誤與迷思

- **「向量裡的每個數字都有意思，可以解讀。」** → 錯。那 384 個數字是模型自己學出來的內部表示，沒有「第 5 格代表溫度」這種對應。 → 正確理解：只有向量之間的「相對位置」有意義，我們永遠是比兩個向量，不是看一個向量。

- **「相似度 0.6 代表 60% 相關。」** → 錯。餘弦相似度不是百分比，不同模型的數字分布差很多，有的模型「無關」是 0.3、有的是 0.0。 → 正確理解：它只能拿來「排序」和「同一個模型內設門檻」。你要用自己的資料實際看幾個例子，才知道這個模型的「好」大概是幾分。

- **「建索引用 A 模型，查詢用 B 模型也可以。」** → 錯。不同模型的向量空間完全不一樣，就像兩張不同比例尺、不同方向的地圖，座標對不上。 → 正確理解：存進去和查詢一定用同一個模型。換模型就要全部重新嵌入。

- **「向量搜尋比關鍵字搜尋好，所以關鍵字可以丟掉了。」** → 錯。活動 7-2 看到兩者平手的題目不少，而且對型號、代號、人名這種「必須一字不差」的查詢，關鍵字反而穩。 → 正確理解：實務上常常兩個都做，再把結果合併（叫混合搜尋）。

- **「把一整篇文章嵌入成一個向量就好。」** → 不好。一篇文章講十件事，壓成一個向量後每件事都變模糊，查任何一件事都只能得到中等分數。 → 正確理解：要先切成小段再嵌入，這就是第 8 章要講的「切塊」。

- **「中文一定要先斷詞、繁簡要先轉。」** → 現在的多語言模型不需要。實測繁簡相似度 0.98、有無空格 0.99。 → 正確理解：直接整句丟進去。但否定詞和專有名詞仍然是弱點，要靠其他方法補。

- **「`collection.add` 可以重複執行，加越多越好。」** → 用同樣的 id 重複 add 會出錯或覆蓋，用不同 id 重複加同一條筆記則會讓它在結果裡出現兩次。 → 正確理解：重建索引前先刪掉舊集合，或用 `get_or_create_collection` 搭配固定 id。

## 想一想

1. 向量 a = [3, 4]、b = [6, 8]，餘弦相似度是多少？它們「一樣」嗎？

<details><summary>參考答案</summary>

內積 = 3×6 + 4×8 = 18 + 32 = 50；|a| = √(9+16) = 5；|b| = √(36+64) = 10；相似度 = 50 ÷ (5×10) = 1。方向完全一樣，所以餘弦相似度是 1，雖然 b 的長度是 a 的兩倍。這正是餘弦相似度的特性：只看方向不看長度。

</details>

2. 你在活動 7-1 裡看到「怎麼量電流」第一名是「歐姆定律」那條，而不是「三用電錶……量電流要串聯」那條。你覺得為什麼？這算是錯嗎？

<details><summary>參考答案</summary>

歐姆定律那條整句都在講電壓、電流、電阻三者的關係，「電流」這個概念在裡面非常核心；三用電錶那條同時講了電壓、電流、電阻三種量法，「量電流」只佔三分之一。對嵌入模型來說，前者整體更貼近「電流」這個主題。這不算錯，因為兩條都在前三名，而且使用者要的資訊確實在第二名裡。這也是為什麼 RAG 通常取前 3 到 5 條，而不是只取第一名。

</details>

3. 如果有人把 50 條筆記裡的「睡前一小時不要看手機……」改成英文「Don't look at your phone an hour before bed; blue light makes it harder to fall asleep.」，再用中文問「晚上睡不著怎麼辦」，你預測還找得到嗎？為什麼？

<details><summary>參考答案</summary>

找得到，而且相似度不會差太多。本章用的是多語言模型，實測「今天天氣很好」和英文版的相似度是 0.88、「機器學習」和「Machine Learning」是 0.95，模型比的是意思不是語言。不過如果你用的是「只訓練英文」的嵌入模型（很多熱門模型是這樣），中文查詢就會變得很差。選模型時要看它支不支援你的語言。

</details>

4. 向量資料庫回傳「距離 0.37」，這條筆記的餘弦相似度是多少？如果你想設「相似度低於 0.4 就不顯示」的門檻，距離要設在幾？

<details><summary>參考答案</summary>

相似度 = 1 − 0.37 = 0.63。門檻：相似度 0.4 對應距離 1 − 0.4 = 0.6，所以「距離大於 0.6 就不顯示」。

</details>

5. （挑戰）請修改 `compare_search.py`，做一個「混合搜尋」：把關鍵字搜尋和向量搜尋的結果合併，兩邊都出現的筆記排最前面。想一想要怎麼合併兩種完全不同尺度的分數（一個是「命中幾個字」，一個是「相似度 0 到 1」）。

<details><summary>參考答案</summary>

最簡單的作法是不用分數、用「名次」：兩種方法各取前 5 名，給第 1 名 5 分、第 2 名 4 分……第 5 名 1 分，同一條筆記在兩邊的分數相加，再依總分排序。這叫「名次融合」，不用煩惱尺度問題。實作上就是建一個 `dict`，key 是筆記內容、value 是累計分數，兩個列表各跑一次迴圈加分，最後 `sorted(scores.items(), key=lambda x: -x[1])`。試試看「鑰匙在哪裡」會不會還是第一名，「ESP32」這種代號會不會變得更穩。

</details>

6. （挑戰）如果你的筆記有 5,000 條，而不是 50 條，`build_index.py` 哪一行會最慢？你會怎麼改，讓它不用每次都全部重做？

<details><summary>參考答案</summary>

最慢的是 `model.encode(NOTES)`，5,000 條在沒有顯示卡的筆電上大約要幾分鐘。改法：(1) 只嵌入「新增的」筆記——先用 `collection.get()` 拿出已存在的 id，跳過已經在裡面的；(2) 分批 encode（例如一次 256 條）並印進度，避免看起來像當機；(3) 把 `batch_size` 參數調大一點，`model.encode(NOTES, batch_size=64)`，在有 GPU 的 Colab 上會明顯變快。另外 chromadb 的 `PersistentClient` 本來就會把資料留在硬碟，所以查詢端不用重做，只有建索引端要處理增量。

</details>

## 本章小結

- 關鍵字搜尋比的是「字」，遇到同義詞、跨語言、換個說法就失靈；嵌入讓電腦能比「意思」。
- 嵌入模型把一句話變成一個固定長度的向量（本章是 384 維），意思相近的句子向量也相近。
- 餘弦相似度 = 內積 ÷ 兩個長度的乘積，只看方向不看長度，1 最像、0 無關。
- sentence-transformers 加上小型多語言模型，不用顯示卡、不用金鑰，筆電就能跑。
- chromadb 把向量和原文存在一個資料夾裡，用 `add` 存、用 `query` 找最近的 k 筆；它回傳的是距離，相似度 = 1 − 距離。
- 建索引和查詢一定用同一個嵌入模型。
- 中文不用先斷詞或繁簡轉換，但否定詞和專有名詞是弱點。
- 向量搜尋不是取代關鍵字搜尋，實務上常常兩個都用。

## 名詞表

| 中文 | 英文 | 一句話解釋 |
|---|---|---|
| 嵌入 | Embedding | 用模型把文字變成一串固定長度的數字，意思相近的數字也相近 |
| 向量 | Vector | 一串數字，可以想成高維空間裡的一個點或一個箭頭 |
| 餘弦相似度 | Cosine Similarity | 量兩個向量方向的相似程度，1 最像、0 無關、−1 相反 |
| 內積 | Dot Product | 兩個向量對應位置相乘再相加 |
| 向量資料庫 | Vector Database | 專門存向量並快速找出最相近幾筆的資料庫 |
| 集合 | Collection | chromadb 裡的一張表，裝一組 id、原文與向量 |
| 索引 | Index | 把資料整理成方便快速查找的結構；也指「建索引」這個動作 |
| 關鍵字搜尋 | Keyword Search | 比對文字裡有沒有出現查詢的字 |
| 混合搜尋 | Hybrid Search | 同時做關鍵字搜尋與向量搜尋，再把結果合併 |
| 最近鄰搜尋 | Nearest Neighbor Search | 在一堆向量裡找離查詢向量最近的 k 個 |
| 句子嵌入 | Sentence Embedding | 把整句話（而不是單一個詞）變成一個向量 |
| 多語言模型 | Multilingual Model | 同時訓練多種語言，讓不同語言的同義句向量相近 |
