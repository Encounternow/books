# 第 1 章　用程式呼叫 AI

## 本章目標

學完這一章，你會：

- 說出 API 是什麼，以及「在聊天視窗打字」和「用程式呼叫」差在哪裡。
- 用 `anthropic` 套件送出第一次請求，讀懂回覆物件裡的 `content`、`stop_reason` 與 `usage`。
- 正確使用 system prompt 與 `messages` 結構，做出會記得前面對話的多輪聊天。
- 用串流（stream）讓回覆一邊產生一邊顯示，並開啟 thinking 讓模型先想再答。
- 處理錯誤、保管金鑰，並且算得出一次呼叫大概要花多少錢。

## 開場：小安的新聞摘要

小安每天早上都想知道三件事：今天有什麼大新聞、今天要不要帶傘、今天學校有什麼活動。她以前的做法是打開聊天 AI，把三篇新聞貼進去，打「幫我各用三句話摘要」，再把答案複製到筆記 App。每天五分鐘，一個月就是兩個半小時。

她想：「如果我能寫一個程式，每天早上自動做這件事，然後把結果傳到我手機呢？」問題在於聊天視窗是給人用的，程式沒辦法「打開網頁、貼文章、按送出」。她需要一個**程式能呼叫的入口**。

這個入口就叫 API。這一章我們要做的，就是用 Python 走進這個入口，讓 AI 變成你程式裡的一個函式：丟文字進去，拿文字出來。學會這件事之後，摘要、翻譯、分類、聊天機器人，都只是「換一段提示」的差別。

本章的兩個活動就是小安計畫的前半段：先做一個會記得對話的聊天機器人，再做一個「文章進、三句出」的摘要工具。後半段（自動抓新聞、傳到手機）要等第 2 章的工具與第 5 章的排程。

## 核心概念

### API 是什麼：餐廳的點餐窗口

**API（Application Programming Interface，應用程式介面）**是「程式跟程式講話的約定」。想像一家餐廳：你不能直接走進廚房自己煮，但你可以在窗口點餐，說清楚「一碗牛肉麵、不要蔥」，廚房做好再從窗口交給你。窗口規定了你能點什麼、怎麼點、會拿到什麼。

呼叫 Claude 的 API 也是一樣：你（程式）把一份「訂單」送到 Anthropic 的伺服器，訂單裡寫著用哪個模型、要講什麼、最多回多少字；伺服器把模型的回覆用固定格式送回來。這份訂單和回覆都是 **JSON** 格式，但我們不用自己拼 JSON，官方的 `anthropic` 套件（SDK，Software Development Kit）會幫我們包好。

真正在網路上跑的訂單長這樣（你不用手寫，看懂就好）：

```
POST https://api.anthropic.com/v1/messages
x-api-key: sk-ant-你的金鑰
{
  "model": "claude-opus-5-5",
  "max_tokens": 1024,
  "messages": [{"role": "user", "content": "用一句話說明什麼是 API"}]
}
```

金鑰（API key）就是你的身分證加錢包：伺服器靠它知道「這是誰在點餐、該跟誰收錢」。所以金鑰不能給別人，也不能寫進程式碼。

| | 聊天視窗 | API |
|---|---|---|
| 誰在用 | 人 | 程式 |
| 怎麼送 | 打字、按送出 | `client.messages.create(...)` |
| 記憶 | 網站幫你存對話 | 沒有，每次要自己把歷史送過去 |
| 收費 | 月費或免費額度 | 按 token 計費 |
| 能做什麼 | 一問一答 | 排程、批次、接資料庫、接硬體 |

### 第一次呼叫

先確定你已經照前言做好三件事：建好 venv、`pip install anthropic`、把金鑰放進環境變數 `ANTHROPIC_API_KEY`。然後把下面存成 `hello.py` 執行。

```python
import anthropic

# 建立客戶端。金鑰不寫在程式裡，SDK 會自動讀環境變數 ANTHROPIC_API_KEY
client = anthropic.Anthropic()

# 送出一則訊息：指定模型、最多回多少 token、以及對話內容
response = client.messages.create(
    model="claude-opus-5-5",
    max_tokens=1024,
    messages=[{"role": "user", "content": "用一句話說明什麼是 API，對象是國中生。"}],
)

# 回覆的 content 是一串「區塊」，只印出文字區塊
for block in response.content:
    if block.type == "text":
        print(block.text)

# 順便看看這次用了多少 token（之後算費用會用到）
print("輸入 token：", response.usage.input_tokens)
print("輸出 token：", response.usage.output_tokens)
```

預期輸出（模型的字句每次會不同）：

```
API 就像餐廳的點餐窗口，程式不用進廚房，只要照規定把需求遞進去，就能拿到結果。
輸入 token： 31
輸出 token： 52
```

三個參數你每次都會寫：`model` 是用哪個模型（本書一律 `claude-opus-5-5`）；`max_tokens` 是「最多回幾個 token」的上限，不是目標長度；`messages` 是對話內容。

回來的 `response` 是一個物件，最重要的三個欄位：

| 欄位 | 內容 | 怎麼用 |
|---|---|---|
| `content` | 一串區塊（block），每塊有 `type`：`text`、`thinking`、`tool_use`…… | 用 `block.type == "text"` 挑出文字再讀 `.text` |
| `stop_reason` | 為什麼停：`end_turn`（講完了）、`max_tokens`（被上限截斷）、`tool_use`（想用工具，第 2 章） | 看到 `max_tokens` 代表回覆不完整 |
| `usage` | `input_tokens`、`output_tokens` | 算費用 |

**token** 是模型的計數單位，大約 0.7 個中文字或 0.75 個英文單字。31 個輸入 token 差不多就是那句問題加上一點包裝。

### system prompt：先設定角色

`messages` 是一來一往的對話，但有些話你想「整場都有效」：你是誰、用什麼語言、回答多長。這些放在 `system` 參數，叫 **system prompt（系統提示）**。

```python
import anthropic

client = anthropic.Anthropic()

# system 是「角色設定」，整場對話都有效；messages 才是一來一往的內容
response = client.messages.create(
    model="claude-opus-5-5",
    max_tokens=1024,
    system="你是一位國中理化老師，回答一律用繁體中文，每次最多三句話，不用表情符號。",
    messages=[{"role": "user", "content": "為什麼冰塊會浮在水上？"}],
)

for block in response.content:
    if block.type == "text":
        print(block.text)
```

預期輸出：

```
水結成冰時分子排成有空隙的六角形結構，體積變大、密度變小。密度比水小的東西就會浮起來。所以冰山才會露出水面。
```

把 system 改成「你是海盜船長，講話要像海盜」再跑一次，你會發現內容一樣但語氣全變了。這就是 system prompt 的威力：它是你跟模型之間的「工作合約」，第 6 章會專門講怎麼寫好它。

### 多輪對話：記憶要自己帶

API **沒有記憶**。你問「我叫小安」，下一次呼叫問「我叫什麼」，它不知道，因為對它來說每次呼叫都是全新的一天。要讓它「記得」，你必須把之前的對話一起送過去。

`messages` 是一個 list，每個元素是 `{"role": ..., "content": ...}`，`role` 只有兩種：`user`（你）和 `assistant`（模型）。第一則一定是 `user`。

```python
import anthropic

client = anthropic.Anthropic()

# API 本身沒有記憶，所以「對話歷史」要由我們自己存在一個 list 裡
messages = [
    {"role": "user", "content": "我叫小安，我最喜歡的科目是理化。"},
    {"role": "assistant", "content": "小安你好！理化很有趣，你最喜歡哪個單元？"},
    {"role": "user", "content": "你還記得我叫什麼名字、喜歡什麼科目嗎？"},
]

# 每次呼叫都把整個 list 送過去，模型才「記得」前面講過的話
response = client.messages.create(
    model="claude-opus-5-5",
    max_tokens=1024,
    messages=messages,
)

for block in response.content:
    if block.type == "text":
        print(block.text)
```

預期輸出：

```
當然記得！你叫小安，最喜歡的科目是理化。
```

畫成圖，每次呼叫送出去的東西長這樣：

```
第 1 次呼叫：[user]                      → 回 A1
第 2 次呼叫：[user, assistant(A1), user]  → 回 A2
第 3 次呼叫：[user, A1, user, A2, user]   → 回 A3
```

注意兩件事。第一，歷史越長，每次送的 token 越多，費用也越高（第 6 章的快取會解決一部分）。第二，中間那句 `assistant` 是我們自己寫進去的，模型會相信那是它說過的話。這個特性在做測試時很方便。

### 串流：一邊產生一邊顯示

模型寫 500 字要幾秒鐘，全部寫完才顯示會讓使用者乾等。**串流（streaming）**讓伺服器每產生一小段就送一小段，像打字機一樣。寫法是把 `create` 換成 `stream`，並用 `with`：

```python
import anthropic

client = anthropic.Anthropic()

# stream() 會一邊產生一邊送回來，像打字機一樣，不用等全部寫完
with client.messages.stream(
    model="claude-opus-5-5",
    max_tokens=4096,
    messages=[{"role": "user", "content": "寫一段 150 字的短文，介紹台灣的夜市。"}],
) as stream:
    # text_stream 每次吐出一小段文字；end="" 讓它接在同一行，flush 立刻顯示
    for text in stream.text_stream:
        print(text, end="", flush=True)

    # 串流結束後還是可以拿到完整的訊息物件，例如看 token 用量
    final = stream.get_final_message()

print()
print("輸出 token：", final.usage.output_tokens)
```

預期輸出：文字會一個詞一個詞跳出來，最後印出 `輸出 token： 210` 之類的數字。

串流還有一個實際好處：長輸出不會因為等太久而連線逾時。本書的規則是**可能輸出很長的請求一律用 stream**。

串流底下其實是一連串的「事件」：`message_start`（開始）、`content_block_delta`（又多了一小段）、`message_stop`（結束）。`text_stream` 幫你把這些事件過濾成純文字；如果你想自己處理事件（例如把思考和回答分開顯示），可以改寫成 `for event in stream:` 再看 `event.type`。第 2 章用工具時會再碰到。

### max_tokens、effort 與 temperature

`max_tokens` 是上限不是目標。設 100 卻要它寫 300 字，它會寫到一半被砍，`stop_reason` 變成 `max_tokens`。建議值：短問答 1024，摘要 2048，寫文章或程式 4096 以上，而且長的用串流。

很多 AI API 有一個叫 **temperature（溫度）**的參數，0 代表每次都挑最可能的字（穩定但呆板），越高越隨機（有創意但容易胡說）。你會在很多教學和其他模型的文件裡看到它。不過本書用的 `claude-opus-5-5` **不接受 temperature**（送了會回 400 錯誤），因為這一代模型內建「思考」，由它自己調節。你真正能控制的是**想多深**：`output_config={"effort": "low"}`（快、便宜，適合簡單分類）到 `"high"`、`"xhigh"`、`"max"`（難題）。預設是 `medium`。

### thinking：讓模型先想再答

這一代的模型在回答前會先「想」，像你解數學題前先在草稿紙上算。這個功能叫 **thinking（延伸思考）**，設定方式是 `thinking={"type": "adaptive"}`，意思是「讓模型自己判斷要不要想、想多久」。對 `claude-opus-5-5` 來說思考是一直開著的，寫不寫這行效果一樣，但寫出來比較清楚；加上 `"display": "summarized"` 可以把思考摘要拿回來看。

```python
import anthropic

client = anthropic.Anthropic()

# thinking 設成 adaptive：模型自己決定要不要先想、想多久
# display="summarized" 會把思考摘要回傳給你看；不設的話思考照樣發生，只是不顯示
response = client.messages.create(
    model="claude-opus-5-5",
    max_tokens=8192,
    thinking={"type": "adaptive", "display": "summarized"},
    output_config={"effort": "high"},  # 想得多認真：low / medium / high / xhigh / max
    messages=[{"role": "user", "content": "一個水池有進水管 3 小時可以注滿，排水管 5 小時可以排空。兩管同時開，幾小時注滿？"}],
)

# 回覆裡會有 thinking 區塊和 text 區塊，分開印
for block in response.content:
    if block.type == "thinking":
        print("[思考摘要]", block.thinking)
    elif block.type == "text":
        print("[回答]", block.text)
```

預期輸出：

```
[思考摘要] 進水每小時 1/3，排水每小時 1/5，淨流入 1/3 − 1/5 = 2/15，所以 15/2 = 7.5 小時。
[回答] 兩管同時開時，每小時淨注入 2/15 池，所以 7.5 小時注滿。
```

思考的 token 也算在輸出費用裡，所以 `max_tokens` 要留夠（這裡給 8192）。簡單任務用 `effort: "low"` 可以省很多。

什麼時候該開高一點的 effort？一個簡單的判斷：**你自己做這件事需不需要草稿紙**。「把這句話翻成英文」不用，`low` 就好；「這段程式為什麼會當掉」需要，用 `high`；「幫我規劃一個有十個步驟的專案」用 `xhigh`。effort 越高，回答越慢、越貴，但在難題上明顯更準。第 6 章做評估時，你會拿同一組題目在不同 effort 下跑，親眼看到差別。

還有一件事要知道：多輪對話時，模型的 `thinking` 區塊要**原封不動**放回歷史裡（活動 1-1 只存文字是因為它每輪都是新問題，不需要延續推理）。第 2 章工具迴圈的寫法 `messages.append({"role": "assistant", "content": response.content})` 就是把整個 content 連同思考一起放回去。

### 錯誤處理與重試

網路會斷、金鑰會打錯、伺服器會忙。SDK 把這些錯誤分成不同的類別，你可以分開處理。原則是**先接具體的、再接籠統的**：

```python
import anthropic

# max_retries：遇到 429（太頻繁）或 5xx（伺服器忙）時 SDK 會自己重試幾次，預設 2
client = anthropic.Anthropic(max_retries=3, timeout=60.0)

try:
    response = client.messages.create(
        model="claude-opus-5-5",
        max_tokens=512,
        messages=[{"role": "user", "content": "你好"}],
    )
    print(response.content[0].text)

# 先接「最具體」的錯誤，再接「最籠統」的，順序不能反
except anthropic.AuthenticationError:
    print("金鑰錯了或沒設定，檢查 ANTHROPIC_API_KEY。")
except anthropic.RateLimitError:
    print("請求太頻繁，等一下再試。")
except anthropic.BadRequestError as e:
    print("請求內容有問題：", e.message)
except anthropic.APIStatusError as e:
    # 其他有 HTTP 狀態碼的錯誤，例如 500、529（伺服器過載）
    print(f"伺服器回了 {e.status_code}：{e.message}")
except anthropic.APIConnectionError:
    print("連不上網路或伺服器。")
```

常見的錯誤代碼：

| 代碼 | 類別 | 意思 | 怎麼辦 |
|---|---|---|---|
| 401 | `AuthenticationError` | 金鑰錯或沒設 | 檢查環境變數 |
| 400 | `BadRequestError` | 請求格式錯，例如 messages 第一則不是 user、送了不支援的參數 | 看錯誤訊息改程式 |
| 429 | `RateLimitError` | 太頻繁或額度用完 | 等一下；SDK 會自動重試 |
| 500 / 529 | `APIStatusError` | 伺服器錯誤或過載 | SDK 會自動重試，還是不行就稍後再跑 |

SDK 預設會對 429 與 5xx 自動重試兩次並且越等越久，大部分情況你不用自己寫重試迴圈。

### 金鑰管理與費用

金鑰就是你的錢包。本書所有程式都用 `anthropic.Anthropic()` 不帶參數，讓 SDK 自己讀環境變數，這樣程式碼裡永遠不會出現金鑰。如果你用 git，把 `.env` 加進 `.gitignore`；如果你在 Colab，用左邊的「密鑰」面板存金鑰，不要寫在儲存格裡。

費用按 token 算，輸入與輸出價格不同。寫書時 `claude-opus-5-5` 每 100 萬 token 輸入 4 美元、輸出 20 美元（會變，以官方頁面為準）。一次 1000 token 輸入、200 token 輸出的呼叫：

```
輸入：1000 ÷ 1,000,000 × 4  = 0.004 美元
輸出： 200 ÷ 1,000,000 × 20 = 0.004 美元
合計 0.008 美元，約 0.25 元台幣
```

所以單次呼叫很便宜，但「每天跑 1000 次」或「每次都把 50 頁文件送進去」就會有感。本章最後的程式會教你在送出前先數 token。

## 動手做

### 活動 1-1：命令列聊天機器人

**材料／工具**：裝好 `anthropic` 的 venv、設定好的金鑰、終端機。

**步驟**：

1. 在專案資料夾建立 `chat.py`，貼入下面整段程式。
2. 在終端機執行 `python chat.py`。
3. 輸入「我叫小安，我最喜歡理化」，等它回答。
4. 再輸入「我叫什麼名字？」，確認它記得。
5. 輸入 `/reset`，再問一次「我叫什麼名字？」，看它還記不記得。
6. 輸入 `/quit` 離開。
7. 把 `SYSTEM` 改成另一種角色（例如「你是講冷笑話的機器人」）再跑一次。

```python
"""活動 1-1：命令列聊天機器人。輸入 /quit 離開、/reset 清掉記憶。"""
import anthropic

MODEL = "claude-opus-5-5"
SYSTEM = "你是一位有耐心的家教，用繁體中文回答，回答簡短，必要時用條列。"

client = anthropic.Anthropic()


def ask(messages: list) -> str:
    """把整段對話歷史送出去，串流印出回覆，並把回覆文字傳回來。"""
    with client.messages.stream(
        model=MODEL,
        max_tokens=4096,
        system=SYSTEM,
        messages=messages,
    ) as stream:
        # 一邊收一邊印，使用者不用乾等
        for text in stream.text_stream:
            print(text, end="", flush=True)
        final = stream.get_final_message()
    print()

    # 把所有文字區塊接起來，當成這一輪的「assistant 說了什麼」
    reply = "".join(b.text for b in final.content if b.type == "text")
    print(f"   （本輪 token：輸入 {final.usage.input_tokens}，輸出 {final.usage.output_tokens}）")
    return reply


def main():
    messages = []  # 對話歷史：user 與 assistant 輪流
    print("聊天機器人已啟動。/quit 離開，/reset 清除記憶。")
    while True:
        try:
            user = input("你> ").strip()
        except EOFError:
            break
        if not user:
            continue
        if user == "/quit":
            break
        if user == "/reset":
            messages = []
            print("（記憶已清除）")
            continue

        # 先把使用者這句加進歷史，再呼叫模型
        messages.append({"role": "user", "content": user})
        print("AI> ", end="", flush=True)
        try:
            reply = ask(messages)
        except anthropic.APIStatusError as e:
            # 出錯時把剛才那句拿掉，避免歷史裡出現沒有回覆的 user 訊息
            messages.pop()
            print(f"\n（API 錯誤 {e.status_code}：{e.message}）")
            continue

        # 模型的回覆也要加進歷史，下一輪才會「記得」
        messages.append({"role": "assistant", "content": reply})


if __name__ == "__main__":
    main()
```

   （本輪 token：輸入 48，輸出 26）

### 活動 1-2：把文章變三句摘要

**材料／工具**：同上，加一篇文章存成 `article.txt`（新聞、課文、維基百科段落都可以，200–2000 字）。

**步驟**：

1. 建立 `summarize.py`，貼入程式。
2. 準備 `article.txt`。
3. 執行 `python summarize.py article.txt`。
4. 數一數它真的是三句嗎？第一句是不是主題？
5. 換三篇不同的文章，記錄每篇的句數與你給的品質分數（1–5）。
6. 挑戰：把 system prompt 裡的「三句」改成「給小學生看的三句」，比較差異。

```python
"""活動 1-2：把一篇文章變成三句摘要。用法：python summarize.py 文章.txt"""
import sys
import anthropic

MODEL = "claude-opus-5-5"
SYSTEM = (
    "你是摘要助手。讀完使用者給的文章後，用繁體中文寫出「剛好三句」的摘要："
    "第一句講主題，第二句講最重要的細節，第三句講結論或影響。"
    "每句一行，句尾用句號，不要編號、不要標題、不要多餘的話。"
)

client = anthropic.Anthropic()


def summarize(article: str) -> str:
    """送出文章，回傳三句摘要的文字。"""
    response = client.messages.create(
        model=MODEL,
        max_tokens=1024,
        system=SYSTEM,
        messages=[{"role": "user", "content": f"文章如下：\n\n{article}"}],
    )
    # 只取文字區塊，接起來
    return "".join(b.text for b in response.content if b.type == "text").strip()


def main():
    if len(sys.argv) < 2:
        print("用法：python summarize.py 文章.txt")
        sys.exit(1)

    # 讀檔，順便檢查是不是空的
    with open(sys.argv[1], encoding="utf-8") as f:
        article = f.read().strip()
    if not article:
        print("檔案是空的。")
        sys.exit(1)

    print(f"文章長度：{len(article)} 字")
    summary = summarize(article)
    sentences = [s for s in summary.splitlines() if s.strip()]
    print(f"摘要（{len(sentences)} 句）：")
    for i, s in enumerate(sentences, 1):
        print(f"  {i}. {s}")


if __name__ == "__main__":
    main()
```

## 程式與執行：先數 token 再算錢

送出前先知道要花多少錢，是養成「用程式呼叫 AI」好習慣的第一步。`count_tokens` 只算輸入會占幾個 token，**不會生成、不收生成費**。

```python
"""估算一次呼叫的費用：先用 count_tokens 數輸入 token，再用牌價換算。"""
import anthropic

MODEL = "claude-opus-5-5"
# 牌價（美元／每 100 萬 token），寫書時 claude-opus-5-5 為輸入 4、輸出 20；價格會變，請以官方頁面為準
PRICE_IN = 4.00
PRICE_OUT = 20.00

client = anthropic.Anthropic()

system = "你是摘要助手，用三句話摘要。"
article = "台灣的夜市文化從日治時期的廟口小吃發展而來。" * 40  # 模擬一篇約 800 字的文章
messages = [{"role": "user", "content": article}]

# count_tokens 不會真的生成，只算輸入有幾個 token，不收生成費
count = client.messages.count_tokens(model=MODEL, system=system, messages=messages)
input_tokens = count.input_tokens

# 假設回覆大約 150 個 token，算出兩邊費用
expected_output = 150
cost_in = input_tokens / 1_000_000 * PRICE_IN
cost_out = expected_output / 1_000_000 * PRICE_OUT

print(f"輸入 token：{input_tokens}")
print(f"輸入費用：約 {cost_in:.5f} 美元")
print(f"輸出費用（假設 {expected_output} token）：約 {cost_out:.5f} 美元")
print(f"合計：約 {cost_in + cost_out:.5f} 美元，呼叫 1000 次約 {(cost_in + cost_out) * 1000:.2f} 美元")
```

**怎麼跑**：存成 `cost.py`，`python cost.py`。

**預期輸出**：

```
輸入 token：1120
輸入費用：約 0.00448 美元
輸出費用（假設 150 token）：約 0.00300 美元
合計：約 0.00748 美元，呼叫 1000 次約 7.48 美元
```

試試看把 `* 40` 改成 `* 400`（模擬 8000 字），再看費用。你會發現輸入費用跟文章長度成正比，而「呼叫 1000 次」那行會告訴你把這個工具排程每天跑是不是划算。

## 常見錯誤與迷思

- **「我把金鑰寫在程式裡比較方便」** → 一旦程式上傳到 GitHub 或截圖分享，別人就能用你的錢包；自動掃描機器人幾分鐘內就會找到。 → 一律用環境變數，程式碼裡只有 `anthropic.Anthropic()`。
- **「它上一輪明明說過，怎麼這輪不記得」** → API 沒有記憶，每次呼叫都是全新的。 → 把歷史存在 list 裡，每次整個送過去（活動 1-1 的 `messages`）。
- **「回覆講到一半就斷了」** → `stop_reason` 是 `max_tokens`，你給的上限太小；開 thinking 時思考也算在裡面。 → 加大 `max_tokens`，長輸出用串流。
- **「我設了 temperature=0 結果報 400」** → `claude-opus-5-5` 不接受 temperature、top_p、top_k。 → 拿掉這些參數，用 `output_config={"effort": ...}` 控制。
- **「messages 第一則放 assistant 當開場白」** → API 規定第一則必須是 `user`，否則 400。 → 開場白放 system，或放在第一則 user 後面當 assistant。
- **「我想在 assistant 那邊先寫一半讓它接下去（prefill）」** → 這一代模型不支援 prefill，會回 400。 → 要控制格式用 system prompt，或第 2 章的結構化輸出。
- **「token 就是字數」** → 不是。中文大約 1 個字 1.3–1.5 個 token，英文大約 1 個單字 1.3 個 token，而且不同語言差很多。 → 用 `count_tokens` 或看 `usage`，不要用字數估。
- **「API 很貴」** → 單次呼叫通常不到 0.3 元台幣；貴的是「送很長的輸入」和「跑很多次」。 → 先用本章的 `cost.py` 估，必要時在主控台設上限。

## 想一想

1. 用自己的話說：聊天視窗和 API 最大的差別是什麼？為什麼小安的每日摘要一定要用 API？

<details><summary>參考答案</summary>

聊天視窗是給人用的介面，程式沒辦法替你打字按送出；API 是給程式用的入口，可以排程、自動化、接到其他程式。小安要的是「每天自動做」，只有程式能做到，所以必須用 API。

</details>

2. 一次呼叫輸入 3000 token、輸出 500 token，用本章的牌價算費用。跑 200 次要多少？

<details><summary>參考答案</summary>

輸入 3000 ÷ 1,000,000 × 4 = 0.012 美元；輸出 500 ÷ 1,000,000 × 20 = 0.010 美元；合計 0.022 美元。200 次 = 4.4 美元。

</details>

3. 活動 1-1 的聊天機器人聊了 10 輪，第 10 輪的輸入 token 為什麼比第 1 輪多很多？有什麼辦法減少？

<details><summary>參考答案</summary>

因為每次都把全部歷史送過去，第 10 輪的輸入包含前面 9 輪的所有內容。可以只保留最近 N 輪、把舊對話先摘要再放進去，或用第 6 章的提示快取（prompt caching）讓重複的前綴變便宜。

</details>

4. 下面這段 messages 送出去會發生什麼事？為什麼？
   `[{"role": "assistant", "content": "你好！"}, {"role": "user", "content": "嗨"}]`

<details><summary>參考答案</summary>

會收到 400 `BadRequestError`，因為 messages 的第一則必須是 `user`。想要開場白應該放在 system，或把順序改成 user 在前。

</details>

5. 你的程式偶爾會收到 429，但隔一秒再跑就好了。要不要自己寫重試迴圈？

<details><summary>參考答案</summary>

通常不用。SDK 預設對 429 與 5xx 自動重試兩次並且越等越久；可以把 `max_retries` 調大。只有當你需要特殊的重試邏輯（例如超過某個次數就改用別的流程）才自己寫。

</details>

6. 開放挑戰：把活動 1-2 的摘要工具改成「讀一個資料夾裡所有 .txt 檔，各做一份摘要，存成 summaries.txt」，並在跑之前先印出總共會花多少錢、問使用者要不要繼續。

<details><summary>參考答案</summary>

思路：用 `pathlib.Path(folder).glob("*.txt")` 列出檔案；對每個檔案先 `count_tokens` 加總輸入，加上「每篇約 150 輸出 token」估費用；印出後用 `input("繼續？(y/n)")` 確認；確認後逐篇呼叫 `summarize()`，結果用 `with open("summaries.txt", "a")` 追加寫入，每篇前面寫檔名。記得用 try/except 包住每次呼叫，一篇失敗不要讓整批中斷。

</details>

## 本章小結

- API 是程式跟程式講話的約定；`anthropic` SDK 幫你把請求包成 `client.messages.create(...)`。
- 每次呼叫必填 `model`、`max_tokens`、`messages`；回覆讀 `content` 裡的 `text` 區塊、看 `stop_reason`、用 `usage` 算錢。
- `system` 是整場有效的角色設定；`messages` 是 user／assistant 輪流的對話，第一則必須是 user。
- API 沒有記憶，多輪對話要自己把歷史整個送過去。
- 長輸出用 `client.messages.stream()` 一邊收一邊印；`thinking={"type": "adaptive"}` 讓模型先想，`output_config.effort` 控制想多深。
- `claude-opus-5-5` 不接受 temperature，也不支援 prefill。
- 錯誤先接具體的（401、429、400）再接籠統的；SDK 會自動重試 429 與 5xx。
- 金鑰只放環境變數；用 `count_tokens` 在送出前估費用。

## 名詞表

| 中文 | 英文 | 一句話解釋 |
|---|---|---|
| 應用程式介面 | API（Application Programming Interface） | 程式跟程式講話的固定約定，像餐廳的點餐窗口 |
| 軟體開發套件 | SDK（Software Development Kit） | 官方寫好的套件，幫你把 API 請求包成函式呼叫 |
| 權杖 | token | 模型計數與計費的單位，約 0.7 個中文字 |
| 系統提示 | system prompt | 整場對話都有效的角色與規則設定 |
| 訊息 | messages | user 與 assistant 輪流的對話清單，第一則必須是 user |
| 串流 | streaming | 回覆一邊產生一邊送回，不用等全部寫完 |
| 延伸思考 | thinking | 模型回答前先推理；`adaptive` 讓它自己決定想多久 |
| 努力程度 | effort | 控制思考深度與 token 花費的旋鈕：low 到 max |
| 停止原因 | stop_reason | 模型為什麼停：講完（end_turn）、被截斷（max_tokens）、要用工具（tool_use） |
| 用量 | usage | 回覆裡的 token 統計，用來算費用 |
| 速率限制 | rate limit | 短時間內請求太多，伺服器回 429 要你等 |
| 環境變數 | environment variable | 作業系統層級的設定值，用來放金鑰而不寫進程式 |
