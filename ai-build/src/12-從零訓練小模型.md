## 開場：你也能擁有自己的 GPT

《AI 怎麼運作》第 11 章用紙筆和骰子做過 2-gram 童話產生器，又用一張圖講了 Transformer 的結構。讀完的人常常問：「那我能不能真的寫一個？」答案是可以，而且比你想像的小。

## 核心概念

### 從查表到算分數

《AI 怎麼運作》的 n-gram 是一張表：記住「前 n 個字」之後各種下一個字出現幾次，產生時照次數抽。它的問題是只能看固定長度、看過的組合才有資料，沒看過的就卡住。

Transformer 改成「算分數」：每個字先變成一串數字（向量），模型用這些數字算出「下一個字是每個候選字的分數」，再用 softmax 變成機率。好處是它不靠記憶整個組合，而是靠向量之間的運算，所以沒看過的組合也能算出一個合理的分布。這一章就是要把「算分數」的每一步寫出來。

### 字元級 tokenizer：一個字一個編號

大模型的 tokenizer 會把常見的詞切成一個 token，複雜得多。本章用最簡單的做法：把教材裡出現過的每一個不同的字（包括標點和換行）排序，第 0 個字編號 0、第 1 個字編號 1。我們的故事有 77 個不同的字，所以字彙表大小 `vocab_size = 77`。

```
字彙表（部分）：
  編號  0 → "\n"      編號  1 → "一"      編號  2 → "三"
  編號 10 → "咪"      編號 11 → "喔"  ...  編號 76 → "：」"之類的標點
```

每個編號對應一個可訓練的 64 維向量（`n_embd = 64`），這就是「字變數字」。

### 注意力：查詢、鑰匙、價值

一個字要決定「我該看前面哪些字」，做法是：

1. 每個字各算出三個小向量：**查詢（Query）** 「我在找什麼」、**鑰匙（Key）** 「我是什麼」、**價值（Value）** 「我能提供什麼」。
2. 當前字的查詢和前面每個字的鑰匙做內積，得到分數；分數高表示「那個字跟我有關」。
3. 分數除以 √維度 避免數字爆掉，過 softmax 變成加總為 1 的權重。
4. 用權重把各字的價值加權平均，得到「吸收了上下文的新向量」。

有一件事一定要做：**遮罩（Mask）**。訓練時整段文字一起餵進去，第 i 個字只能看第 0 到 i 個字，不能偷看後面的，否則它會直接抄答案。程式用一個下三角矩陣，把「未來」位置的分數設成負無限大，softmax 之後權重就是 0。

```
遮罩（block_size = 4 時）     1 = 可以看，0 = 不能看
         看第0字 看第1字 看第2字 看第3字
 第0字      1       0       0       0
 第1字      1       1       0       0
 第2字      1       1       1       0
 第3字      1       1       1       1
```

多頭注意力只是把 64 維切成 4 份、每份 16 維各自做一次上面的事，再接回來。四顆頭可以各看各的：一顆看前一個字、一顆看引號、一顆看句號之後的開頭。

### 一層 Transformer 長什麼樣

```
      輸入 x（每個字 64 維）
         │
         ├──────────────┐
         ▼              │
     LayerNorm          │
         ▼              │
     多頭注意力          │  殘差連接：把原本的 x 加回來
         ▼              │
        (+) ◄───────────┘
         │
         ├──────────────┐
         ▼              │
     LayerNorm          │
         ▼              │
   前饋網路 64→256→64    │
         ▼              │
        (+) ◄───────────┘
         │
      輸出（還是 64 維）
```

一層做兩件事：注意力「看別人」，前饋網路「自己消化」。**殘差連接**（把輸入加回輸出）讓每一層只需要學「要改多少」，不用重學全部，疊很多層也訓練得動。**LayerNorm** 把數字拉回合理範圍。本章疊 2 層；GPT-2 小型版疊 12 層，大模型疊幾十到上百層。

最後再接一個線性層把 64 維變成 77 個分數（每個字一個），這就是「下一個字的分數」。

### 損失：模型猜得有多差

訓練用的是交叉熵（Cross Entropy）：正確答案那個字的機率是 p，損失就是 −log(p)。你不需要會對數，只要記住三個數字：

| 情況 | 正確字的機率 | 損失 |
|---|---|---|
| 完全亂猜（77 個字平均分） | 1/77 ≈ 0.013 | 4.34 |
| 猜得還可以 | 0.5 | 0.69 |
| 幾乎確定 | 0.95 | 0.05 |

所以你看到訓練一開始 loss 是 4.47，就知道「跟亂猜差不多」；掉到 0.05，就知道「幾乎每個字都猜對」。損失是訓練時唯一的儀表板，看懂它就看懂訓練。

### 參數量、資料量、算力

三個數字決定一個語言模型的尺寸：

- **參數量**：模型裡可調的數字有幾個。本章 111,693 個；GPT-2 小型版 1.24 億；現在的大模型幾千億到上兆。
- **資料量**：訓練時看過幾個 token。本章 600 步 × 16 段 × 32 字 = 307,200 個字（而且是同一段故事反覆看）；大模型是十幾兆個 token。
- **算力**：一個常用的估算是「每個 token 大約要做 6 × 參數量 次乘加運算」。

用這個公式算一下：

| | 參數量 | 訓練 token 數 | 算力（次運算） |
|---|---|---|---|
| 本章 mini GPT | 1.1 × 10⁵ | 3.1 × 10⁵ | 6 × 1.1×10⁵ × 3.1×10⁵ ≈ 2 × 10¹¹ |
| 70 億參數的開源模型 | 7 × 10⁹ | 2 × 10¹² | 6 × 7×10⁹ × 2×10¹² ≈ 8 × 10²² |

後者是前者的 4 × 10¹¹ 倍。你的筆電跑本章要 5 秒，照比例要跑 6 萬年；所以大模型得用幾千張 GPU 跑幾個月，電費以百萬美元計。這就是為什麼第 11 章要用 LoRA 只訓練一小塊、第 9 章要用別人預訓練好的模型：從零訓練大模型不是個人做得到的事，但從零訓練「小」模型可以，而且學到的原理完全一樣。

### 背起來，還是學會了？

本章的教材只有一段故事重複 20 次。模型訓練到 loss 0.05，產生的文字幾乎逐字照抄原文——它**背起來**了。這不是壞事，因為我們就是要看它能不能學會這段文字；但你要知道，這個模型對沒看過的句子毫無能力，問它「小狗」它只會硬接「貓咪」。

大模型之所以「會講話」，是因為教材多到背不下來（幾兆個 token、幾千億參數都背不完），只好學規律。這也是《AI 怎麼運作》講的過擬合：資料少、模型相對大，就會背；資料多到背不完，才會學。活動 12-2 會請你親手把重複次數降低，看看它從「會背」變成「背不起來也學不會」的樣子。

## 動手做

### 活動 12-1：手算一次注意力

**材料／工具**：紙、筆、計算機。

**步驟**：

1. 假設三個字「小」「貓」「咪」，各有 2 維的查詢、鑰匙、價值向量（數字隨便給，這裡用下面的）：

| 字 | 查詢 q | 鑰匙 k | 價值 v |
|---|---|---|---|
| 小 | (1, 0) | (1, 0) | (2, 0) |
| 貓 | (0, 1) | (0, 1) | (0, 2) |
| 咪 | (1, 1) | (1, 1) | (1, 1) |

2. 算「咪」對三個字的分數：q咪 · k小 = 1×1 + 1×0 = 1；q咪 · k貓 = 1；q咪 · k咪 = 2。
3. 除以 √2 ≈ 1.41：得到 0.71、0.71、1.41。
4. 做 softmax：先取 e 的次方（用計算機的 eˣ）：2.03、2.03、4.11；加總 8.17；各除以總和得權重 0.25、0.25、0.50。
5. 加權平均價值：0.25×(2,0) + 0.25×(0,2) + 0.50×(1,1) = (0.5+0+0.5, 0+0.5+0.5) = (1.0, 1.0)。

**你應該看到／得到**：「咪」的新向量是 (1.0, 1.0)，一半來自自己、各四分之一來自「小」和「貓」。改一下 q咪 變成 (2, 0)，權重會往「小」偏。

**觀察與記錄**：

| 改什麼 | 三個權重 | 新向量 | 誰的影響最大 |
|---|---|---|---|
| 原始 | 0.25 / 0.25 / 0.50 | (1.0, 1.0) | 咪 |
| q咪 = (2, 0) | | | |
| q咪 = (0, 3) | | | |

### 活動 12-2：用自己的文字訓練，調層數與步數

**材料／工具**：本章的 `mini_gpt.py`、一段你自己寫或抄的文字（300 字以上，童話、日記、歌詞都可以）。

**步驟**：

1. 把 `story` 的內容換成你的文字。中文、英文、注音都行，程式會自動建字彙表。
2. 先照預設跑一次（`n_layer = 2`、`steps = 600`、`text = story * 20`），記下最後的 loss 和產生的文字。
3. 把 `story * 20` 改成 `story * 3`，重跑。資料變少，看 loss 還掉不掉得下去、產生的文字還像不像話。
4. 改回 `* 20`，把 `n_layer` 改成 1，再改成 4，各跑一次。注意參數量和時間的變化。
5. 把 `steps` 改成 100 和 2000 各跑一次。
6. 每次都用溫度 0.5 和 1.0 各產生一次。

### mini_gpt.py

```python
# mini_gpt.py：從零寫一個字元級的迷你 Transformer（nanoGPT 風格），本機 CPU 幾分鐘可跑
import math, time, torch
import torch.nn as nn
import torch.nn.functional as F

torch.manual_seed(42)                     # 固定亂數，讓你跑出來的數字和書上接近

# ===== 1. 訓練文字：一段自己寫的小故事，重複幾遍讓模型有東西可學 =====
story = """小貓咪住在山腳下的小木屋。每天早上，小貓咪都會去河邊釣魚。
河邊有一隻老烏龜，老烏龜說：「小貓咪，今天的魚很多喔。」
小貓咪笑著說：「謝謝老烏龜，我釣到魚分你一條。」
中午的時候，小貓咪釣到了三條魚，一條給老烏龜，一條給媽媽，一條自己吃。
晚上，小貓咪躺在屋頂上看星星，星星一閃一閃的，好像在對小貓咪眨眼睛。
小貓咪想：明天還要再去河邊釣魚，還要再跟老烏龜聊天。
"""
text = story * 20                         # 重複 20 次，總長約 4000 字

# ===== 2. 字元級 tokenizer：每個不同的字給一個編號 =====
chars = sorted(set(text))
vocab_size = len(chars)
stoi = {ch: i for i, ch in enumerate(chars)}   # 字 → 編號
itos = {i: ch for ch, i in stoi.items()}        # 編號 → 字
data = torch.tensor([stoi[c] for c in text], dtype=torch.long)
print(f"總字數 {len(text)}，不同的字 {vocab_size} 個")

# ===== 3. 超參數：故意很小，CPU 才跑得動 =====
block_size = 32     # 一次看前 32 個字
n_embd = 64         # 每個字用 64 個數字表示
n_head = 4          # 4 顆注意力頭
n_layer = 2         # 2 層
batch_size = 16
steps = 600
lr = 3e-3

def get_batch():
    # 隨機切 batch_size 段，每段 block_size 個字；y 是 x 往右平移一格（下一個字）
    ix = torch.randint(len(data) - block_size - 1, (batch_size,))
    x = torch.stack([data[i:i + block_size] for i in ix])
    y = torch.stack([data[i + 1:i + block_size + 1] for i in ix])
    return x, y

# ===== 4. 模型零件 =====
class Head(nn.Module):
    """一顆注意力頭：每個字算出 查詢(q)、鑰匙(k)、價值(v)，用 q·k 決定要看誰"""
    def __init__(self, head_size):
        super().__init__()
        self.key = nn.Linear(n_embd, head_size, bias=False)
        self.query = nn.Linear(n_embd, head_size, bias=False)
        self.value = nn.Linear(n_embd, head_size, bias=False)
        # 下三角遮罩：第 i 個字只能看第 0..i 個字，不能偷看未來
        self.register_buffer("tril", torch.tril(torch.ones(block_size, block_size)))

    def forward(self, x):
        B, T, C = x.shape
        k, q, v = self.key(x), self.query(x), self.value(x)
        # 分數 = q·k，除以 sqrt(維度) 避免數字太大
        w = q @ k.transpose(-2, -1) / math.sqrt(k.shape[-1])
        w = w.masked_fill(self.tril[:T, :T] == 0, float("-inf"))  # 未來的位置設成 -inf
        w = F.softmax(w, dim=-1)                                   # 變成加總為 1 的權重
        return w @ v                                               # 加權平均各字的 v

class MultiHead(nn.Module):
    """多顆頭並排，各看各的，再接起來"""
    def __init__(self):
        super().__init__()
        self.heads = nn.ModuleList([Head(n_embd // n_head) for _ in range(n_head)])
        self.proj = nn.Linear(n_embd, n_embd)
    def forward(self, x):
        return self.proj(torch.cat([h(x) for h in self.heads], dim=-1))

class Block(nn.Module):
    """一層 Transformer = 注意力 + 小型前饋網路，各自配殘差連接與 LayerNorm"""
    def __init__(self):
        super().__init__()
        self.ln1, self.ln2 = nn.LayerNorm(n_embd), nn.LayerNorm(n_embd)
        self.attn = MultiHead()
        self.ff = nn.Sequential(nn.Linear(n_embd, 4 * n_embd), nn.ReLU(), nn.Linear(4 * n_embd, n_embd))
    def forward(self, x):
        x = x + self.attn(self.ln1(x))    # 殘差：把原本的 x 加回來，訓練才穩
        x = x + self.ff(self.ln2(x))
        return x

class MiniGPT(nn.Module):
    def __init__(self):
        super().__init__()
        self.tok_emb = nn.Embedding(vocab_size, n_embd)     # 字 → 向量
        self.pos_emb = nn.Embedding(block_size, n_embd)     # 位置 → 向量
        self.blocks = nn.Sequential(*[Block() for _ in range(n_layer)])
        self.ln = nn.LayerNorm(n_embd)
        self.head = nn.Linear(n_embd, vocab_size)           # 向量 → 每個字的分數

    def forward(self, idx, targets=None):
        B, T = idx.shape
        x = self.tok_emb(idx) + self.pos_emb(torch.arange(T))  # 字向量 + 位置向量
        logits = self.head(self.ln(self.blocks(x)))
        loss = None
        if targets is not None:
            # 交叉熵：答對的那個字機率越高，loss 越低
            loss = F.cross_entropy(logits.view(B * T, vocab_size), targets.view(B * T))
        return logits, loss

    @torch.no_grad()
    def generate(self, idx, n_new, temperature=1.0):
        for _ in range(n_new):
            logits, _ = self(idx[:, -block_size:])          # 只看最後 block_size 個字
            probs = F.softmax(logits[:, -1, :] / temperature, dim=-1)
            nxt = torch.multinomial(probs, 1)               # 依機率抽一個字
            idx = torch.cat([idx, nxt], dim=1)
        return idx

# ===== 5. 訓練 =====
model = MiniGPT()
n_params = sum(p.numel() for p in model.parameters())
print(f"參數量：{n_params:,}")
opt = torch.optim.AdamW(model.parameters(), lr=lr)

t0 = time.time()
for step in range(steps + 1):
    xb, yb = get_batch()
    _, loss = model(xb, yb)
    opt.zero_grad(); loss.backward(); opt.step()   # 標準三步：清梯度、算梯度、更新
    if step % 100 == 0:
        print(f"step {step:4d}  loss {loss.item():.3f}  ({time.time() - t0:.0f} 秒)")

# ===== 6. 產生文字：從「小貓咪」開始接龍 =====
start = torch.tensor([[stoi[c] for c in "小貓咪"]])
for temp in (0.5, 1.0):
    out = model.generate(start, 80, temperature=temp)[0].tolist()
    print(f"\n[溫度 {temp}] " + "".join(itos[i] for i in out))
```

### 讀這份輸出

- **step 0 的 loss 4.469**：77 個字亂猜的理論值是 4.34，模型一開始就是在亂猜（還略差一點，因為初始權重是隨機的）。
- **100 步就掉到 0.14**：資料是同一段重複 20 次，模型很快就「認出」這段文字。
- **後面在 0.04–0.08 之間抖動**：已經背完了，剩下的是隨機抽 batch 造成的小起伏。再訓練也不會更低多少。
- **兩種溫度產生的文字一模一樣**：因為模型對每個下一字都「非常確定」（機率接近 1），溫度 1.0 也抽不到別的字。這正是「背起來」的證據。活動 12-2 把資料改成 × 3 之後，兩種溫度的差異就會出現。
- 注意產生的文字從「小貓咪想：」開始而不是「小貓咪住在」：因為「小貓咪」在故事裡出現很多次，模型選了其中一個它最有把握的接法，接下去就照原文走。

## 常見錯誤與迷思

- **loss 掉到 0 附近就是訓練成功 → 不一定 → 在重複的小資料上 loss 很低只代表背熟了，拿沒看過的文字算 loss 會很高。真正的訓練會留一份驗證資料算 loss，第 11 章的微調也一樣。**
- **產生的文字跟原文一樣，程式一定有 bug → 不是 → 資料太小、模型相對太大就會這樣。把 `story * 20` 改成 `* 3` 或換更長的教材就會看到差別。**
- **層數越多越好 → 不對 → 在 4000 字的教材上 4 層和 2 層看不出差別，只會更慢。層數要配資料量。**
- **溫度調高會讓模型「更聰明」 → 不會 → 溫度只改變抽字的隨機程度，不改變模型會的東西。背熟的模型溫度 1.0 也只會照抄。**
- **忘了遮罩，loss 很快變 0 → 這是作弊 → 模型看到了答案。產生文字時（沒有答案可看）會一團亂。遮罩那一行 `masked_fill` 絕對不能拿掉。**
- **`RuntimeError: index out of range` → 通常是 `block_size` 改大了但 `pos_emb` 沒跟著改，或產生時餵進去的序列超過 `block_size`。程式裡 `generate` 用 `idx[:, -block_size:]` 就是在防這個。**

## 想一想

1. 教材有 77 個不同的字，為什麼一開始的 loss 大約是 4.3？如果教材改成只有 26 個英文字母加空格（27 種），一開始的 loss 大約會是多少？

<details><summary>參考答案</summary>

亂猜時每個字機率 1/77，loss = −log(1/77) = log(77) ≈ 4.34。27 種時 log(27) ≈ 3.30。字彙表越小，起點越低，但這不代表比較好學，只是「亂猜也比較容易猜中」。

</details>

2. 把 `block_size` 從 32 改成 8，模型會變得怎樣？哪一類句子最先出錯？

<details><summary>參考答案</summary>

模型一次只能看前 8 個字，超過 8 個字之前的資訊完全不知道。像「老烏龜說：「小貓咪，今天的魚很多喔。」」這種引號要對應、主詞在十幾個字前的句子最先出錯，可能引號不閉合或主詞接錯。短句子（「晚上，小貓咪」）影響小。

</details>

3. 程式用 `data` 的全部當訓練資料。如果你要知道模型「有沒有背起來」，該怎麼改？

<details><summary>參考答案</summary>

把 `data` 切成兩份，例如前 90% 訓練、後 10% 當驗證，每 100 步用驗證資料算一次 loss（不做 `backward`）。如果訓練 loss 一直掉但驗證 loss 不掉或反而上升，就是背起來了。注意本章教材是重複 20 次的同一段，後 10% 和前 90% 內容一樣，要先去掉重複才算得準。

</details>

4. 本章模型 111,693 個參數，哪一部分最多？如果把 `n_embd` 從 64 改成 128，參數大概變幾倍？

<details><summary>參考答案</summary>

每一層的前饋網路最多：64→256 加 256→64，約 33,000 個，兩層共 66,000，占六成。`n_embd` 加倍時，所有「n_embd × n_embd」形狀的矩陣（注意力的 q、k、v、proj，前饋的兩層）都變 4 倍，嵌入與輸出層變 2 倍，整體大約 3.5 到 4 倍，約 40 萬。

</details>

5. 用本章的「6 × 參數量 × token 數」估算：如果你想在 Colab 免費 GPU（假設每秒能做 10¹³ 次運算）上訓練一個 1,000 萬參數的模型看 1 億個 token，要多久？合理嗎？

<details><summary>參考答案</summary>

6 × 10⁷ × 10⁸ = 6 × 10¹⁵ 次，除以 10¹³ 每秒 = 600 秒 = 10 分鐘。合理，Colab 免費 GPU 做得到。這也是為什麼「幾千萬參數、幾億 token」是個人能從零訓練的上限附近，再上去就得花錢租 GPU。

</details>

6. 開放挑戰：把 tokenizer 從「一個字一個編號」改成「一個詞一個編號」（用空格或 jieba 之類的工具切詞）。字彙表會變大還是變小？`block_size = 32` 能看到的「內容」變多還是變少？對產生文字的品質你預期會有什麼影響？

<details><summary>參考答案</summary>

字彙表會變大很多（詞的種類遠多於字），輸出層的參數跟著變大，每個詞看到的次數變少、更難學。但同樣 32 個 token 能看到的內容變多（32 個詞比 32 個字長得多），長距離的呼應比較容易學。品質上：資料少時字元級通常比較穩（每個字都看過很多次）；資料多時詞級或現在大模型用的「子詞」比較好。這就是大模型用子詞 tokenizer 的原因：介於兩者之間。

</details>

## 本章小結

- 一個能跑的字元級 Transformer 不到 150 行：字變向量、位置向量、注意力（q、k、v、遮罩、softmax、加權平均）、前饋網路、殘差與 LayerNorm、輸出分數。
- 交叉熵損失 = −log(正確字的機率)。77 個字亂猜約 4.34，幾乎確定約 0.05。訓練就是看著這個數字往下掉。
- 遮罩讓每個字只能看前面的字，拿掉就是作弊。
- 本章模型 11 萬參數、31 萬 token、約 2 × 10¹¹ 次運算，CPU 5 秒。70 億參數模型是它的 4 × 10¹¹ 倍，所以要幾千張 GPU。
- 小資料上 loss 很低代表背起來了，兩種溫度產生一樣的文字是證據；資料多到背不完，模型才會學規律。
- 層數、寬度、步數要配資料量；在 4000 字的教材上加層數只會變慢。
- 同樣的骨架放大幾萬倍就是大模型，所以第 9 章用別人預訓練的、第 11 章用 LoRA 只動一小塊。

| 多頭注意力 | Multi-head Attention | 把向量切成幾份各做一次注意力，再接回來。 |
