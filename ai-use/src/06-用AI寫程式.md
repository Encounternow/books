# 第 6 章　用AI寫程式

## 本章目標
- 學完你會說出 AI 程式助手能做什麼、不能做什麼，以及為什麼「看懂再用」是最重要的規矩。
- 學完你會用「描述→執行→修改」三步驟，和 AI 一起從零做出一個會動的程式。
- 學完你會把錯誤訊息整段貼給 AI，請它解釋並一起找出問題。
- 學完你會做出一個完整可玩的 Python 猜數字遊戲，並且能說出每一行在做什麼。
- 學完你會說出哪些東西絕對不能貼進 AI（密碼、金鑰、別人的程式與個資）。

## 開場：一個不會寫程式的人寫出了遊戲

小安從來沒寫過程式。某個週末他在表哥小明的電腦上看到一個黑色視窗，裡面跑著一個「猜數字」小遊戲：電腦想一個 1 到 100 的數字，你猜，它說太大或太小。小安玩了幾局，問：「這要學多久才寫得出來？」

小明打開聊天型 AI，打了一句話：「用 Python 寫一個猜數字遊戲，電腦隨機想一個 1 到 100 的整數，玩家一直猜到對為止，每次提示太大或太小。」十秒後，一段十幾行的程式出現了。小明複製、存檔、執行，遊戲就跑起來了。

小安眼睛一亮：「所以不用學程式了？」小明搖頭：「你現在要它加一個『最多猜 7 次』的功能，它會改；但如果它改錯了，你看不出來；如果它改出一個你不想要的行為，你也不知道怎麼跟它講。**AI 可以替你打字，不能替你看懂。**」

這一章我們就用這個猜數字遊戲，走一遍「和 AI 一起寫程式」的完整過程，包括它寫對的時候，和它寫錯的時候。

## 核心概念

### AI 程式助手能做什麼

**AI 程式助手（AI Coding Assistant）**就是聊天型 AI 用在寫程式上。它讀過網路上大量的程式碼和說明文件，所以它很擅長：

| 它很會 | 例子 |
|---|---|
| 從文字描述寫出程式 | 「寫一個計算 BMI 的程式」 |
| 解釋一段程式在做什麼 | 「這段程式的第 5 行是什麼意思？」 |
| 解釋錯誤訊息 | 「這個 ValueError 是什麼？」 |
| 幫現有程式加功能或改寫 | 「加一個計次功能」 |
| 翻譯程式語言 | 「把這段 Python 改成 JavaScript」 |
| 加註解、整理格式 | 「每一行加上中文註解」 |

但它也有明確的弱點：它**沒有真的執行過**它寫的程式（除非工具特別支援），所以它可能寫出跑不動的程式，而且講得一臉自信；它不知道你的電腦裝了什麼、你的檔案放在哪；它有時會用到已經過時或根本不存在的函式。這些都是第 3 章說的幻覺，只是換成程式的形式。所以：**程式一定要自己跑過才算數。**

### 三步驟：描述→執行→修改

和 AI 一起寫程式，就是不斷重複這三步：

```
  ① 描述你要什麼  ──►  ② 複製、存檔、執行  ──►  ③ 回報結果、要求修改
        ▲                                               │
        └───────────────────────────────────────────────┘
```

**① 描述**要具體。「寫一個遊戲」太模糊；「用 Python 寫猜數字：電腦隨機想一個 1 到 100 的整數，玩家輸入猜測，程式回應太大、太小或答對，答對就結束」才夠清楚。第 2 章的四要素（角色、任務、背景、格式）在這裡一樣適用，「背景」要包括你用什麼語言、什麼程度（「我是初學者，請用最簡單的寫法，不要用進階語法」）。

**② 執行**是 AI 做不到、你一定要做的事。程式跑起來了嗎？行為和你要的一樣嗎？

**③ 修改**要把你看到的事實貼回去：「我輸入 50 它說太大，輸入 25 它也說太大，輸入 1 還是太大，好像永遠都說太大」。描述現象比說「它壞了」有用一百倍。

一次只加一個功能。加一個、跑一次、確認沒問題，再加下一個。一口氣要求五個功能，出錯時你會不知道是哪一個害的。

### 看懂它寫的程式再用

這是本章最重要的規矩。拿到 AI 的程式之後，先不要急著跑，請它：

```
請在這段程式每一行後面加上中文註解，說明這一行在做什麼。
然後用三句話告訴我整個程式的流程。
```

讀完註解，試著**蓋住註解，自己講一遍每一行在做什麼**。講不出來的那幾行，就追問：「第 7 行的 `int()` 是什麼意思？如果拿掉會怎樣？」直到你能解釋為止。這和第 4 章的費曼法是同一件事。

為什麼要這麼麻煩？因為程式和作文不一樣，作文寫錯了頂多扣分，程式寫錯了可能刪掉你的檔案、傳出你的資料，或在別人電腦上做你不知道的事。**不懂的程式不要執行**，就像不認識的藥不要吃。

### 錯誤訊息是線索，不是懲罰

程式跑不動時，電腦會印出一大段紅字，叫**錯誤訊息（Error Message）**。新手看到會害怕，但它其實是在告訴你「哪一行、什麼問題」。例如猜數字遊戲裡，如果玩家輸入了「abc」而不是數字，會看到：

```
Traceback (most recent call last):
  File "guess.py", line 7, in <module>
    guess = int(input("你猜："))
ValueError: invalid literal for int() with base 10: 'abc'
```

讀法：最後一行是錯誤類型與說明（`ValueError`：「abc」不是合法的整數），上面的 `line 7` 是出錯的行數。看不懂沒關係，**整段複製貼給 AI**，加一句「這是什麼意思？怎麼修？」它會解釋得很清楚。貼的時候要連程式一起貼，它才知道第 7 行是什麼。

### 不要貼的東西

和 AI 一起寫程式的時候，有幾樣東西絕對不能貼進去：

- **密碼、金鑰（API Key）、帳號**：程式裡如果有一行 `password = "xxxx"`，貼之前先把它換成 `password = "我的密碼"`。貼進 AI 的東西你就收不回來了。
- **別人的程式**：同學寫的、網路上有版權聲明的、公司的，未經同意都不要貼。這和不能把別人的作文貼上去請 AI 改是一樣的道理。
- **含個資的資料檔**：班級名單、家人電話、成績檔。第 8 章和第 9 章會再講。

另外，AI 給你的程式如果包含「下載並安裝某個東西」「刪除某個資料夾」「連到某個網址」，在你搞懂之前不要跑，拿給大人看。

### 小專題：一步一步做出 Python 猜數字

**準備工具。** 你需要一個能執行 Python 的環境。有三種選擇：（a）電腦上安裝 Python（到 python.org 下載，安裝時勾選「加入 PATH」）；（b）用瀏覽器上的線上 Python 執行環境（搜尋「online python」就有很多，不用安裝）；（c）請家長幫忙。本書的程式在 Python 3 上測試過。

**第一步：描述。** 貼上這個提示詞：

```
我是程式初學者，請用 Python 3 寫一個猜數字遊戲，要求：
1. 電腦隨機想一個 1 到 100 的整數。
2. 玩家輸入猜測，程式回應「太大了」「太小了」或「答對了」。
3. 答對就結束。
請用最簡單的寫法，不要用函式和進階語法，程式不超過 15 行，並且每行加中文註解。
```

你應該得到一段長這樣的程式（註解可能不同）：

```python
import random                                   # 載入隨機數工具

answer = random.randint(1, 100)                 # 電腦想一個 1 到 100 的整數
print("我想了一個 1 到 100 的數字，猜猜看！")

while True:                                     # 一直重複，直到 break
    guess = int(input("你猜："))                 # 讀玩家輸入，轉成整數
    if guess < answer:
        print("太小了")
    elif guess > answer:
        print("太大了")
    else:
        print("答對了！")
        break                                   # 跳出迴圈，遊戲結束
```

**第二步：執行。** 把程式存成 `guess.py`，在終端機輸入 `python3 guess.py`（Windows 多半是 `python guess.py`），或在線上環境按執行。玩一局，確認太大、太小、答對三種回應都出現過。

**第三步：看懂。** 蓋住註解，自己講一遍。特別問自己：`while True` 是什麼意思？`break` 拿掉會怎樣？`int()` 為什麼需要？不確定就問 AI。

**第四步：加功能。** 一次加一個：

```
請修改上面的程式：
1. 玩家最多猜 7 次，用完就印出「機會用完了，答案是 X」。
2. 每次猜完顯示「剩下幾次」。
3. 如果玩家輸入的不是整數，或不在 1 到 100 之間，提示重新輸入，而且不算一次。
一樣不用函式，每行加中文註解。
```

你應該得到類似這樣的程式：

```python
import random

answer = random.randint(1, 100)
count = 0                                       # 已經猜了幾次
print("我想了一個 1 到 100 的數字，你有 7 次機會。")

while count < 7:                                # 還有機會就繼續
    text = input("你猜：")
    if not text.isdigit():                      # 不是純數字
        print("請輸入 1 到 100 的整數")
        continue                                # 回到迴圈開頭，不算一次
    guess = int(text)
    if guess < 1 or guess > 100:                # 超出範圍
        print("超出範圍了，請猜 1 到 100")
        continue
    count = count + 1                           # 算一次
    if guess < answer:
        print("太小了，剩下", 7 - count, "次")
    elif guess > answer:
        print("太大了，剩下", 7 - count, "次")
    else:
        print("答對了！你用了", count, "次")
        break
else:                                           # while 正常結束（沒 break）才執行
    print("機會用完了，答案是", answer)
```

執行後，故意測試三種狀況：輸入「abc」、輸入「500」、連續猜錯 7 次。這叫**測試（Testing）**：你不是在玩，你是在找它的漏洞。

**第五步：換你主導。** 現在你自己想一個功能（例如「答對後問要不要再玩一局」、「改成 1 到 1000」、「記錄最佳成績」），自己描述給 AI，自己跑，自己看懂。這一步做完，你就真的「和 AI 一起寫了一個程式」。

**延伸：讓燈閃起來。** 猜數字是在螢幕裡動；如果你想讓真的東西動，Arduino 的「閃燈（Blink）」是所有電子專題的第一步，流程完全一樣：描述→上傳→修改。同書架的《動手玩電》第 12 章有從接線到程式的完整教學（https://book.vichuang.tw/electric/ ），你可以用本章的方法請 AI 幫你改閃燈的節奏，再親眼看燈的變化對不對。

## 動手做

### 活動 6-1：請 AI 寫一個猜數字遊戲並加功能

**材料／工具**：聊天型 AI、可執行 Python 3 的環境（電腦安裝或線上環境）、紙筆。

**步驟**：

1. 照「小專題」第一步的提示詞請 AI 寫出基本版，存檔、執行，玩一局。
2. 請 AI 逐行加註解，蓋住註解自己講一遍，講不出來的行追問到懂。
3. 照第四步的提示詞加入「7 次機會」與「輸入檢查」功能，執行，測試三種狀況（非數字、超出範圍、7 次猜錯）。
4. 自己再設計一個新功能，寫出你的描述（寫在記錄表裡），請 AI 修改，執行。
5. 關掉 AI，在紙上寫出這個程式的流程（可以用「先……然後……如果……」）。

**你應該看到／得到**：步驟 1 的程式應該十幾行、有 `import random`、`randint`、`while`、`if/elif/else`、`break`。執行後三種提示都會出現。步驟 3 輸入「abc」時程式**不會當掉**，而是提示重新輸入；猜錯 7 次後會印出答案。如果 AI 寫出的程式跑不動或行為不對，把你看到的現象貼回去請它修，這是正常流程不是失敗。步驟 5 你寫的流程應該能對上程式的每一段。

**觀察與記錄**：

| 項目 | 記錄 |
|---|---|
| 基本版程式共幾行、執行成功嗎 | |
| 蓋住註解後講不出來的行數與內容 | |
| 測試「abc」的結果 | |
| 測試「500」的結果 | |
| 猜錯 7 次的結果 | |
| 我自己設計的功能描述（原文） | |
| AI 第一次就寫對嗎？改了幾輪 | |

### 活動 6-2：故意放一個錯讓 AI 找

**材料／工具**：活動 6-1 完成的程式、聊天型 AI。

**步驟**：

1. 把 7 次機會版本的程式複製一份，存成 `guess_bug.py`。
2. 故意製造一個「邏輯錯誤」：把 `print("答對了！你用了", count, "次")` 下面那一行 `break` 刪掉。存檔。
3. 執行，猜到正確答案，觀察發生什麼事。
4. **先不要說你改了什麼**，把程式和現象貼給 AI：

```
這是我的猜數字程式，答對之後它印了「答對了」卻還繼續問我猜，要猜滿 7 次才停。
請找出問題在哪一行、為什麼會這樣，並告訴我怎麼修。先不要直接給我整段修好的程式。
〔貼上程式〕
```

5. 看它找得對不對。對了就自己改回去；錯了就追問「不是那裡，請再看一次答對的那段」。
6. 再做第二種錯：製造一個「語法錯誤」，例如把某一行的 `else:` 後面的冒號刪掉。執行，複製整段錯誤訊息貼給 AI，請它解釋。
7. 第三種錯（挑戰）：把 `if guess < answer` 改成 `if guess > answer`，兩邊都改成大於，執行看會發生什麼，再請 AI 找。

**你應該看到／得到**：步驟 3 你會看到「答對了！」之後程式還繼續問「你猜：」，這就是少了 `break` 的症狀。步驟 5 AI 應該指出「答對的分支少了 `break`，所以迴圈沒有結束」。步驟 6 的錯誤訊息會寫 `SyntaxError`，並標出行數，AI 會說「缺少冒號」。步驟 7 比較難：程式不會當掉，但提示會一直說「太大了」，不管你猜什麼，AI 應該能發現兩個條件都寫成大於。你會親身體會：**語法錯誤電腦會幫你抓，邏輯錯誤只有看懂程式的人抓得到。**

**觀察與記錄**：

| 錯誤種類 | 我做了什麼改動 | 執行時看到的現象 | AI 找到了嗎（第幾次） | AI 的解釋是否正確 |
|---|---|---|---|---|
| 邏輯錯：少 break | | | | |
| 語法錯：少冒號 | | | | |
| 邏輯錯：條件寫反 | | | | |

## 用工具看看：用 print 看程式裡面發生什麼事

AI 找錯很方便，但有一個最老、最可靠、不需要 AI 的工具：在程式裡加 `print()`，把變數印出來看。

1. 打開 7 次機會版本的程式，在 `count = count + 1` 的下一行加一行：

```python
    print("【除錯】answer =", answer, "guess =", guess, "count =", count)
```

注意前面的空格要和上一行對齊（Python 用縮排表示「在迴圈裡面」）。

2. 執行。每猜一次，你會看到類似這樣的一行：

```
【除錯】answer = 31 guess = 50 count = 1
```

3. 現在你能直接看到電腦「心裡想的數字」和你猜的數字。活動 6-2 的第三種錯（條件寫反）在這裡一眼就看穿：answer 是 31、guess 是 50，它卻說「太小了」。
4. 找到問題後，把這行刪掉或在最前面加 `#` 變成註解。

這招叫**印出除錯（Print Debugging）**，專業工程師到現在都還在用。請 AI 找錯之前先自己 print 一下，常常你自己就找到了；就算沒找到，把 print 的結果一起貼給 AI，它也會找得更準。

## 常見錯誤與迷思

- **「AI 寫的程式一定能跑。」** → 它沒有執行過，可能用到不存在的函式或寫錯語法。 → 一定自己跑，跑不動就把錯誤訊息貼回去。
- **「程式能跑就表示是對的。」** → 能跑只代表沒有語法錯誤，邏輯錯誤（例如條件寫反）電腦不會報錯。 → 設計測試：故意輸入奇怪的值，看它的反應對不對。
- **「看不懂沒關係，能用就好。」** → 看不懂的程式你不能改、不能除錯，也不知道它會不會做危險的事。 → 請 AI 加註解，蓋住註解自己講一遍。
- **「錯誤訊息一大堆紅字，我看不懂，直接刪掉重寫。」** → 錯誤訊息是最精準的線索，告訴你第幾行、什麼問題。 → 整段複製貼給 AI 請它解釋，順便學會讀最後一行。
- **「一次把所有功能都叫它加好比較快。」** → 一次改太多，出錯時找不到是哪個功能害的。 → 一次一個功能，跑一次，確認再下一個。
- **「程式裡有密碼也沒關係，反正 AI 不會記住。」** → 貼出去的東西收不回來，而且你不知道它會被存在哪裡。 → 貼之前把密碼、金鑰換成假的，個資檔不貼。

2. 玩家輸入「abc」時，基本版程式會印出 `ValueError: invalid literal for int() with base 10: 'abc'`。請用自己的話解釋這句錯誤訊息，並說明 7 次機會版本為什麼不會出現這個錯。

<details><summary>參考答案</summary>

意思是：`int()` 想把「abc」變成整數，但「abc」不是合法的十進位數字。7 次機會版本先用 `text.isdigit()` 檢查輸入是不是純數字，不是就印提示並 `continue`，根本不會呼叫 `int()`，所以不會出錯。

</details>

3. 為什麼活動 6-2 的「條件寫反」錯誤比「少冒號」難抓？

<details><summary>參考答案</summary>

少冒號是語法錯誤，Python 執行前就會檢查並報出行數；條件寫反是邏輯錯誤，程式語法完全正確、能正常執行，只是行為不對。電腦不知道你「想要」什麼，只有看懂程式、而且知道正確行為應該是什麼的人才能發現。這也是為什麼要測試。

</details>

4. 你想請 AI 幫你改一個同學寫的程式，同學沒說可不可以。這有什麼問題？該怎麼做？

<details><summary>參考答案</summary>

同學的程式是他的作品，未經同意貼給 AI 等於把他的東西交給第三方，而且如果裡面有他的帳號或個資會更嚴重。正確做法是先問同學，或只貼出你自己寫的部分、把他的部分用文字描述。

</details>

5. 設計一個測試清單：7 次機會版本的猜數字遊戲，你至少要輸入哪五種東西才算測過？

<details><summary>參考答案</summary>

(1) 正常數字且猜對；(2) 比答案小的數；(3) 比答案大的數；(4) 非數字如「abc」或空白；(5) 超出範圍如 0、101、-5；(6) 連續猜錯 7 次看會不會印答案。還可以測「剩下次數」有沒有正確遞減。測試就是把所有「使用者可能做的怪事」都做一遍。

</details>

6. 開放挑戰：請 AI 把猜數字改成「換人猜」：你心裡想一個數字，由電腦來猜，你只回答「大」「小」「對」。先自己想：電腦該用什麼策略才能最快猜到？再和 AI 寫出來的比。

<details><summary>參考答案</summary>

最有效率的策略是每次猜「範圍的中間」：1 到 100 先猜 50，你說「小」就改猜 1 到 49 的中間 25，依此類推，最多 7 次一定猜到。這叫二分搜尋。AI 寫出來的程式應該會維持 `low` 和 `high` 兩個變數，每次猜 `(low + high) // 2`。如果它寫成隨機亂猜，你現在有能力指出它效率不好了。

</details>

## 本章小結

- AI 程式助手很會從描述寫程式、解釋程式、解釋錯誤訊息；但它沒真的跑過，程式一定要自己執行才算數。
- 三步驟：描述（具體、說明程度）→執行（你來）→修改（貼回現象）。一次加一個功能。
- 看懂再用：請 AI 逐行加註解，蓋住註解自己講一遍，講不出來的行追問到懂。不懂的程式不要執行。
- 錯誤訊息是線索：看最後一行的錯誤類型和上面的行數，整段貼給 AI 請它解釋。
- 語法錯誤電腦會抓，邏輯錯誤只有看懂的人抓得到，所以要測試：故意輸入奇怪的值。
- 密碼、金鑰、別人的程式、含個資的檔案不要貼進 AI。
- 猜數字的流程（描述→執行→修改→測試）可以直接搬到 Arduino 閃燈等任何小專案上。
