# 第 12 章　專題

## 本章目標

- 學完你會用聊天型 AI 當家教，在一到兩週內學會一個你原本不會的主題，而且能用「考自己」證明真的學會了。
- 學完你會和 AI 程式助手合作做出一個能跑的小程式或小網站，並且看得懂裡面每一行在做什麼。
- 學完你會挑一個網路上的熱門說法，用 AI 加上原始資料把它查清楚，寫出一份有證據、有判定的查證報告。
- 學完你會寫一份格式完整的專題報告，誠實標示 AI 幫了哪些忙、哪裡出錯、你自己做了什麼。

## 開場：從「會用」到「做出一件事」

前面十一章，你每一章都打開 AI 做了一件小事：問一個問題、改一段文章、寫一個猜數字遊戲、抓一次幻覺。這些都是「單一招式」。但真實世界裡用 AI，從來不是一招就結束。你會問、得到答案、發現不對、追問、查證、修改、再問，來回十幾次，最後才做出一個能拿出來的成果。

這一章有三個專題，每一個都要花一到兩週，把全書的招式串起來用一遍。

**專題一：用 AI 當家教。** 挑一個你現在還不會的主題，請 AI 一步一步教你，每天記學習日誌，最後用「考自己」證明真的學會了。這個專題練的是第 4 章的學習法，加上第 3 章的查證。

**專題二：用 AI 做一個小程式或小網站。** 從「我想要一個什麼東西」開始，請 AI 幫你寫、跑起來、看懂、加功能、修 bug，最後交出一個能用的東西。這個專題練的是第 6 章的程式方法，加上第 2 章的問法。

**專題三：AI 查證報告。** 挑一個大家常講、但你不確定對不對的說法，用 AI 當起點、原始資料當終點，寫一份有判定的報告。這個專題練的是第 3 章的查證三步驟，加上第 10 章的誠實原則。

三個專題可以只做一個，也可以全做。每個專題都有目標、步驟、可以直接複製的提示詞、記錄表範本、驗證方法、檢核清單與延伸。最後一節告訴你專題報告怎麼寫。

## 開始之前：好專題的三個條件

**第一，有證據。** 「我覺得我學會了」不算；「我在不看筆記的情況下，十題對了九題，錯的那題是這個，我現在知道為什麼」才算。「程式好像可以跑」不算；「我測了這六種輸入，結果全部和預期一樣」才算。「AI 說這個說法是假的」不算；「我找到原始研究，裡面寫的是……」才算。

**第二，AI 的每一句重要的話都查過。** 三個專題裡 AI 都會出錯，這是正常的，不是失敗。專題報告裡要有一欄專門寫「AI 哪裡說錯了、我怎麼發現的」。這一欄如果是空的，通常代表你沒有認真查，而不是 AI 全對。

**第三，誠實標示。** 報告最後要有一段「AI 使用聲明」：用了哪個 AI、用在哪些步驟、哪些是你自己做的。這不是處罰，而是讓看報告的人知道該相信哪一部分。全書講到現在，你應該已經很習慣了。

還有一件事要先說：這三個專題都會用到聊天型 AI（例如 ChatGPT、Claude、Gemini）。未滿 13 歲請由家長申請帳號並陪同；整個過程中，不要把你的真實姓名、學校、班級、家人資料貼進去。專題裡需要「個人資料」的地方，一律用假名與假資料。

## 專題一：用 AI 當家教，學會一個我原本不會的主題

### 目標

- 挑一個「現在還不會，但一到兩週內學得會」的主題，請 AI 當家教教會你。
- 每天寫學習日誌，記錄學了什麼、AI 哪裡講得好、哪裡講錯或講不清楚。
- 用「學前測驗」與「學後測驗」比較，證明你真的進步了。
- 用費曼法把這個主題講給一個家人聽，對方聽得懂才算過關。

### 你需要的東西

- 一個聊天型 AI 帳號（未滿 13 歲由家長申請與陪同）
- 一本筆記本或一份文件，用來寫學習日誌
- 這個主題的「第二個來源」：課本、圖書館的書、教學影片，或另一個 AI
- 一個願意聽你講五分鐘的家人或同學
- 7 到 14 天，每天 20 到 30 分鐘

### 怎麼挑主題

好的主題有三個條件：**你現在真的不會**（不然測不出進步）、**有明確的對錯**（學會了考得出來）、**一到兩週學得完**。下面是幾個適合的例子，也可以自己挑：

| 主題 | 為什麼適合 | 怎麼考自己 |
|---|---|---|
| 二進位與十進位互換 | 規則明確，自己可以驗算 | 隨機出 10 個數字互換 |
| 一元一次方程式的應用題 | 下學期會用到 | 做 10 題課本題 |
| 月相為什麼會變 | 有圖像可以畫出來 | 畫出 8 個月相與日地月位置 |
| 簡單的英文現在完成式 | 有明確規則與例外 | 改 10 個句子 |
| 看懂天氣圖的高低氣壓 | 每天可以對照真實天氣圖 | 預測明天天氣並驗證 |
| 樂理：大調音階怎麼組成 | 有固定公式（全全半全全全半） | 寫出 5 個大調音階 |

下面的步驟用「二進位與十進位互換」當範例。你換成自己的主題，提示詞裡把主題名稱換掉就好。

### 步驟

**第 0 步：學前測驗（第 1 天）**

在請 AI 教你之前，先請它出 10 題測驗，你憑現在的程度作答。這份成績是「起點」，之後才能比較。

```
你是一位國中老師。我是台灣的國中生，想學「二進位與十進位互換」，但我現在完全不會。
請先出 10 題測驗讓我測試起點程度，由易到難，先不要給答案，也不要教我。
題目請用編號列出，每題一行。
```

**你應該看到**：10 道有編號的題目。作答完再貼上去請它批改：

```
這是我的答案：1. ___ 2. ___ …（照題號填）
請一題一題批改，告訴我對幾題、每題錯在哪裡。先不要重新教，只要批改。
```

把分數記進學習日誌。考得很差是正常的，你本來就不會。

**第 1 步：請 AI 擬一份學習計畫（第 1 天）**

```
我想在 7 天內學會「二進位與十進位互換」，每天 20 到 30 分鐘。
請幫我排一份 7 天的學習計畫，每天一個小目標，最後一天是總複習與測驗。
計畫請用表格列出：天數、今天要學會的事、今天的自我檢查方式。
```

**你應該看到**：一張 7 列的表格。看一下有沒有太難或太趕的地方，請它調整：「第 3 天太多了，請拆成兩天。」計畫抄進你的日誌。

**第 2 步：每天上課（第 2 天到第 6 天）**

每天開一段新的對話（或接續同一段都可以），用這個提示詞開始：

```
今天是我學習計畫的第 2 天，今天的目標是「把十進位的數字換成二進位」。
請先用一個生活例子解釋為什麼需要二進位，再用一個簡單的數字（例如 13）示範一次換算過程，每一步都要寫出來。
解釋完請問我一個問題確認我有沒有聽懂，等我回答之後再繼續。
```

這個提示詞有四件重要的事：**告訴它進度**、**給今天的目標**、**要求一步一步示範**、**要求它問我**。最後一點最重要，不要讓它一次倒完所有東西。

聽不懂的時候，不要裝懂。用這幾句追問：

```
我不懂「餘數」為什麼要倒過來讀，請用另一種方式解釋，最好畫一個表格。
```

```
請用一個更小的數字（例如 5）再做一次，這次每除一次都停下來告訴我現在的狀態。
```

每天結束前，做兩件事：（1）**自己出一題給自己**，不看 AI 的答案先算，再請 AI 批改；（2）**把今天學到的用自己的話寫三句**，寫進日誌。

**第 3 步：中途查證（第 4 天）**

AI 教的東西要查。第 4 天挑一件「它講過的規則」，到第二個來源確認：翻課本、看教學影片，或開另一個 AI 問同一個問題。

```
請問「把十進位換成二進位」的標準做法是什麼？請一步一步說明，並用 13 當例子。
```

比較兩邊的答案。規則一致、例子算出來一樣，就打勾；不一樣，就要搞清楚誰對。二進位這種主題可以自己驗算：13 = 8 + 4 + 1 = 1101₂，用這個方法檢查。查證結果寫進日誌。

**第 4 步：費曼法講給別人聽（第 6 天）**

找一個家人或同學，用五分鐘把這個主題講一遍，不看筆記。對方可以隨時問「為什麼」。講完請對方幫你打分數：聽懂多少（0 到 10）、哪裡沒聽懂。

講不順的地方就是你還不會的地方。回去再問 AI：

```
我剛剛向家人解釋二進位，講到「為什麼 2 進 1」的時候卡住了。
請幫我用一個十歲小孩聽得懂的比喻解釋這件事，不超過 100 字。
```

**第 5 步：學後測驗（第 7 天）**

請 AI 再出 10 題，難度和第 0 步差不多。**重要：開一段全新的對話**出題，不然它會記得之前教過什麼，題目會偏向你會的。

```
請出 10 題「二進位與十進位互換」的測驗，由易到難，包含 5 題十進位換二進位、5 題二進位換十進位。
先不要給答案。
```

作答、批改、記分數。然後做最後一件事：**挑三題自己驗算 AI 的批改**。AI 出題和批改都可能出錯，你現在已經學會了，有能力抓它。

### 學習日誌範本

每天一列，一到兩週就是一張完整的表。

| 天 | 今天的目標 | 我學到的（用自己的話，三句） | 我問了什麼追問 | AI 講得好的地方 | AI 講錯或講不清的地方 | 自我檢查結果 |
|---|---|---|---|---|---|---|
| 1 | 學前測驗、排計畫 | | | | | 學前 ___/10 |
| 2 | | | | | | |
| 3 | | | | | | |
| 4 | 中途查證 | | | | 第二個來源說： | 一致／不一致 |
| 5 | | | | | | |
| 6 | 講給家人聽 | | | | | 對方打 ___/10 |
| 7 | 學後測驗 | | | | | 學後 ___/10 |

### 驗證方法

這個專題的「證據」有三層，缺一不可：

1. **分數的變化**：學前 ___/10 → 學後 ___/10。進步至少 3 分才算有效；沒進步不代表你笨，可能是主題太難或方法不對，報告裡要分析原因。
2. **自己驗算 AI 的批改**：至少挑三題，用第二個來源或自己的方法確認 AI 批得對。如果抓到 AI 批錯，恭喜你，這是報告裡最精采的一段。
3. **費曼法的分數**：家人給你幾分，哪裡沒聽懂。

### 檢核清單

做完請一條一條打勾：

- [ ] 有學前測驗的分數與答案紙
- [ ] 有 7 天以上的學習日誌，每天都有「用自己的話寫的三句」
- [ ] 至少有一次中途查證，寫出第二個來源與比較結果
- [ ] 至少記錄一次「AI 講錯或講不清」的地方（找不到就要寫「我查了哪些地方，都沒找到錯」）
- [ ] 向一個人講過一次，有對方的分數與回饋
- [ ] 有學後測驗的分數，而且至少三題自己驗算過批改
- [ ] 整個過程沒有貼過真實姓名、學校、家人資料

### 延伸

- **教別人**：把你的學習計畫與提示詞整理成一頁，給同學照著學同一個主題，看他能不能也在 7 天內學會。
- **換一種媒材**：請 AI 幫你把這個主題做成 10 張閃卡（正面問題、背面答案），一週後再抽考自己一次，看還記得多少。
- **挑戰更大的主題**：用同樣的方法學一個要三到四週的主題，例如「看懂一張簡單的電路圖」或「英文的 12 種時態」。

## 專題二：用 AI 協助做一個小程式或小網站

### 目標

- 從一句「我想要一個……」開始，寫出一份簡單的需求說明。
- 和 AI 程式助手合作，做出一個能跑、能用的小程式或單頁網站。
- 看懂程式裡的每一行在做什麼，能用自己的話解釋給別人聽。
- 用測試表證明程式在各種情況下都正確，並記錄你抓到與修好的 bug。

### 你需要的東西

- 一個聊天型 AI 或 AI 程式助手帳號
- 二選一：
  - **做小程式**：一台有 Python 的電腦，或任何可以在瀏覽器裡執行 Python 的線上環境（第 6 章用過的那種）。
  - **做小網站**：一台電腦、一個純文字編輯器（記事本、TextEdit 的純文字模式，或任何程式編輯器）、一個瀏覽器。不需要伺服器，雙擊 HTML 檔就能打開。
- 一份「開發日誌」文件
- 7 到 14 天，每天 30 分鐘

### 挑一個題目

好題目的條件：**一句話講得完**、**你自己會用到**、**第一版兩小時內可以跑起來**。下面是幾個參考：

| 類型 | 題目 | 第一版要能做到 | 之後可以加的功能 |
|---|---|---|---|
| 小程式 | 英文單字抽考機 | 從清單隨機抽一個單字問中文，答對答錯都告訴你 | 記錄答對率、只抽錯過的、計時 |
| 小程式 | 零用錢記帳小工具 | 輸入項目與金額，列出所有紀錄與總和 | 分類、存檔、算每週平均 |
| 小程式 | 讀書番茄鐘 | 倒數 25 分鐘，時間到印出提醒 | 休息 5 分鐘、記錄完成幾輪 |
| 小網站 | 班級活動倒數頁 | 顯示活動名稱與剩幾天 | 多個活動、換背景顏色 |
| 小網站 | 我的讀書清單 | 列出書名與讀完沒，可以勾選 | 新增書名、資料存在瀏覽器裡 |
| 小網站 | 單位換算器 | 輸入公分顯示英吋 | 多種單位、歷史紀錄 |

下面用「英文單字抽考機」（Python）當範例走一遍；做網站的同學把提示詞裡的「Python 程式」換成「單一 HTML 檔案的網頁，用 HTML、CSS、JavaScript 寫在同一個檔案裡」就可以。

### 步驟

**第 1 步：寫需求說明（第 1 天）**

在問 AI 之前，先自己寫。這一步是專題裡最重要的一步，因為 AI 只會做你說清楚的事。

```
【我的需求說明】
名稱：英文單字抽考機
給誰用：我自己，練英文單字
第一版要做到：
1. 程式裡先放 10 個單字和中文意思。
2. 執行後隨機抽一個單字，顯示英文，讓我輸入中文。
3. 答對顯示「答對了」，答錯顯示正確答案。
4. 問完 5 題後顯示答對幾題，然後結束。
不用做的：不用存檔、不用圖形介面、不用音效。
```

**第 2 步：請 AI 寫第一版（第 1 天）**

把需求說明整段貼上，加上這段：

```
我是台灣的國中生，剛學 Python，只會變數、if、for、while、函式、串列。
請根據上面的需求說明寫一個 Python 程式，要求：
1. 只用我會的語法，不要用我沒學過的東西；如果非用不可，請在程式後面解釋。
2. 每一段程式都要有中文註解。
3. 程式完成後，告訴我怎麼執行，以及執行時應該看到什麼。
```

**你應該看到**：一段約 20 到 40 行的程式，每一段有註解，後面附執行方法。把程式貼進你的環境執行。

**第 3 步：跑起來，然後讀懂它（第 2 天）**

程式能跑之後，先不要加功能，先讀懂。一行一行看，看不懂的就問：

```
下面這行是什麼意思？`random.choice(words)` 裡的 random 是什麼？choice 又是什麼？
如果我把它換成 words[0] 會發生什麼事？
```

```
請把整個程式的流程畫成一張簡單的文字流程圖，用箭頭表示每一步接到哪裡。
```

然後做一件驗證你真的懂的事：**故意改一個地方，先猜結果，再執行看對不對**。例如把「問 5 題」改成「問 3 題」，或把答對的訊息改成別的字。猜對了，代表你懂那一行。

**第 4 步：寫測試表，一個一個測（第 3 天）**

程式「可以跑」和「都正確」是兩回事。想一想使用者可能怎麼用它，列成測試表，逐一試：

| 編號 | 測試情況 | 我的輸入 | 預期結果 | 實際結果 | 通過？ |
|---|---|---|---|---|---|
| T1 | 答對 | 正確的中文 | 顯示「答對了」 | | |
| T2 | 答錯 | 錯的中文 | 顯示正確答案 | | |
| T3 | 什麼都不輸入直接按 Enter | （空白） | 應該算答錯，不能當機 | | |
| T4 | 中文前後多打空格 | 「 蘋果 」 | 應該算對（要先決定規則） | | |
| T5 | 問完 5 題 | 隨便答 | 顯示答對幾題後結束 | | |
| T6 | 同一個字連續抽到 | — | 可以接受嗎？要不要避免？ | | |

**你應該看到**：至少有一、兩個測試沒過。這很正常，第一版從來不會全對。

**第 5 步：修 bug（第 3 到 4 天）**

把沒過的測試交給 AI，但要給它完整資訊：

```
我的程式在這個情況下有問題：
測試情況：什麼都不輸入直接按 Enter
預期：算答錯，顯示正確答案
實際：（把畫面上的錯誤訊息或錯誤行為完整貼上）
下面是目前的完整程式：
（貼上程式）
請告訴我問題出在哪一行、為什麼，然後給我修改後的那一段就好，不要重寫整個程式。
```

「不要重寫整個程式」很重要。AI 很喜歡整個重寫，重寫之後你又要重新讀一次，而且常常會順手改掉其他地方。修完重新跑整張測試表，不是只跑那一個。

**第 6 步：加功能，一次一個（第 5 到 10 天）**

第一版穩了，才加功能。每個功能走一樣的流程：寫需求 → 請 AI 改 → 讀懂 → 補測試 → 跑整張測試表。

```
目前的程式可以正常運作（貼上完整程式）。
我想加一個功能：結束時列出我答錯的單字，讓我可以再看一次。
請只修改需要改的地方，標出哪幾行是新的，並說明為什麼這樣改。
```

每加一個功能就在開發日誌記一列。加到第三個功能的時候，你會發現程式開始變長、變難讀，這時可以問：

```
程式變長了，請建議我怎麼把它拆成幾個函式，讓每個函式只做一件事。先不要改，先告訴我你會怎麼拆、為什麼。
```

**第 7 步：請第二個 AI 審查（第 11 天）**

開另一個聊天型 AI（或同一個 AI 的新對話），把最終版貼上：

```
請以程式審查者的角度看這段 Python 程式，列出：
1. 可能出錯的地方（例如使用者亂輸入時）
2. 可以寫得更清楚的地方
3. 有沒有安全或隱私上的問題
每一點請指出行數，並說明理由。不要重寫程式。
```

它說的不一定對。每一點自己判斷：同意就改並記錄，不同意就寫下為什麼不同意。

### 開發日誌範本

| 日期 | 今天做了什麼 | 給 AI 的主要提示詞（摘要） | AI 的輸出有沒有問題 | 我自己改了什麼 | 測試表通過數 |
|---|---|---|---|---|---|
| 第 1 天 | 寫需求、第一版 | 「根據需求說明寫 Python 程式…」 | 用了我沒學過的 try/except，請它解釋 | 改了提示文字 | — |
| 第 2 天 | 讀懂程式 | 「這行是什麼意思…」 | | 改 5 題成 3 題測試 | — |
| 第 3 天 | 測試表 | — | — | — | 4/6 |
| 第 4 天 | 修 bug | 「這個情況有問題…」 | 第一次修沒修好 | 自己加了 .strip() | 6/6 |
| … | | | | | |

### 驗證方法

1. **測試表全部通過**，而且測試情況至少 6 個，其中至少 2 個是「使用者亂用」的情況（空白、亂打、超大數字）。
2. **解釋測試**：隨便挑程式裡的 5 行，不看註解，用自己的話說出它在做什麼。請家人隨機指，你來解釋。講不出來的那幾行，回去再問 AI，直到講得出來。
3. **改動測試**：家人出一個小改動要求（例如「改成問 8 題」「答對時多顯示一個笑臉」），你要在 10 分鐘內不靠 AI 改好並跑過測試。做得到，代表這個程式真的是你的。

### 檢核清單

- [ ] 有一份先寫好的需求說明（在問 AI 之前寫的）
- [ ] 程式或網頁可以執行，不會一開就當機
- [ ] 測試表至少 6 項，全部通過，並且有「亂用」的情況
- [ ] 程式裡每一行我都能解釋；看不懂的語法都問過
- [ ] 至少修過一個 bug，並且日誌裡有記錄
- [ ] 至少加過兩個功能，每個都走「需求 → 改 → 讀懂 → 測試」
- [ ] 請第二個 AI 審查過，而且我對每一點都有自己的判斷
- [ ] 程式裡沒有任何真實密碼、真實姓名、家人資料
- [ ] 程式開頭有註解標示「本程式在 AI 程式助手協助下完成，作者：（你的暱稱）」

### 延伸

- **給別人用**：把程式交給一個同學用五分鐘，不要在旁邊解釋。觀察他卡在哪裡，那就是下一個要改的地方。
- **做小網站的同學**：請 AI 教你怎麼把資料存在瀏覽器裡（關掉再打開還在），這是第一個真正「有記憶」的功能。
- **做小程式的同學**：請 AI 教你怎麼把單字清單改成從一個文字檔讀進來，這樣不用改程式就能換單字。
- **連結《動手玩電》**：如果你有 Arduino 或 micro:bit，可以把「番茄鐘」做成實體的：時間到就亮燈或響一聲。

## 專題三：做一份「AI 查證報告」

### 目標

- 挑一個網路上常見、很多人相信、但你不確定的說法。
- 用聊天型 AI 當「起點」（幫你整理爭議、找關鍵字），用原始資料當「終點」（最後的判斷只看原始資料）。
- 給這個說法一個明確的判定等級，並寫出證據。
- 記錄 AI 在過程中說對了什麼、說錯了什麼、編了什麼。

### 你需要的東西

- 一個聊天型 AI 帳號（最好能用到兩個不同的 AI，用來交叉比對）
- 可以上網查資料的電腦或手機
- 一份「查證記錄表」文件
- 5 到 10 天，每天 30 分鐘

### 挑一個說法

好的說法有三個條件：**很多人講過**（你在網路、群組、課堂上聽過）、**可以被查**（有研究、有統計、有官方資料）、**你自己也不確定**。下面幾個是常見的例子：

| 說法 | 可以查的方向 |
|---|---|
| 「人只用了大腦的 10%」 | 腦科學研究、科普機構的說明 |
| 「金魚的記憶只有三秒」 | 動物行為研究 |
| 「在黑暗中看書會近視」 | 眼科醫學會或衛生機關的說明 |
| 「吃完飯馬上游泳會抽筋」 | 急救或運動醫學組織的說明 |
| 「台灣是全世界 OO 最高／最低的地方」 | 政府統計、國際組織的資料 |
| 「某食物可以抗癌」 | 醫學研究、衛生福利部或食藥署的資訊 |

下面用「金魚的記憶只有三秒」走一遍。

### 步驟

**第 1 步：把說法寫精確（第 1 天）**

很多說法查不清楚，是因為它本身很模糊。先把它改寫成可以驗證的句子：

- 原始說法：金魚記憶只有三秒。
- 精確版：**金魚無法記住超過三秒鐘前發生的事情**，所以不會記得被餵食、被訓練過的事。

精確之後，你才知道要查什麼：有沒有研究顯示金魚能記住幾分鐘、幾天、幾個月前的事？

**第 2 步：請 AI 當「起點」（第 1 到 2 天）**

```
我在查證這個說法：「金魚無法記住超過三秒前發生的事」。
請你：
1. 說明這個說法通常從哪裡來、為什麼大家會這樣講。
2. 列出支持與反對這個說法的主要論點。
3. 告訴我如果要查證，應該找哪一類的原始資料（例如研究論文、官方機構說明），以及用什麼關鍵字搜尋（中文與英文都要）。
請不要直接下結論，也不要編造具體的研究名稱；如果你不確定某篇研究是否存在，請直接說不確定。
```

**你應該看到**：來源說明、正反論點、建議的關鍵字。注意最後一句：即使你叫它不要編，它還是可能編。這一步你只拿「方向與關鍵字」，不拿「結論」。

接著問來源：

```
請列出你認為最相關的 3 項原始資料（研究、機構說明或書籍），每一項請給：作者或機構、標題、年份，以及你對「這項資料是否真的存在」的把握程度（高／中／低）。
```

**第 3 步：找原始資料（第 2 到 5 天）**

這是整個專題最花時間、也最重要的一步。拿著 AI 給的關鍵字與來源清單，自己去找：

1. **AI 給的每一項來源，逐一確認存不存在。** 用搜尋引擎搜標題與作者。找到就記下連結；找不到就在記錄表寫「查無此資料」。這就是第 3 章說的幻覺，親眼看到一次印象會很深。
2. **用關鍵字自己搜。** 優先找這幾種：大學或研究機構網站、政府或國際組織（例如衛生福利部、教育部、世界衛生組織）、有同行審查的期刊、大型博物館或科學中心的科普說明。
3. **至少找到 2 份彼此獨立的原始資料。** 獨立的意思是：不是互相抄的。兩篇新聞都引用同一項研究只算一份。
4. **讀資料本身，不只讀標題。** 很多說法是「研究有做，但結論被誇大」。看看研究到底怎麼做的、測了多少隻魚、得到什麼結果。

遇到英文資料看不懂，可以請 AI 翻譯與摘要，但要記得：**翻譯可以靠 AI，判斷不行**。

```
下面是一段英文研究摘要，請翻成中文，並用三句話說明：研究做了什麼、發現了什麼、有什麼限制。請忠實翻譯，不要加入摘要裡沒有的內容。
（貼上摘要）
```

**第 4 步：交叉比對（第 5 到 6 天）**

把你找到的原始資料內容，拿回去問第二個 AI（或同一個 AI 的新對話）：

```
我找到這份資料：（貼上標題、來源與重點內容）。
它和「金魚記憶只有三秒」的說法是支持、反對，還是無關？請說明理由，並指出這份資料有沒有什麼限制讓它不能完全證明或推翻這個說法。
```

同時比較兩個 AI 在第 2 步的回答：它們哪裡說法一致、哪裡不一致、哪個給的來源存在、哪個編了。這些都寫進記錄表。

**第 5 步：下判定（第 7 天）**

用這五個等級，只能選一個：

| 等級 | 意思 | 什麼情況用 |
|---|---|---|
| 正確 | 原始資料明確支持 | 至少兩份獨立原始資料都支持，沒有可靠的反證 |
| 大致正確 | 方向對，細節有誇大或不精確 | 核心沒錯，但數字、範圍或條件被講過頭 |
| 部分正確 | 某些情況對、某些情況錯 | 資料顯示要看條件 |
| 錯誤 | 原始資料明確反駁 | 至少兩份獨立原始資料都反駁 |
| 無法判定 | 找不到足夠的原始資料 | 誠實寫出找了哪些地方、為什麼不夠 |

「無法判定」是合法的答案。寫得清楚的「無法判定」比硬掰的「錯誤」更有價值。

以金魚為例，你很可能會找到多項動物行為研究顯示金魚能記住訓練內容數週甚至更久，判定會落在「錯誤」。但這是你要自己找到資料才能寫的，不是因為書上這樣說。

### 查證記錄表範本

**第一部分：AI 給的來源逐一確認**

| 編號 | AI 給的來源（作者／機構、標題、年份） | 哪個 AI 給的 | AI 自稱把握度 | 我搜尋後的結果 | 真的存在？ | 內容和 AI 說的一樣？ |
|---|---|---|---|---|---|---|
| S1 | | | | | 是／否／找不到 | 是／否／部分 |
| S2 | | | | | | |
| S3 | | | | | | |

**第二部分：我自己找到的原始資料**

| 編號 | 來源（機構或作者、標題、年份、連結） | 來源類型 | 它說了什麼（三句話） | 支持／反對／無關 | 限制或注意事項 |
|---|---|---|---|---|---|
| R1 | | 研究／官方／科普／其他 | | | |
| R2 | | | | | |
| R3 | | | | | |

**第三部分：AI 表現紀錄**

| 項目 | AI 一 | AI 二 |
|---|---|---|
| 對說法的初步判斷 | | |
| 給了幾個來源 | | |
| 其中幾個真的存在 | | |
| 存在的來源裡，內容描述正確的有幾個 | | |
| 有沒有主動說「不確定」 | | |
| 翻譯或摘要有沒有加油添醋 | | |

### 驗證方法

1. **來源能被第二個人找到**：把你的記錄表給家人或同學，請他照連結或標題找一次，找得到才算。
2. **判定有證據支撐**：每一個判定等級都對應記錄表裡至少兩份獨立原始資料；拿不出來就要降為「無法判定」。
3. **AI 的錯被抓出來**：記錄表第三部分至少要有一個「找不到」或「內容不一樣」的來源。如果真的一個都沒有，要寫出你確認了幾個、怎麼確認的。

### 檢核清單

- [ ] 說法有改寫成可以驗證的精確版本
- [ ] AI 給的每一個來源都逐一確認過，結果記在表裡
- [ ] 至少 2 份彼此獨立的原始資料，而且我讀過內容不只標題
- [ ] 有用第二個 AI 或新對話交叉比對過
- [ ] 判定等級只有一個，而且每一份證據都列在表裡
- [ ] 有記錄 AI 說錯或編造的地方（或清楚寫出「確認過沒有」）
- [ ] 翻譯與摘要有對照原文抽查過至少一段
- [ ] 報告裡沒有把 AI 的話當成來源引用（AI 不是來源，資料才是）

### 延伸

- **做成一頁懶人包**：把你的判定與證據整理成一張給家人看的一頁圖文（可以請 AI 幫你排版文字，但內容是你的）。
- **查第二個說法，看會不會更快**：第一次通常要 10 天，第二次可能 5 天就夠。記錄你的速度變化。
- **查一個「AI 自己說的事」**：請 AI 介紹你住的城市或你喜歡的一項運動，挑出三個具體的數字或日期去查。這是最貼身的查證練習。
- **連結《AI 怎麼運作》**：想知道為什麼 AI 會編出不存在的研究，可以看理論書裡關於「預測下一個字」與「幻覺」的章節（https://book.vichuang.tw/ai-theory/ ）。

## 常見錯誤與迷思

- **「AI 說我答對了，所以我答對了」** → AI 批改會錯，尤其是數學與需要精確答案的題目 → 學後測驗至少三題自己驗算，發現批錯是加分不是扣分。
- **「程式可以跑就代表完成了」** → 可以跑只代表沒有語法錯誤，不代表邏輯正確 → 測試表全過、而且有「亂用」的情況，才算完成。
- **「AI 整個重寫比較快」** → 重寫之後你又要重新讀懂，而且常常順手改壞別的地方 → 要求「只改需要改的地方，標出改了哪裡」。
- **「AI 列出來源了，所以有查證」** → 列出來源和來源存在是兩回事 → 每一個來源都要自己搜到才算。
- **「兩個 AI 說一樣，所以是對的」** → 它們可能用類似的資料訓練，一起錯很常見 → 交叉比對只能幫你找出不一致的地方，最後還是要看原始資料。
- **「無法判定等於專題失敗」** → 寫清楚找了什麼、為什麼不夠，本身就是有價值的結論 → 誠實的「無法判定」比硬掰的結論分數高。
- **「專題報告要寫 AI 很厲害」** → 報告不是廣告 → 最有價值的段落是「AI 哪裡錯了、我怎麼發現的」。

## 專題報告格式

三個專題共用這一份格式。用文件軟體或 Markdown 寫都可以，總長度 3 到 6 頁（不含附錄）。

### 1. 封面

專題名稱、你的暱稱（不要用真實全名）、班級代號（可省略）、日期、做了幾天。

### 2. 目標（3 到 5 行）

你想做出什麼、想證明什麼。寫成可以檢查的句子，例如「在 7 天內把二進位互換從 2/10 進步到 8/10 以上」。

### 3. 方法與步驟（半頁到一頁）

你實際走的步驟，不是書上的步驟。哪裡照書做、哪裡自己改了、為什麼。用了哪個聊天型 AI、大約問了幾次、最有用的三個提示詞原文附上。

### 4. 過程紀錄（一到兩頁）

把學習日誌、開發日誌或查證記錄表整理後放進來。不用全放，挑最重要的幾天或幾列，但原始的完整表格放附錄。

### 5. 結果與證據（一頁）

- 專題一：學前與學後分數、費曼法分數、你自己驗算 AI 批改的三題。
- 專題二：最終程式（附錄放完整版，這裡放最關鍵的 10 到 20 行並解釋）、測試表全貌、修過的 bug 清單。
- 專題三：判定等級、支撐判定的每一份原始資料、記錄表第一部分與第三部分。

### 6. AI 哪裡幫了、哪裡錯了（半頁）

這一段是整份報告最重要的一段，分兩欄寫：

| AI 幫了什麼 | AI 錯了什麼、我怎麼發現的 |
|---|---|
| 例：用三種方式解釋餘數，第三種我才聽懂 | 例：批改第 7 題時把 1011₂ 算成 13，我自己算是 11 |

### 7. 反思與下一步（5 到 8 行）

如果重做一次你會怎麼改？下一次想做什麼？這個專題讓你對「用 AI」這件事的想法有什麼改變？

### 8. AI 使用聲明（必填）
